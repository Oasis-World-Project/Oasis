# 检查与交付

现在是怎么做的。为什么这么定，在 git 历史里（`git log -- docs/adr`）。

## 1. 原则

- Oasis 帮普通用户出成果，不是过审计的生产系统。检查只为一件事：别把明显坏掉的东西交给用户。
- 做得好不好由做成果的 AI 自己对照任务单判断，最后由用户看成果判断。平台不派模型给成果打分。
- 关卡只提醒，不拦截：没过退回一次，改过还没过就带着提醒往下走，任务照样交付。

## 2. 关卡查什么

一样成果做完后查一次（`services/task/src/service/gate.ts`、`engine/checks.ts`），都是便宜、确定的检查：

1. **文件齐不齐**：产出非空；方案写明的文件（`expects`）都在；文件解析得了。路径模式不带通配符时也指目录：`site` 既是文件 `site`，也是目录 `site/` 下的全部文件。
2. **网页打不打得开**：有 `oasis-app.json` 的成果在检查浏览器里按画布的方式跑一遍，看页面错误和画面，再按 `oasis-test.json` 里的步骤点一遍。
3. **音视频能不能播**：完整解码一遍。
4. **交给用户的网页要配清单**：交付文件里子目录中的 `.html` 没有被同目录或上层目录的 `oasis-app.json` 覆盖，算没过，退回补上。

没过时：干活节点在原会话里改一轮（单轮，不进入持续目标），交回关卡再查一次；工具节点没有 AI，不返工。整体验收只核对任务单上的交付物文件齐不齐，缺的只让负责它的节点补。

## 3. AI 自己怎么查

- 沙箱里有 Chromium 和 playwright-core：AI 可以自己写脚本打开做好的页面、操作、读页面状态、截图。
- `oasis-tool app.check --dir out/site`：把当前的网页交给和关卡同一套检查，当场返回报错。AI 自己用浏览器打开的方式和画布不同，交付前按画布的方式查一次才算数。给了 `--out` 就把完整报告存成 JSON。
- 音视频用沙箱里的 ffprobe、ffmpeg 自己查。风格、像不像参考图这类主观要求，AI 用 `media.inspect` 自己看、自己判断。
- 3D 用 `oasis-3d check`、`oasis-3d snapshot`（见《工具与沙箱》）。

## 4. 检查在哪里做：inspector

判断成果的检查都在 inspector（端口 4109）：文件解析、音视频解码、网页的浏览器检查（交付关卡、`app.check`、外站测试 `website.test`）、模型预览、用户素材解析。

- inspector 不调别的服务、不存东西、不连数据库和事件。要查的内容由调用方给：对象存储的临时下载链接（只认 `SOURCE_ORIGINS` 里放行的地址），或直接放在请求里。结论交回调用方，要留档的由调用方存。
- 开容器的检查由付钱的一方定核数，算力在 model-gateway 冻结，按 inspector 报回的实际用量（核数 × 实际用时）结算，记在任务和节点上。检查没做完不收钱。交付关卡由任务付，`app.check`、`website.test` 由调用的节点付。
- 检查容器用完即删。音视频解码用沙箱基础镜像，不联网。浏览器检查用镜像 `oasis/inspector-browser`（Playwright + Chromium，`pnpm browser:build`），应用和浏览器同容器、没有外部网络。同时开的检查浏览器最多 `BROWSER_CONCURRENCY`（默认 3）个，解码容器 `MEDIA_CHECK_CONCURRENCY`（默认 2）个，多的排队。
- 外站测试只放行 `WEBSITE_TEST_ORIGINS` 里的 HTTPS 来源，只许 GET、HEAD。

接口（都在 `/internal/`）：`files/check`、`media/check`、`applications/check`（task 调）；`applications/check-files`、`websites/check`（model-gateway 调）；`materials/inspect`（conversation 调）；`models/inspect`、`models/poster`（canvas 调）。

### 浏览器检查的细节

- 静态网页套上和画布一样的隔离框外壳，框里是和画布一模一样的文档（同一份 CSP、同一个 sandbox）。画布里加载不了的东西直接算没过，原因里写明规则。
- 画面检查：加载完后每隔 30 帧截一次图，不是一整片纯色就算画出来了，最多等 300 帧。
- 测试步骤等页面安定：页面一直在变、条件一直不满足时，最多等 600 帧就下结论。按帧不按秒。
- `oasis-test.json` 要和 `oasis-app.json` 放在同一目录，放错了明确报错。静态网页的测试不能带查询参数或 # 片段。
- 不设时限，但服务之间的 HTTP 调用等响应头最多 300 秒：特别慢的页面仍可能被断开，报成「模型服务暂时连不上」。这一条还没解决。

## 5. 画布怎么运行网页

组装规则在共享包 `packages/live-page`，画布和检查共用。

- 一个可运行的成果是一组文件加一份清单 `oasis-app.json`（应用根目录、入口、种类）。只认显式清单，不把任意 HTML 当成应用。
- `kind: static` 的应用和单个 HTML 文件在本机的隔离框里运行：`sandbox="allow-scripts allow-pointer-lock"`，不给 `allow-same-origin`、弹窗、表单、顶层跳转、下载。框是不透明来源，读不到 Oasis 的 Cookie、本地存储和父页面。
- 文档最前面插入 CSP：`default-src 'none'`，脚本、样式、图片、媒体、字体、连接都只允许内联和 `data:`、`blob:`。所以网页读不到外网、CDN、`localStorage`，也不能用 fetch 或 XHR 读本地文件。
- 同一节点交出的文件按相对地址内嵌：脚本、样式表（和里面 `url()` 引用的图片、字体）、图片、音视频。ES 模块的引用改写后用 blob 地址加载，多文件互相 import 可以用。JS 里按路径加载的文件（如 `new Audio('audio/x.mp3')`）读不到，要写在 HTML 标签里。
- 带后端的应用（`kind: node`）画布里不运行，只能下载。
- 读取上限：单文件 64 MiB、整页合计 256 MiB。

## 6. 交付

- 任务完成时，负责交付物的节点交出的文件登记进画布：canvas 消费 `task.task.status_changed`，把每个成果文件复制进自己的桶，写一行 `artifacts`。中间节点的产出不登记；失败、取消的任务不登记。
- 交付消息只在任务第一次交付时发到发起它的私聊。修改后再交付，画布里的成果原地换新，不再发消息。
- 成果文件是 AI 写的，下载接口一律加 `Content-Security-Policy: sandbox` 和 `X-Content-Type-Options: nosniff`（PDF 例外）。内容接口流式返回、支持分段请求，视频和音频能拖进度。
- 默认不往用户电脑上存东西。桌面端的「同步到电脑」要用户用系统对话框选文件夹；主进程只往这个文件夹里写，已有同名文件不覆盖。

## 7. 批注和修改意见

- 成果页可以批注：图片上圈画；运行中的网页、应用和 3D 模型先截下此刻的画面再圈画（只有桌面端能截，浏览器里只能写文字意见）。截图由桌面端主进程截运行框所在的矩形，作为普通上传存进 canvas。
- 「发给 AI 团队修改」直接调 task 的 `POST /v1/tasks/:taskId/revisions`，不经过私聊。怎么改见《任务与工作流》§6。

## 8. 用户删除就是真删除

| 用户删除 | 真删除的内容 |
|---|---|
| 任务 | task 库的任务、节点、消息；canvas 的成果记录、对象、批注截图；harness 的运行记录、存档、工作目录、检查报告（运行中的先停、结算再删）；model-gateway 的工具中间文件；聊天里这个任务的卡片和交付消息 |
| 聊天消息 | 消息和 AI 的回复；随消息发的附件在 canvas 里删除记录和对象 |
| 私聊 | 会话、消息、接需求记录、上下文摘要；附件里被任务用作素材的留着，其余真删除。任务和成果不受影响 |
| 没用上的上传 | 从没被消息或批注用上的，超过 24 小时由 canvas 清掉 |

保留的只有 billing 的账本和 model-gateway 的调用、费用记录（只有金额、模型、ID，没有内容）：它们是钱的凭证。发件箱里已投递的事件留一天，NATS 里的留 7 天。
