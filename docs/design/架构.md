# 架构

现在是怎么做的。工程规矩（分层、迁移、命名、提交）在 `AGENTS.md`，方向在 `docs/engineering/项目工程方向.md`。为什么这么定，在 git 历史里（`git log -- docs/adr`）。

## 1. 技术栈

| 事项 | 现在用的 |
|---|---|
| 语言和仓库 | 全 TypeScript，Node 24；pnpm workspaces + Turborepo 单仓 |
| 通信 | 同步走内部 HTTP（Fastify + zod 契约），异步走 NATS JetStream |
| 存储 | PostgreSQL 18（每个服务独占一个 database 和账号）、Valkey、SeaweedFS（S3 兼容） |
| 迁移 | Drizzle 写查询，dbmate 管迁移（纯 SQL，含 up 和 down），按 Expand → Migrate → Contract 分步 |
| 前端 | React 19 + Vite + TanStack Router / Query + Zustand；Tailwind v4 + 设计令牌 + Radix；Electron 壳 |
| 模型 | model-gateway 是唯一出口，OpenAI 兼容，接 OpenRouter；dsh 的模型端点也指向它 |
| 执行底座 | dsh（DeepSeek Harness，TypeScript 运行时），精确锁定版本，只在 harness 的 adapter 层接触 |

## 2. 九个服务

| 服务 | 端口 | 管什么 |
|---|---|---|
| gateway | 8080 | 对外唯一入口：鉴权、CSRF、转发 `/v1/*`；不转发 `/internal/*`。另有两条给「在你的电脑上干活」：桌面版连 harness 的 WebSocket（照常认人）、电脑上的 dsh 调模型和工具（`/api/run/v1`，只认这一轮的临时 Key） |
| identity | 4101 | 邮箱验证码登录、会话 |
| billing | 4102 | 钱包、账本：冻结、结算、退回 |
| agent | 4103 | 对话 AI 的目录（每个 AI 几档型号）、人设和型号路由；用户的设置（「只用国内模型」、每个 AI 用哪一档） |
| conversation | 4104 | 私聊（用户说一句开一轮或插话、跟进 AI 做到哪了、一轮结束登记成果）、群聊 |
| canvas | 4106 | 上传的素材、成果、批注、画布 |
| harness | 4107 | 在云端沙箱或用户的电脑上（桌面版连上来）跑私聊的 AI（dsh）：每一轮的运行、插话、停止、接管、存产出；给 AI 的平台说明和技能 |
| model-gateway | 4108 | 模型和工具的唯一出口：计量、冻结结算、工具目录、长任务、一轮花了多少；一轮里要用户点的确认卡 |
| inspector | 4109 | 检查成果：文件解析、音视频解码、浏览器检查、模型预览 |

每个服务用 `@oasis/service-kit` 的 `startService` 启动，统一有 `/health`、`/ready`、`/v1/meta`。服务内分层 `src/api → src/service → src/repo`。共享包 `packages/*` 只放契约（contracts）、基础设施库（service-kit）、画布运行网页的组装规则（live-page）、设计令牌和 tsconfig。

## 3. 调用只往一个方向走

- 私聊这条链：conversation → agent（型号路由）、harness（开一轮、拉事件、插话、停止）、canvas（查要改的成果、登记成果）、model-gateway（一轮的花费和待定的确认卡、作答）；harness → model-gateway（运行 Key、算力）、canvas（把素材和要改的成果拷进沙箱）；model-gateway → inspector（`app.check`、`website.test`）。沙箱里的工具经入口代理到 model-gateway。
- 在用户电脑上干活：桌面版登录后主动连 gateway 的 `/api/harness/v1/devices/connect`（WebSocket，带登录 Cookie、查来源），gateway 认人后转给 harness，harness 把一轮交给这台电脑（协议在 `packages/contracts/src/device.ts`）。电脑上的 dsh 和 `oasis-tool` 经 gateway 的 `/api/run/v1/*` 到 model-gateway 的 `/run/v1/*`，和沙箱的入口代理是同一套接口。
- 删私聊时 conversation 依次调 harness、model-gateway、canvas 的 `/internal/conversations/:id/purge`（开新话题只清 harness 那边的会话和工作目录），不发事件。
- inspector 不调任何服务、不存东西。
- `pnpm check:engineering` 按 `createServiceClient('<对方>', …)` 画调用图，出现新的环就拦下。已知例外两条：canvas → harness（取一轮交出的文件）、canvas → model-gateway（开数字人会话）。
- 依赖检查（dependency-cruiser）连只导入类型的引用也算，文件之间不能成环。

## 4. 事件

- 发布一律走 transactional outbox：业务事务里写 `outbox` 表，中继每 500 ms 把没发的事件发到 JetStream，消息 ID 用事件 ID。
- 消费者都是持久消费者，手动 ack，失败 5 秒后重投，最多 20 次，都要幂等（`processed_events`）。
- 事件的形状在 `packages/contracts/src/events.ts`，现在只有一种：

| 事件 | 谁消费 | 做什么 |
|---|---|---|
| `identity.user.registered` | billing | 发注册额度 |

## 5. 代码怎么放

- 契约先行：服务间的接口和事件都在 `packages/contracts`，服务从构建好的 `dist` 引用它，改了契约要重新构建。
- 单个文件不超过 500 行（ESLint `max-lines`）。测试的公共部分放 `test/support/`。
- 大服务按职责拆目录：harness 的 `service/run/`（执行、停止和接管、搬文件、读产出）；model-gateway 的 `service/tools/`（每类工具一个文件）。

## 6. 本地运行

- `pnpm dev` 起 8 个后端服务加 gateway 和 Web；基础设施（Postgres、NATS、Valkey、SeaweedFS、Mailpit、沙箱的入口和出口代理）用 Docker Compose。
- 密钥只放本地 `.env`（`pnpm env:init` 生成）。Turborepo 用严格环境变量模式，只有 `.env` 文件里的配置会交给服务。
- harness 在 `pnpm dev` 里是稳定进程，不随源码变动重启；重启后接管原来的运行。
- 桌面端 `pnpm desktop`：登录后自动连上 Oasis，可以在这台电脑上干活（要装 Node 24 或 22.19 以上的 22 版）。
- 回归和验收见 `docs/engineering/回归测试.md`。

## 7. 以桌面端为准

产品面向 Electron 桌面窗口。桌面端加载的就是 `apps/web` 这一套界面，前端代码只有一份。用浏览器直接打开只需能用，不为浏览器单独做降级或兼容，也不把「浏览器里做不到」当成限制。
