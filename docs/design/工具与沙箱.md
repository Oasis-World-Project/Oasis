# 工具与沙箱

现在是怎么做的。为什么这么定，在 git 历史里。

## 1. 沙箱

- 一份会话一个容器，容器里只跑 dsh（精确锁定版本，经 stdin/stdout 说 JSON-RPC）。这份会话的第一轮起它，一轮做完不销毁，空着留一会儿（`SANDBOX_IDLE_SECONDS`，默认 60 秒；用户电脑上的 dsh 留 `DEVICE_IDLE_SECONDS`，默认 30 分钟）：下一轮接着用同一个 dsh，不用再起容器、握手、读会话记录，它手里的临时 Key 改归新的一轮（model-gateway 的 `rebind`）。起它时定死的东西（环境变量、平台说明和技能、`oasis-tool` 这些命令）变了，或上一轮是停下、出错的，就重起一个接上原会话（`run/hosts.ts`）。全仓只有 `services/harness/src/adapter/` 接触 dsh。
- 镜像：`oasis/harness-sandbox-base:<dsh 版本>`（`pnpm sandbox:build`）和带 Blender 的 `oasis/harness-sandbox-3d`（`pnpm sandbox:build:3d`）。harness 用哪个由 `SANDBOX_IMAGE` 定。
- **云端的沙箱开在哪**（`CLOUD_EXECUTOR`）：`docker` 是这台机器上的 Docker（开发机、回归）；`e2b` 是租的 E2B 沙箱（线上，`executor/e2b.ts`）。E2B 上一份会话一个沙箱，按会话打元数据；沙箱的盘就是这份会话的持久工作目录，做完不删：空着留够 `SANDBOX_IDLE_SECONDS` 就整个暂停（不收运行费，dsh 原样留在里面，下一轮恢复约 1 秒接着用），歇够 24 小时或停下、出错时结束里面的进程再暂停，删对话、开新话题才真的删掉。模板由 `pnpm sandbox:e2b` 照沙箱镜像的两份 Dockerfile 在 E2B 上建（`ARG` 展开成每条命令前的 `export`；镜像的 `ENV` 对 E2B 起的命令不生效，写成 `/opt/oasis/image-env.sh`，起 dsh、跑命令前先读它）。沙箱出站只放行 `E2B_RUN_API_URL` 那台主机和 `E2B_ALLOW_OUT` 里的软件包仓库；dsh 调模型和工具走公网上 gateway 的 `/api/run/v1`。同时能开几个看 E2B 的档位（`MAX_CONCURRENT_RUNS` 照着填，Hobby 是 10），沙箱连续运行到 `E2B_TIMEOUT_SECONDS`（Hobby 最长 1 小时）会自动暂停。真机测试：`OASIS_E2B_TEST=1` 跑 `services/harness/test/e2b.test.ts`。
- 默认 2 核 2 GB、最多 512 个进程（`SANDBOX_CPUS`、`SANDBOX_MEMORY_MB`）。没有显卡，3D 页面靠 CPU 画。实测：用 Chromium 驱动带 WebGL 的页面，内存峰值约 445 MiB、进程 212 个；一次 50 分钟的小游戏运行（反复开浏览器自查、生音频），内存峰值 799 MiB、进程 206 个。
- 目录：`in/`（平台放的说明：沙箱里有什么、文件格式）、`materials/`（用户随消息发的文件；「让 AI 改」之前话题的成果在 `materials/canvas/` 下）、`out/`（要交出的文件，素材放 `out/素材/`，做好一个就进画布）、`work/` 等（脚本、草稿，不进画布）。文件由 harness 拷进拷出，容器不直接访问对象存储；画布登记成果时由 harness 从这个会话的工作目录里现读（`run/outputs.ts`）：一轮还在做时读它的沙箱；收尾后云端的读持久卷，用户电脑上的经桌面版读（电脑没连上就取不到，这一轮的消息里会写明）。
- 正常做完时，harness 存产出前先在容器里用 LibreOffice 给 `out/` 里的 Word、PPT 各配一份同名 PDF（已有同名 PDF 的不动，单个最多 2 分钟，转不了不挡交付），画布按这份 PDF 预览，和下载的样子一致。
- 网络：容器在内部网络里，不通外网。只能经入口代理访问 model-gateway 的 `/run/v1/*`（模型、工具），带着这次运行的临时 Key；经出口代理（tinyproxy，只放 443，整个域名精确匹配）访问明确放行的站：`SANDBOX_EGRESS_ALLOW_HOSTS`（npm 和 PyPI 的仓库或镜像站），加上镜像里的名单 `infra/images/sandbox-egress/project-hosts`（GitHub / GitLab、Go、Rust、Maven / Gradle、RubyGems、Packagist 等，`SANDBOX_EGRESS_PROJECT_HOSTS=off` 时不放行）。所以装依赖、`git clone` 公开仓库能用，别的网站打不开。碰不到任何服务的 `/internal`。
- 停下、取消、出错，或空着留够了时间，销毁容器、作废临时 Key。工作目录和 dsh 会话留在这个会话的持久卷里，下一轮接着做（见《私聊与一轮》§2）。删对话、开新话题时先收掉空着的容器再删卷。
- **缓存卷**：每个付钱的人一块 `oasis-cache-<用户>`，挂在他每个云端沙箱的 `/cache`（群里的席位用的是群主的）。各语言下载的包用环境变量指到这里（npm、pip、uv、cargo、rustup、Go 模块和构建缓存、Gradle、Maven、Bundler、Composer），用时再装的工具链也装在这里（`/cache/bin`、`/cache/cargo/bin`、`/cache/go/bin` 在 PATH 里），所以换话题、换私聊不用重新下载。每轮开沙箱时量一遍：超过 `SANDBOX_CACHE_MAX_MB`（默认 5120）就按「工具 / 条目」两层目录从最久没用的删起，删到上限的八成（`executor.ts` 的 `TRIM_CACHE`）。里面只有下载下来的东西，不放项目文件。
- **开工前的脚本**：每一轮是新容器，上一轮留在后台的进程不在了。工作目录和它下一层目录里有 `oasis-setup.sh` 就在把话交给 AI 之前执行（在脚本所在目录里跑，最多 `SANDBOX_SETUP_SECONDS` 秒，默认 300），退出码和输出的结尾接在交给 AI 的那句话后面（`run/setup.ts`）；没成功不算这一轮失败，由 AI 处理。脚本是用户项目里带的，或者 AI 自己写的。
- **接手现成的项目**（技能 `projects`）：压缩包或公开的 Git 地址；Go、Rust、JDK 不预装，AI 用时装进 `/cache`；PostgreSQL、MariaDB、Valkey 的程序预装但不启动，AI 以普通用户在项目目录里起；改动交补丁或压缩包，不推回用户的仓库。私有仓库、沙箱里跑 Docker、装系统软件包都不支持。
- 开沙箱时 harness 把平台说明放成 dsh 的用户级 `AGENTS.md`、场景经验（`services/harness/guide/playbooks/*.md`）放成技能，并把当前版本的 `oasis-tool`（连同 `tool-api.ts`、`batch.ts`、`tool-files.ts`）、`oasis-op` 和它们用到的两个契约文件放进 `/opt/oasis`，把 Oasis 的 dsh 组合 `cordis.patch.yml` 和同目录的两个插件 `node-goal.mjs`、`approval.mjs` 放进 dsh 用户目录的 `profiles/oasis/`：改了这些不用重建镜像（镜像里那份只给离线验收用）。同一套文件也交给用户的电脑（§10）。
- 思考档：dsh 组合不给整条模型路由设默认思考档，由 `node-goal` 按每个型号原生的最高一档选；不会思考的型号（如 Llama 4 Maverick）不带。

### 预装的东西

写在镜像的 `/opt/oasis/software.txt`，`oasis-tool list` 会列出来；沙箱里有什么也写在 `in/.oasis-environment.json`。

| 用途 | 预装 |
|---|---|
| 网页、小游戏 | Node、Chromium、playwright-core、esbuild、typescript |
| 文档、数据 | LibreOffice、pandoc、poppler、sqlite3、jq，Python 的 pandas、openpyxl、python-docx 等 |
| 图片 | Pillow、ImageMagick |
| 字体（`/usr/share/fonts`，可以拷进成果或取子集后内嵌） | Noto CJK、Noto Color Emoji、点阵像素字体 Unifont（16×16，含中文） |
| 音视频 | ffmpeg、MLT（melt）、sox |
| 代码项目 | Python 3、git、ripgrep、zip、unzip、make、g++、curl、xz、pkg-config、libssl-dev、libpq-dev、python3-dev |
| 数据库（不自动启动） | PostgreSQL、MariaDB、Valkey |
| 3D（3D 镜像） | Blender、`oasis-3d`、`oasis_blender` 模块、`@gltf-transform/cli`、trimesh |

Chromium 的默认参数已经按沙箱的限制配好（非 root、`/dev/shm` 只有 64 MB、没有显卡），不带参数的 `chromium.launch()` 就能用。

## 2. 工具目录和调用

工具目录在 model-gateway（定义在 `src/service/tools/`，和供应商适配放在一起）：一个工具的名字、参数、调用方式和计费是一体的。没配 Key 的工具自动不可用。

**型号清单**（`packages/contracts/src/lineup.ts`）：所有型号写在这一个文件里——能聊天的 AI 们的各档型号和标价、各工具按顺序用哪些型号、「只用国内模型」认的国内厂商。model-gateway 的默认配置（`TOOL_IMAGE_MODELS` 这类）和 agent 的「AI 们」都读它；`.env` 只在要临时换时填。某家出了新型号、下架了旧的，改这个文件，再跑 `pnpm models:check`：对着 OpenRouter 目录列出下架的、标价变了的、清单里这些厂商在核对日之后新出的（`--probe` 给每个对话 AI 的型号发一次带工具的小请求，看这边调不调得通、会不会按格式调工具）。视频、音乐、3D 每个型号怎么调（入参、标价）写在 `tools/` 的表里。

- 沙箱里用命令行程序 `oasis-tool`（`services/harness/sandbox/oasis-tool.ts`）调用，例如 `oasis-tool image.generate --prompt "……" --out out/首屏.png`。不写成 dsh 插件，换掉 dsh 也照样能用。`oasis-tool list` 列出全部工具、用法和单价，`oasis-tool <工具> --help` 只看一个、连同每个参数。
- 生图、视频、配音、音乐、3D 做出的文件花了用户的钱，都留给用户：`--out` 只能写在交付目录里（沙箱里是 `/workspace/out/`，用户电脑上是项目里的 `.oasis/out/`，由 `OASIS_OUT_DIR` 给出绝对路径，AI 在别的目录里跑命令也一样），写到别处这次不提交、不收费，告诉 AI 存进 `out/`、素材存进 `out/素材/`（`tool-files.ts` 的 `requireDelivered`）。
- 每次调用和模型调用一样：冻结额度 → 调供应商 → 按实际花费（拿不到就按目录单价 × 数量）结算 → 记调用记录（记着属于哪一轮）。
- 生音乐、生成 3D 在 fal 上按型号标价（fal 不按调用回报花费）：冻结是这次标价的 1.2 倍，音乐不低于 $0.5、3D 不低于 $1；按时长计价的音乐型号照 `--duration` 算标价，结果里带实际时长的照实际的算。供应商明说没生成（内容审核拦下、它下游的服务出错）就不收费，把它说的原因交回去。
- 私聊把花钱的工具设成「问我」时（这一轮的临时 Key 带着 `askPaid`），生图、视频这类工具交上去先登记一张确认卡、回给 `oasis-tool` 确认号，不冻结、不调供应商；用户点了允许，`oasis-tool` 带着确认号重交才真正调用（见《私聊与一轮》§7）。
- 供应商的 Key 只在 model-gateway。生成的文件由 model-gateway 取回，先存进自己的私有对象存储并校验，再交给 `oasis-tool`；沙箱不直连供应商。
- **长任务**（视频、音乐、3D、云渲染）：提交后拿到任务号，`oasis-tool` 自己轮询，一条命令最多等 100 秒（`OASIS_TOOL_WAIT_SECONDS`），没等到就把任务号告诉 AI，之后用 `oasis-tool wait <任务号>` 接着等。等待期间不调模型。进度记在 `tool_jobs`，重启后接着查；同一轮里用同样参数重做时取回原来的结果，不重复生成。
- **几个一起做**：生图一次最多 4 张同时生成——同一个画面几张用 `--n`，几个不同画面用 `--prompts '["…","…"]'`（存成 `名字-1`、`名字-2`……，号和描述的顺序对得上，中间有一张没做出来就空着号）。长任务加 `--wait false` 只提交、马上给任务号（交的时候写的 `--out` 记在恢复记录里），几个都交完后 `oasis-tool wait 任务号1 任务号2 …` 一起等，各存到各自的 `--out`；有一个没做出来，其余的照样等完。
- **同时在做的上限**：每个人同时在做的生图、视频、音乐、3D 生成最多 4 个（一次 `image.generate` 算一个，按调用记录里还没做完的数），超了直接拒绝（429 `too_many_running`），说清楚在做的是哪些，没有提交也没有收费。
- 进度页要用的：`oasis-tool`、`oasis-op` 存下文件时输出「已保存：路径」，长任务交上去没等时输出「已提交，没等结果（任务号 X）」，等到时先输出「做好了（任务号 X）」再存它的文件，每个「已保存」后面带「（任务号 X）」（AI 常只看输出的末几行，靠它对上任务号）。harness 从完整输出里认出这些（`adapter/step-facts.ts`；等的命令放到后台时，结果在之后看它输出的 `job_output` 那一步里），连同 AI 写、改的文件和调的 `oasis-tool` 工具名、点名的型号一起写进运行事件（见《私聊与一轮》§1）；只是查用法（`--help`）的不算调用工具。`oasis-tool` 没做成时命令退出码不是 0、输出里有「oasis-tool 出错：…」，dsh 照样算这次调用成功，harness 把这一步记成没做完、带上出错的那句。harness 有内部接口读一轮工作目录里的一个文件（`/internal/runs/:id/workspace/*`）：都从这个会话的工作目录里现读（只给普通文件）。
- 参数定义一份几处用：`packages/contracts/src/tool-args.ts`、`ops.ts`。工具目录、`oasis-tool`、`oasis-op` 用同一份检查参数。

现有的工具：

| 类别 | 工具 |
|---|---|
| 生成 | `image.generate`、`video.generate`、`audio.speech`、`audio.music`、`3d.generate`（给一张参考图或一段文字生成 3D）、`3d.render`（云 GPU 渲染） |
| 看和听 | `media.inspect`（图片、视频、音频可以混着给，1 到 4 个文件）、`audio.transcribe` |
| 联网 | `web.search`、`web.fetch`（Tavily）；用户关了这段私聊的联网搜索时不给（《私聊与一轮》§7） |
| 判断和问 | `jev.decide`、`model.ask`（问另一个模型）、`text.batch` |
| 检查 | `app.check`、`website.test`、`android.test`（见《检查与交付》） |
| 本地操作 | `op.video.concat`、`op.video.trim`、`op.video.frames`、`op.video.audio`、`op.audio.concat`、`op.media.convert`：沙箱里的 `oasis-op` 用 ffmpeg 做，不花工具钱 |

`media.inspect` 的型号清单是 `TOOL_INSPECT_MODELS`，每个型号读得了哪几种文件照供应商目录；调用时只留读得了这次全部文件的型号。干活的 AI 的型号最多能直接看图，视频和音频都要用 `media.inspect`。

## 3. 别的模型怎么用

私聊里干活的 AI 一直握着全部过程，别的模型被它叫来做一件事，结果交回它手里：

1. **当工具用**：上表里的生成、看和听、`model.ask`。`model.ask` 是一个问题加一段文字材料，拿回文字；对方只答这一次，看不到提问的 AI 的会话。能问的型号在 `TOOL_ASK_MODELS`。
2. **子 AI**：dsh 原生的 `subagent`，沙箱配置里开着，可以指定型号。什么时候用由干活的 AI 判断。

## 4. 型号

- 私聊里每个 AI 的型号和人设由 agent 给（AI 目录）。
- **实测数据**：model-gateway 从调用记录里算每个型号最近 30 天的每秒输出 token、含缓存的实际单价、上游出错的比例（只算沙箱里的聊天调用，不到 30 次的不算），写进 `model.ask` 的工具说明。开关是 `ESTIMATE_FROM_HISTORY`，开发环境默认关（开发库里混着假模型回归的记录）。哪个型号更擅长哪类活没有数据，不写。
- **工具用时**：工具目录里每个型号「一次大约多久」总按调用记录的中位数算（不受上面的开关管，开关只管估价）；没有记录的型号不写。进度页上长任务的「通常约多久」就是它。
- **「只用国内模型」开关**：按账号记在 agent（`user_ai_settings`），在「AI 们」页设置，默认关。开了以后国外厂商的 AI 暂停（harness 开一轮时拒绝，409 `model_out_of_scope`，聊天记录都在）；这一轮的临时 Key 记着开关，工具目录和子 AI 能选的型号都只留国内厂商的（名单在型号清单里，`DOMESTIC_MODEL_VENDORS` 可以临时覆盖），点名国外型号的工具调用在调供应商之前就拒绝。

## 5. 给 AI 的话

给 AI 的说明只有三种：**事实**（有什么、多少钱、各自看得到什么）、**硬约束**（格式、上限、系统做不到的事、角色边界）、**用户的要求**（用户的话、确认过的任务单、修改意见）。不写「尽量、宁可、只在…时才、够用就」这类把选择往一边推的话；背后有事实的改成只写事实，没有的删掉。

- 平台说明在 `services/harness/guide/AGENTS.md`（怎么聊、怎么干活、怎么交付、什么时候问用户和给任务单）。场景经验在 `services/harness/guide/playbooks/*.md`（网页、文档、图片、音频、视频、3D、数字人等 11 份），放成 dsh 的技能，AI 用得上时自己读。
- 交互网页、3D 预览等的文件格式写在 `in/.oasis-formats.json`。

## 6. 算力

harness 按每一轮用了多久（从冻结到这一轮结束；空着等下一轮的那一会儿不收）× 核数 × 单价计费（`COMPUTE_PRICE_MICRO_PER_CORE_HOUR`，默认每核每小时 $0.015）。一轮开始时在 model-gateway 冻结，结束时按实际时长结算，调用记录的 `kind` 是 `compute`。检查容器的算力同一套（见《检查与交付》§3）。

## 7. 音视频

- 配音、转写、生视频走 OpenRouter；生音乐走 fal（`FAL_API_KEY`，型号在型号清单里）。
- 大文件按流处理：canvas 上传直接流向私有桶，harness 流式读沙箱的 `out/`，较大的工具结果只给带归属和有效期的文件引用，`oasis-tool` 分块下载并核对哈希。
- 视频工程：交付可播放的 MP4 时可以附 Shotcut 工程（`project.mlt` 加 `media/` 素材，相对路径），用同一份时间轴生成工程和成片。

## 8. 3D 和云渲染

- 两条路线，AI 自己选：生成 3D（`3d.generate`，fal：给一张参考图或一段文字，两种是不同的型号，都在型号清单里），或在 3D 沙箱里用 Blender 写脚本建模。
- 3D 沙箱里的工具：`oasis-3d snapshot <模型>`（多视角图，Cycles CPU）、`oasis-3d check <模型>`（尺寸、贴地、网格问题、画布预览问题、glTF 校验）、`oasis_blender` 模块（材质、导出 GLB、取景、渲染）。
- 云 GPU 渲染（`3d.render`，Runpod）：GPU 侧只接受验证过的几何资产和声明式场景参数，由镜像里的固定入口构建和渲染，不接收任意脚本或镜像。扣款 = (执行秒 + 最多 90 秒延迟 + 5 秒空闲) × 锁定单价，封顶冻结额；GPU 失败退回冻结。只取回成品图。渲染 worker 镜像 `oasis/harness-render` 按不可变摘要拉取。
- 画布里交互预览 GLB；3D 导演台（视角、线框、网格、灯光、动画）只为看图。

## 9. 实时数字人

- 交付的是一份数字人配置（人设、开场白、知识要点、转人工规则、形象、声音、语言）。成果页点「开始对话」才开实时会话。
- 供应商是 LiveAvatar（FULL 模式：听写、配音、口型、形象由它负责），大脑接我们自己的模型：LiveAvatar 每轮调用 model-gateway 单独端口（`AVATAR_LLM_PORT`，默认 4118）上的 `/avatar/v1/chat/completions`，只认会话专用的临时 Key。公网只暴露这一条路径（线上由入口容器转过来，见 `docs/ops/部署.md`；开发机没有公网入口）。
- 计费：开始时按最长分钟数冻结，结束按实际分钟结算；大模型调用照常计量。浏览器关掉发不出「结束」时，model-gateway 的清扫任务查到会话状态后停止并结算。
- 开发环境沙箱（`AVATAR_SANDBOX=true`）：免费，约 1 分钟自动结束，但 LiveAvatar 只给官方测试形象和它的声音，配置里选的形象、声音不生效，对话页写明了这一点。看真实形象要临时改成 `false`（按分钟扣积分）。
- 说话要麦克风：桌面端只放行自己页面的麦克风，别的权限一律拒绝；浏览器里由浏览器问用户。都不给时可以打字提问。

## 10. 在用户电脑上

这段对话的家在用户电脑上时（《私聊与一轮》§7），harness 用第二种执行器 `executor/device.ts`：和 Docker 执行器同一个接口（起进程、标准输入输出、取文件、结束、会话在不在、清会话），消息经桌面版的 WebSocket 转发，适配层原样用。

- **位置**：沙箱里的目录换成电脑上的——工作目录 `/workspace` → 项目里的 `.oasis/`（dsh 的工作目录是项目文件夹本身）；dsh 用户目录 → 桌面版数据目录里这个会话的 dsh 家目录；`/opt/oasis` → 家目录下的 `tools/`。路径和环境变量里写成 `{project}`、`{home}`、`{origin}`，桌面版换成实际的。桌面版只认这两个地方，放进来的包跳不出去；交给 dsh 的环境变量只收 `OASIS_`、`DSH_` 开头的。
- **权限档**：手动 → `workspace-write`（要做出文件夹的事时 dsh 来问，插件 `approval.mjs` 向 Oasis 登记确认卡、长轮询等结果；点过「以后都允许」的由插件直接答允许），自动 → `danger-full-access`（不问）。组合里就配这两个预设，`approval.mjs` 每轮把会话切到这一轮的预设（`DSH_PERMISSION_MODE`）。
- **Windows**：dsh 用受限令牌把写限制在项目文件夹里，要求当前用户对文件夹有完全控制（D 盘的目录默认只有「修改」），桌面版在用户选文件夹时用 `icacls` 给自己加上；受限令牌只限写，不限网络，所以 `oasis-tool` 照样连得上 Oasis。命令行是 PowerShell（有 PowerShell 7 用 7，没有用 5.1），执行策略不放开，`oasis-tool`、`oasis-op` 是会话家目录 `bin/` 里的 `.cmd`，用电脑上的 node 跑 `tools/` 里的脚本。经 PowerShell 给 `.cmd` 传 JSON 参数时里面的双引号要写成 `\"`（5.1 时这种参数里不能带空格），说明里写给了 AI（`guide/device.md`）。
- **不一样的地方**：不跑平台的命令（电脑上不一定有 LibreOffice，Word、PPT 不配 PDF）；没有 `oasis-media`；不收算力钱、不占云端并发。macOS（Seatbelt）和 Linux 没有机器测过。
