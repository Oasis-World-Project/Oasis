# 工具与沙箱

现在是怎么做的。为什么这么定，在 git 历史里。

## 1. 沙箱

- 私聊的每一轮起一个容器，容器里只跑 dsh（精确锁定版本，经 stdin/stdout 说 JSON-RPC）。全仓只有 `services/harness/src/adapter/` 接触 dsh。
- 镜像：`oasis/harness-sandbox-base:<dsh 版本>`（`pnpm sandbox:build`）和带 Blender 的 `oasis/harness-sandbox-3d`（`pnpm sandbox:build:3d`）。harness 用哪个由 `SANDBOX_IMAGE` 定。
- 默认 2 核 2 GB、最多 512 个进程（`SANDBOX_CPUS`、`SANDBOX_MEMORY_MB`）。没有显卡，3D 页面靠 CPU 画。实测：用 Chromium 驱动带 WebGL 的页面，内存峰值约 445 MiB、进程 212 个；一次 50 分钟的小游戏运行（反复开浏览器自查、生音频），内存峰值 799 MiB、进程 206 个。
- 目录：`in/`（平台放的说明：沙箱里有什么、文件格式）、`materials/`（用户随消息发的文件；「让 AI 改」之前话题的成果在 `materials/canvas/` 下）、`out/`（要交出的文件）。文件由 harness 拷进拷出，容器不直接访问对象存储。
- 正常做完时，harness 存产出前先在容器里用 LibreOffice 给 `out/` 里的 Word、PPT 各配一份同名 PDF（已有同名 PDF 的不动，单个最多 2 分钟，转不了不挡交付），画布按这份 PDF 预览，和下载的样子一致。
- 网络：容器在内部网络里，不通外网。只能经入口代理访问 model-gateway 的 `/run/v1/*`（模型、工具），带着这次运行的临时 Key；经出口代理访问明确放行的软件包仓库（`SANDBOX_EGRESS_ALLOW_HOSTS`，npm 和 PyPI），所以 `npm install`、`pip install` 能用。碰不到任何服务的 `/internal`。
- 一轮结束或取消时销毁容器、作废临时 Key。工作目录和 dsh 会话留在这个会话的持久卷里，下一轮接着做（见《私聊与一轮》§2）。
- 开沙箱时 harness 把平台说明放成 dsh 的用户级 `AGENTS.md`、场景经验（`services/harness/guide/playbooks/*.md`）放成技能，并把当前版本的 `oasis-tool`、`oasis-op` 和它们用到的两个契约文件放进 `/opt/oasis`：改了这些命令不用重建镜像（镜像里那份只给离线验收用）。

### 预装的东西

写在镜像的 `/opt/oasis/software.txt`，`oasis-tool list` 会列出来；沙箱里有什么也写在 `in/.oasis-environment.json`。

| 用途 | 预装 |
|---|---|
| 网页、小游戏 | Node、Chromium、playwright-core、esbuild、typescript |
| 文档、数据 | LibreOffice、pandoc、poppler、sqlite3、jq，Python 的 pandas、openpyxl、python-docx 等 |
| 图片 | Pillow、ImageMagick |
| 字体（`/usr/share/fonts`，可以拷进成果或取子集后内嵌） | Noto CJK、Noto Color Emoji、点阵像素字体 Unifont（16×16，含中文） |
| 音视频 | ffmpeg、MLT（melt）、sox |
| 代码项目 | Python 3、git、ripgrep、zip、unzip、make、g++ |
| 3D（3D 镜像） | Blender、`oasis-3d`、`oasis_blender` 模块、`@gltf-transform/cli`、trimesh |

Chromium 的默认参数已经按沙箱的限制配好（非 root、`/dev/shm` 只有 64 MB、没有显卡），不带参数的 `chromium.launch()` 就能用。

## 2. 工具目录和调用

工具目录在 model-gateway（定义在 `src/service/tools/`，和供应商适配放在一起）：一个工具的名字、参数、调用方式和计费是一体的。没配 Key 的工具自动不可用。

- 沙箱里用命令行程序 `oasis-tool`（`services/harness/sandbox/oasis-tool.ts`）调用，例如 `oasis-tool image.generate --prompt "……" --out out/首屏.png`。不写成 dsh 插件，换掉 dsh 也照样能用。`oasis-tool list` 列出全部工具、用法和单价，`oasis-tool <工具> --help` 只看一个、连同每个参数。
- 每次调用和模型调用一样：冻结额度 → 调供应商 → 按实际花费（拿不到就按目录单价 × 数量）结算 → 记调用记录（记着属于哪一轮）。
- 供应商的 Key 只在 model-gateway。生成的文件由 model-gateway 取回，先存进自己的私有对象存储并校验，再交给 `oasis-tool`；沙箱不直连供应商。
- **长任务**（视频、音乐、3D、云渲染）：提交后拿到任务号，`oasis-tool` 自己轮询，一条命令最多等 100 秒（`OASIS_TOOL_WAIT_SECONDS`），没等到就把任务号告诉 AI，之后用 `oasis-tool wait <任务号>` 接着等。等待期间不调模型。进度记在 `tool_jobs`，重启后接着查；同一轮里用同样参数重做时取回原来的结果，不重复生成。
- **几个一起做**：生图一次最多 4 张同时生成——同一个画面几张用 `--n`，几个不同画面用 `--prompts '["…","…"]'`（存成 `名字-1`、`名字-2`……，号和描述的顺序对得上，中间有一张没做出来就空着号）。长任务加 `--wait false` 只提交、马上给任务号（交的时候写的 `--out` 记在恢复记录里），几个都交完后 `oasis-tool wait 任务号1 任务号2 …` 一起等，各存到各自的 `--out`；有一个没做出来，其余的照样等完。
- **同时在做的上限**：每个人同时在做的生图、视频、音乐、3D 生成最多 4 个（一次 `image.generate` 算一个，按调用记录里还没做完的数），超了直接拒绝（429 `too_many_running`），说清楚在做的是哪些，没有提交也没有收费。
- 进度页要用的：`oasis-tool`、`oasis-op` 存下文件时输出「已保存：路径」，长任务交上去没等时输出「已提交，没等结果（任务号 X）」，等到时先输出「做好了（任务号 X）」再存它的文件，每个「已保存」后面带「（任务号 X）」（AI 常只看输出的末几行，靠它对上任务号）。harness 从完整输出里认出这些（`adapter/step-facts.ts`；等的命令放到后台时，结果在之后看它输出的 `job_output` 那一步里），连同 AI 写、改的文件和调的 `oasis-tool` 工具名、点名的型号一起写进运行事件（见《私聊与一轮》§1）；只是查用法（`--help`）的不算调用工具。harness 有内部接口读一轮工作目录里的一个文件（`/internal/runs/:id/workspace/*`）：沙箱还在就从沙箱读（只给普通文件），结束后从产出包读（只剩 `out/`）。
- 参数定义一份几处用：`packages/contracts/src/tool-args.ts`、`ops.ts`。工具目录、`oasis-tool`、`oasis-op` 用同一份检查参数。

现有的工具：

| 类别 | 工具 |
|---|---|
| 生成 | `image.generate`、`video.generate`、`audio.speech`、`audio.music`、`3d.generate`（图生 3D）、`3d.render`（云 GPU 渲染） |
| 看和听 | `media.inspect`（图片、视频、音频可以混着给，1 到 4 个文件）、`audio.transcribe` |
| 联网 | `web.search`、`web.fetch`（Tavily） |
| 判断和问 | `jev.decide`、`model.ask`（问另一个模型）、`text.batch` |
| 检查 | `app.check`、`website.test`、`android.test`（见《检查与交付》） |
| 本地操作 | `op.video.concat`、`op.video.trim`、`op.video.frames`、`op.video.audio`、`op.audio.concat`、`op.media.convert`：沙箱里的 `oasis-op` 用 ffmpeg 做，不花工具钱 |

`media.inspect` 的型号清单是 `TOOL_INSPECT_MODELS`，每个型号读得了哪几种文件照供应商目录；调用时只留读得了这次全部文件的型号。干活的 AI 的型号最多能直接看图，视频和音频都要用 `media.inspect`。

## 3. 别的模型怎么用

私聊里干活的 AI 一直握着全部过程，别的模型被它叫来做一件事，结果交回它手里：

1. **当工具用**：上表里的生成、看和听、`model.ask`。`model.ask` 是一个问题加一段文字材料，拿回文字；对方只答这一次，看不到提问的 AI 的会话。能问的型号在 `TOOL_ASK_MODELS`。
2. **子 AI**：dsh 原生的 `subagent`，沙箱配置里开着，可以指定型号。什么时候用由干活的 AI 判断。

## 4. 型号

- 私聊里每个 AI 的型号和人设由 agent 给（AI 目录）。
- **实测数据**：model-gateway 从调用记录里算每个型号最近 30 天的每秒输出 token、含缓存的实际单价、上游出错的比例（只算沙箱里的聊天调用，不到 30 次的不算），写进 `model.ask` 的工具说明。开关是 `ESTIMATE_FROM_HISTORY`，开发环境默认关（开发库里混着假模型回归的记录）。哪个型号更擅长哪类活没有数据，不写。
- **工具用时**：工具目录里每个型号「一次大约多久」总按调用记录的中位数算（不受上面的开关管，开关只管估价）；没有记录的型号不写。进度页上长任务的「通常约多久」就是它。
- **「只用国内模型」开关**：按账号记在 agent（`user_ai_settings`），在「AI 们」页设置，默认关。开了以后国外厂商的 AI 暂停（harness 开一轮时拒绝，409 `model_out_of_scope`，聊天记录都在）；这一轮的临时 Key 记着开关，工具目录和子 AI 能选的型号都只留国内厂商的（名单 `DOMESTIC_MODEL_VENDORS`），点名国外型号的工具调用在调供应商之前就拒绝。

## 5. 给 AI 的话

给 AI 的说明只有三种：**事实**（有什么、多少钱、各自看得到什么）、**硬约束**（格式、上限、系统做不到的事、角色边界）、**用户的要求**（用户的话、确认过的任务单、修改意见）。不写「尽量、宁可、只在…时才、够用就」这类把选择往一边推的话；背后有事实的改成只写事实，没有的删掉。

- 平台说明在 `services/harness/guide/AGENTS.md`（怎么聊、怎么干活、怎么交付、什么时候问用户和给任务单）。场景经验在 `services/harness/guide/playbooks/*.md`（网页、文档、图片、音频、视频、3D、数字人等 11 份），放成 dsh 的技能，AI 用得上时自己读。
- 交互网页、3D 预览等的文件格式写在 `in/.oasis-formats.json`。

## 6. 算力

harness 按沙箱容器实际存在的时长 × 核数 × 单价计费（`COMPUTE_PRICE_MICRO_PER_CORE_HOUR`，默认每核每小时 $0.015）。开容器前在 model-gateway 冻结，销毁后按实际时长结算，调用记录的 `kind` 是 `compute`。检查容器的算力同一套（见《检查与交付》§3）。

## 7. 音视频

- 配音、转写、生视频走 OpenRouter；生音乐走 fal（`FAL_API_KEY`，型号 `TOOL_MUSIC_MODELS`）。
- 大文件按流处理：canvas 上传直接流向私有桶，harness 流式读沙箱的 `out/`，较大的工具结果只给带归属和有效期的文件引用，`oasis-tool` 分块下载并核对哈希。
- 视频工程：交付可播放的 MP4 时可以附 Shotcut 工程（`project.mlt` 加 `media/` 素材，相对路径），用同一份时间轴生成工程和成片。

## 8. 3D 和云渲染

- 两条路线，AI 自己选：图生 3D（`3d.generate`，fal，型号 `TOOL_GEOMETRY_MODELS`），或在 3D 沙箱里用 Blender 写脚本建模。
- 3D 沙箱里的工具：`oasis-3d snapshot <模型>`（多视角图，Cycles CPU）、`oasis-3d check <模型>`（尺寸、贴地、网格问题、画布预览问题、glTF 校验）、`oasis_blender` 模块（材质、导出 GLB、取景、渲染）。
- 云 GPU 渲染（`3d.render`，Runpod）：GPU 侧只接受验证过的几何资产和声明式场景参数，由镜像里的固定入口构建和渲染，不接收任意脚本或镜像。扣款 = (执行秒 + 最多 90 秒延迟 + 5 秒空闲) × 锁定单价，封顶冻结额；GPU 失败退回冻结。只取回成品图。渲染 worker 镜像 `oasis/harness-render` 按不可变摘要拉取。
- 画布里交互预览 GLB；3D 导演台（视角、线框、网格、灯光、动画）只为看图。

## 9. 实时数字人

- 交付的是一份数字人配置（人设、开场白、知识要点、转人工规则、形象、声音、语言）。成果页点「开始对话」才开实时会话。
- 供应商是 LiveAvatar（FULL 模式：听写、配音、口型、形象由它负责），大脑接我们自己的模型：LiveAvatar 每轮调用 model-gateway 单独端口（`AVATAR_LLM_PORT`，默认 4118）上的 `/avatar/v1/chat/completions`，只认会话专用的临时 Key。公网只暴露这一条路径（开发期怎么暴露见 `docs/ops/云服务器.md`）。
- 计费：开始时按最长分钟数冻结，结束按实际分钟结算；大模型调用照常计量。浏览器关掉发不出「结束」时，model-gateway 的清扫任务查到会话状态后停止并结算。
