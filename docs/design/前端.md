# 前端

现在是怎么做的。前端约定（组件、样式、测试）在 `AGENTS.md`。为什么这么定，在 git 历史里（`git log -- docs/adr`）。

界面只有 `apps/web` 一套，Electron 桌面端（`apps/desktop`）加载的就是它。功能以桌面端为准（见《架构》§7）。

## 1. 私聊

- 和一个 AI 聊天，回复是 SSE 流：`accepted` → 多个 `delta` → `done`，出错时最后一个事件是 `error`。浏览器断开后服务端继续生成并保存。带整段对话作上下文，快到窗口时压缩较早的部分。
- 停止后可以「继续回复」：接着已经收到的正文往下写，不新建用户消息。
- 输入框「＋」菜单：添加文件、「只用国内模型」开关。文件也可以拖进来或粘贴；选中后立即上传到 canvas（单个最多 100 MB、一条消息最多 10 个），全部传完才能发送。
- 右上角可以删除整个私聊：任务和成果不受影响。

### 任务在私聊里

- 每条用户消息先判断一次是不是在交代一件要交付成果的事；也可以直接点「发任务」。
- 接需求由正在聊的这个 AI 做：conversation 直接调它的模型，要它按固定 JSON 回答，要么给问题卡，要么给任务单。问题卡是选择题，每题带默认项和「你看着办」；用户可以点「直接开始」。
- 任务单卡：标题、要交付的东西、怎么算做好、风格与限制、AI 自己定的事、素材。用户确认后建任务。任务单上没有预算。
- 任务卡只存 `taskId`，进度、已花的钱、需要处理的原因由前端向 task 查；任务还在动时定时刷新。
- 「需要处理」时按原因给选择：节点失败（再试一次、跳过它继续、取消）、规划失败（重新规划、取消）、修改方案等确认（确认修改、不改了）。
- 交付消息按交付物列出文件，可以预览和下载。只在任务第一次交付时发。

## 2. 群聊

- 建群、邀请（一次性邀请码，24 小时有效，库里只存摘要）、移除成员、退出、解散。群内名由用户自己填，不通过群暴露邮箱。
- 纯文字消息，客户端 `requestId` 去重；SSE 推送成员和消息。非成员读取或发送一律 404。
- 默认每群 50 人、每人 20 个群（`GROUP_*` 配置）。
- 群里现在没有 AI、任务和附件。

## 3. 工作流页

见《任务与工作流》§8。代码在 `apps/web/src/workflow/`：`rules.ts`（状态、能做什么、任务清单怎么取）、`layout.ts`（排版）、`WorkflowGraph.tsx`、`NodeCard.tsx`（三种框）、`NodePanel.tsx`（详情）、`use-progress.ts`（从运行事件取每样成果做到哪了）。

## 4. 画布和成果页

- `/canvas`：类别标签、搜索、成果卡片，可以按任务筛选。类别由 canvas 按扩展名定：文档和图片、音频和视频、3D 和实景、网页和应用、数据和其他。
- 成果页：图片、视频、音频、PDF、Markdown、文字直接预览；网页和静态应用在隔离框里运行（见《检查与交付》§5）；GLB 模型交互预览，带 3D 导演台（视角、线框、网格、灯光、动画）；数字人成果可以「开始对话」；其他格式提示下载。
- 顶栏三个图标：返回、批注、下载。应用的下载是整个任务的压缩包。
- 批注：图片上圈画；运行中的网页、应用、3D 模型先截下此刻的画面再圈画（桌面端）。批注面板底部「发给 AI 团队修改」。
- 任务卡片上可以删除任务（真删除）。

## 5. 桌面端

- preload 只暴露 `oasisDesktop` 的几个接口：选同步文件夹、看同步状态、写一个文件、打开文件夹、截取页面上一个矩形。
- 「同步到电脑」：用户用系统对话框选文件夹后，把还没同步过的成果下载进去（`<文件夹>/<任务名>/<文件路径>`）。主进程只往这个文件夹里写，路径不能跳出去，已有同名文件不覆盖。
- 点下载时文件存进系统的「下载」文件夹，存好后在文件管理器里选中它。
- 截图由主进程 `webContents.capturePage` 截运行框所在的矩形，只接受本应用主页面的请求。
