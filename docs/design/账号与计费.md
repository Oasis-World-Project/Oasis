# 账号与计费

现在是怎么做的。为什么这么定，在 git 历史里（`git log -- docs/adr`）。

## 1. 登录和会话

- 邮箱加验证码，本地用 Mailpit 收信。验证码 6 位数字，10 分钟有效；同一邮箱 60 秒内只能发一次、每小时最多 5 次；每个验证码最多试 5 次。库里只存 HMAC（密钥 `AUTH_CODE_PEPPER`，绑定邮箱），比较用常数时间。
- 第一次验证就是注册，这时发账号 ID、起默认的名字（账号资料见《好友》§1）。验证码核销、建用户、写 outbox 事件、建会话在同一个事务里。
- 会话令牌是 32 字节随机数，库里只存 sha256；默认 30 天，最多每小时续一次。只用 Cookie `oasis_session`（httpOnly、SameSite=Lax；`COOKIE_SECURE` 本地为 false，线上必须为 true）。前端拿不到令牌。
- gateway 负责鉴权：调 identity 的 `/internal/sessions/introspect`，结果按令牌哈希缓存 30 秒（`SESSION_CACHE_TTL_MS`）。所以退出登录后旧 Cookie 最晚 30 秒失效，这是有意的取舍。
- gateway 先删掉客户端传来的所有 `x-oasis-*` 头，再写入 `x-oasis-user-id`。Cookie 只转发给 identity。
- CSRF：写请求的 `Origin` 必须在 `GATEWAY_ALLOWED_ORIGINS` 里，否则 403。登录后的跳转地址只接受站内路径。

## 2. 额度

- 金额一律用微美元整数（1 美元 = 1,000,000）。
- 注册送额度：identity 写 outbox → `identity.user.registered` → billing 发放 `SIGNUP_GRANT_MICRO`（默认 30,000,000）。三层去重：消息 ID、`processed_events` 表、账本上的唯一索引。钱包还没建好时 `/v1/wallet` 返回 404 `wallet_not_ready`，前端稍等重试。
- 钱包按账户算：个人的账户号是用户 ID，群的金库是群的 ID，都在 billing 的 `wallets` 里（`user_id` 这一列就是账户号）。花哪个账户的钱由调用方在 `x-oasis-payer-id` 里指明：私聊花主人自己的，群里的 AI 花群的金库。
- **金库**（用户 2026-11-26 定）：群里的 AI 花的钱（模型、工具、云端沙箱、判断谁想接话）都从群的金库出，金库从 0 开始。
  - 存入：群成员从自己的钱包转进去（`POST /v1/groups/:id/vault/deposits`，conversation 核对是群成员后调 billing 的 `/internal/treasuries/:id/deposits`），存进去就是群的，不能取回。账本上记两条：这个人的 `transfer_out`、金库的 `transfer_in`。
  - 记在谁头上：冻结和扣费的流水上记着是谁叫 AI 花的（`actor_id`，调用方在 `x-oasis-actor-id` 或临时 Key 上带来）。没人叫的（AI 自己接话、判断谁想接话）只算进总数。金库页（`GET /v1/groups/:id/vault`）给出现在有多少、一共存了花了多少、每个人存了多少、叫 AI 花了多少。
  - 空了：群里的 AI 开一轮前 conversation 先看一眼金库，没钱就不开，它那条消息写「金库空了，存入后群里的 AI 才能用」（402 `vault_empty`）。做到一半花完的和个人钱包一样，这一轮按余额不够停下。
  - 解散：解散群时金库里没被冻结的钱按各人累计存入的比例退回各自的钱包（除不尽的零头给存得最多的人；退了群的人也有份），金库记成已解散、不能再冻结。解散时还冻结着的钱，结算或退回之后由清扫任务接着按比例退。退不成就不删群，可以再点一次。
  - 送的额度仍算送的：存入时流水上记着其中多少是注册送的额度（`detail.giftedMicro`，送的先花、先存），退回时按同样的比例记回去。

## 3. 每次调用怎么扣

模型调用、工具调用、算力都走同一套，都在 model-gateway 计量：

1. **冻结**：按价格表和输出上限估一笔，查不到价格用 `FALLBACK_HOLD_MICRO`。余额不够返回 402 `insufficient_balance`。
2. **调用**。
3. **结算或退回**：按实际花费结算，多冻结的退回。实际花费的来源按优先级：供应商返回的花费 > token 数 × 价格表 > 按字数估算；每次调用记下用的是哪一种（`cost_source`）。流断掉的调用凭生成 ID 向供应商查实际花费，不按字数估。

- 实际扣费 = 花费 × `BILLING_PRICE_MULTIPLIER`（默认 1.0），向上取整到微美元。超出余额的部分记为未收回，不会扣成负数。
- 失败就退回冻结。进程中途崩溃时，冻结超过 `HOLD_TTL_MS` 由清扫任务退回。
- 调用记录的 `kind`：`chat`（模型）、`tool`（工具）、`compute`（沙箱和检查容器的算力）。调用记着它属于哪一轮（`run_id`），一轮花了多少由 conversation 向 model-gateway 汇总（`/internal/v1/runs/:runId/spend`），写在 AI 的消息和任务卡上。
- 缓存：沙箱里的 dsh 每次调模型都带会话编号（`x-session-id`），model-gateway 原样作为 `session_id` 交给 OpenRouter，同一会话尽量固定在同一家供应商、吃得到上次的缓存。调用记录里记下这次输入有多少读的缓存、多少写进缓存（`cached_tokens`、`cache_write_tokens`）。Claude 这类要标缓存位置的，dsh 自己会标。
- 送到哪几家：OpenRouter 账号里放开了「会拿请求训练的付费供应商」，只为用 DeepSeek 官方（用户 11-14 定）。DeepSeek 的型号先只走官方，官方出错再换别家；别的型号、换的别家，都只走不拿请求训练的（`data_collection: deny`）。写在 `adapters/openrouter.ts` 的聊天请求里。官方这家 V4.1 Flash 的单价约是最便宜那家的 3 倍（每百万 token 输入 $0.15、输出 $0.60）。
- 哪家答的、哪家不送：同一型号在 OpenRouter 上有好几家在跑，各家的表现不一样，网关又把同一段会话固定在一家，所以一家出问题会错一整轮（2026-11-26：Kimi K2.5 在 Amazon Bedrock 上不把工具结果交给模型，一轮空转了 83 次调用）。
  - 每次模型调用记下 OpenRouter 转给了哪家（`calls.provider`）和发出去的消息有多少字符（`calls.input_chars`，不含工具定义和多媒体）。
  - 实测有问题的写在 `adapters/openrouter.ts` 的 `PROVIDERS_TO_AVOID`（型号 → 供应商），哪次都不送（`provider.ignore`）。
  - 没写在清单里的自动避开（`service/provider-health.ts`）：供应商报回的输入 token 少得不可能（消息至少 2 万字符、平均每个 token 超过 6 个字符，`promptFellShort`；各家实测代码每个 token 2 到 2.8 个字符，报回的 token 里还含着工具定义）就是有内容没送到模型。同一型号在同一家 6 小时里出现两次，这 6 小时先避开它；从调用记录里数，开几份服务、重启后都认。避开后没有别家接（这个型号只有它一家）时照常送。
- 一轮没有预算和上限：界面只显示已经花了多少，钱包余额用完才停。

## 4. 上游出错怎么说

上游拒绝的原因归成几类：地区限制（`provider_region_unavailable`）、限流（`provider_busy`）、其他（`provider_error`），界面据此给不同的提示。原始错误只写进日志和调用记录。流已经开始后出的错（供应商在流里报错、没收到完成标记就断了）也记进调用记录，带上 OpenRouter 把这次请求转给了哪家：同一型号在 OpenRouter 上有好几家在跑，各家的限制不一样。没配 Key 时模型调用返回 503 `provider_not_configured`。

## 5. 密钥

- 供应商的 Key（`OPENROUTER_API_KEY`、`TAVILY_API_KEY`、`FAL_API_KEY` 等）只放 model-gateway 的本地 `.env`，不进 git、日志、浏览器和沙箱。
- 沙箱里用的是每一轮一把的临时 Key：只能调模型和工具，花费记在这一轮上，这一轮结束就作废。

## 6. 删除

用户删除就是真删除，见《检查与交付》§7。保留的只有账本和调用、费用记录。
