# ADR 0008：场景 A——文件类（5.6）

- 状态：草案（2026-10-24，待用户确认第 8 节）
- 依据：`claude/business-scenarios.md`（场景 1、8、14、11、13）、ADR 0003 §10（5.6 的范围）、ADR 0005（进门和出门）、ADR 0006（工具与能力网关、经验手册）、ADR 0007（画布与预览）
- 范围：harness（沙箱镜像、文字提取）、model-gateway（工具）、task（规划、关卡、成果清单）、agent（经验手册）、conversation（任务说明）、canvas（打包下载、网页响应头）、web（预览）

## 背景

5.1–5.5 把一条任务从「私聊里说需求」走到「成果进画布、同步到电脑」，中间的规划、工具、关卡、交付都已经通了。5.6 要让五类「交付物是文件」的场景真正做得好：

| 场景 | 一句话 |
|---|---|
| 1 文档 / 表格 / 数据看板 | 把一批资料整理成报告、周报、PPT、Excel、交互看板 |
| 8 图片 | 文生图、图生图、改图、海报、批量配图 |
| 14 深度研究与情报简报 | 围绕主题或竞品查资料，写带引用、图表的报告 |
| 11 合成数据与微调数据集 | 用领域资料批量合成样本，去重、打分、过滤、出数据集 |
| 13 电商 / 营销内容 | 围绕商品批量出多平台、多版本的文案、商品图、素材包 |

## 原则

1. **不写场景模板。** 场景只出现在三个地方：经验手册（给规划员参考，不是硬规定）、通用能力（工具、沙箱里的软件）、按文件格式的预览。工作流照旧由规划员按任务单现排，代码里没有任何「场景 → 工作流」的映射。
2. **复用现有通路。** 问题卡和任务单、规划门、节点出口关卡、整体验收、交付消息、成果登记、桌面端同步都不另起一套，只补缺口。
3. **按格式写，不按场景写。** 文字提取、预览、成果登记都按文件格式处理：任何场景交出 Word，都能被关卡读到、在画布里打开。
4. **新能力先看能不能挂在已有入口上。** 例如批量生成直接走沙箱已有的模型入口，记账和计费一行不改。

## 1. 五类场景的输入与输出

### 1.1 用户给什么、AI 怎么读

用户一律经上传给素材（ADR 0007：单个文件 100 MB，一条消息 10 个，进沙箱的 `materials/`），链接写在对话里。

| 场景 | 典型输入 | 沙箱里怎么读（5.6 之后） |
|---|---|---|
| 1 | Word、PDF、PPT、Excel / CSV、数据库导出（CSV、SQL 文本）、参考模板、链接 | python-docx、python-pptx、pdfplumber、pandas、openpyxl（都预装）；扫描件和图里的字用「看图」；链接用 `web.fetch` |
| 8 | 文字要求、参考图、待修改的图、品牌规范（PDF / 图片） | 参考图和待改的图交给 `image.generate --ref`；品牌规范用上面的文档工具读 |
| 14 | 研究问题、竞品官网和新闻链接、财报 PDF、行业视频、内部资料 | `web.search` / `web.fetch`（长网页、PDF 链接全文写进文件）；本地 PDF 用 pdfplumber；视频用 ffmpeg 抽音轨 → `audio.transcribe`，抽关键帧 → 看图 |
| 11 | 领域文档、手册、对话记录、示例数据；数量、格式、质量要求 | 同场景 1 的文档工具；示例数据用 pandas 读 |
| 13 | 商品主图、标题、卖点、价格、活动信息、平台规范、禁用词表、品牌调性 | 主图交给 `image.generate --ref`；规范和禁用词表用文档工具读 |

### 1.2 交付格式：怎么做、关卡怎么读、画布怎么看

按格式统一，不分场景：

| 格式 | 沙箱里怎么做 | 关卡怎么读 | 画布里怎么看（5.6 之后） |
|---|---|---|---|
| Markdown / 文本 | 直接写 | 原文 | 已有（渲染 Markdown） |
| Word（.docx） | python-docx；或先写 HTML / Markdown 再用 LibreOffice 转 | harness 提取正文 | 新增：浏览器里渲染（docx-preview） |
| PPT（.pptx） | python-pptx；**同时用 LibreOffice 导出同名 PDF** | harness 提取每页文字 | 新增：显示同名 PDF；没有就提示下载 |
| PDF | HTML → WeasyPrint；或 Office → LibreOffice | harness 提取文字 | 已有（浏览器自带阅读器） |
| Excel（.xlsx） | openpyxl（公式、图表、多个工作表） | harness 提取单元格 | 新增：表格视图（分工作表，前 1000 行） |
| CSV / JSONL | pandas / 直接写 | 原文（前 8,000 字） | 新增：表格视图（JSONL 按字段成列） |
| Parquet | pyarrow | 读不了，看节点写的统计报告 | 不预览，提示下载；配套的统计报告可看 |
| 单文件 HTML（报告、看板） | 写一个 HTML，脚本、样式、图片全部内嵌（ECharts 从 npm 装好后内嵌） | 原文 | 改：允许运行页面里的脚本（第 2 节 G8），图表能切换、引用能点开 |
| 图片（PNG / JPG / WebP） | `image.generate`、Pillow 排字和改尺寸 | 新增：先「看图」得到描述，再判断 | 已有；新增同一任务的成果前后翻看 |
| 打包 | — | — | 新增：按任务「全部下载」（zip） |

### G1 沙箱镜像预装

- 系统软件：LibreOffice（Writer、Calc、Impress，无界面）、ffmpeg、poppler-utils（`pdftotext`、`pdftoppm`），以及 WeasyPrint 需要的 Pango 库。中文字体已有。
- Python 包（精确版本，写进 `requirements.txt`）：pandas、openpyxl、python-docx、python-pptx、pdfplumber、pypdf、matplotlib（设好中文字体）、Pillow、pyarrow、weasyprint、jinja2、markdown。
- 构建时 pip 走根目录 `.env` 里的 `SANDBOX_PIP_INDEX_URL`（开发机用国内镜像站）。
- 预计镜像大约增加 0.7–1 GB（以实际构建为准）。浏览器（Chromium）不在 5.6 装，5.7 定预览环境时一起定。
- 沙箱规格（2 核、2 GB、30 分钟）不变；LibreOffice 转大文件慢，在手册里提醒。

### G3 看图（`image.inspect`）

- 视觉模型列表 `TOOL_VISION_MODELS`，按地区可用性挑默认（实现时实测，候选是 Qwen-VL、GLM-V、Gemini Flash 这几类便宜的模型），地区不可用照样自动跳过。
- 按实际花费结算，目录单价约 $0.002 / 次。
- 关卡里每次最多看 4 张图；看图出错就按原来的方式（只看说明）判断，不卡用户。

### G8 单文件网页的预览安全

5.5 的做法是：网页在不带 `allow-same-origin` 的 iframe 里，服务端加 `CSP: sandbox`，脚本一律不跑。5.6 改为：

- 对 HTML 类型的成果，CSP 改为 `sandbox allow-scripts allow-popups allow-popups-to-escape-sandbox; default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; media-src data: blob:; connect-src 'none'`；iframe 同样加 `allow-scripts allow-popups`。
- 效果：页面的来源仍是不透明的，碰不到登录状态（登录 Cookie 是 `SameSite=Lax`，不透明来源发出的请求不带它）；不能联网（不能偷偷往外发数据，也不能从 CDN 加载东西，逼着 HTML 必须自带全部内容，同步到电脑后离线也能看）；外部链接（研究报告的引用）在新窗口打开。
- 桌面端：新窗口一律交给系统浏览器打开。
- 这是给「单文件报告和看板」用的；多文件的网页应用、要启动服务的原型，5.7 放到独立的预览域名和预览环境里。

## 3. 边界（冻结）

### 5.6 做

- 第 2 节的 G1–G10。
- 五类场景都能从私聊里提出需求，经规划、执行、关卡、整体验收，交付到私聊和画布，用第 1.2 节的方式看。
- 第 6 节的验收矩阵全部通过。

### 5.6 不做（以及放到哪里）

| 不做 | 去向 |
|---|---|
| 批注、打回、批准、版本对比、参数面板、「重新生成某一章 / 某一张」 | 5.11 修改成果 |
| 看板定时更新、表格在线改数 | 以后（不在第 5 阶段承诺内） |
| 多文件网页应用、要启动的原型、在画布里截图网页 | 5.7（预览环境） |
| 营销里的图生视频、剪辑、配音合成；5.6 的营销短视频只用现有的文生视频 | 5.8 |
| 投放数据回流、发布到平台、真正的 A/B 分流 | 不做；只出多个版本和分流建议 |
| 下载网上的任意文件、抓视频网站 | 不做；需要的文件由用户上传（网页和 PDF 链接的正文能读） |
| 直连用户的数据库 | 不做；只收导出的文件 |
| 桌面端本地文件夹自动上传 | 维持 ADR 0007 §10：以后再做，现在用上传 |
| 大规模多模态合成数据（图文配对上百组） | 5.6 只支持小规模（20 组以内），用生图和看图工具 |
| Parquet 在线预览 | 不做；看节点交的统计报告 |

## 4. 规划员和节点怎么用上这些（不写模板）

- 规划员的说明里只加一句：「先运行 `oasis-tool list` 看有哪些工具、沙箱里装了什么软件」（规划员本身就是一次沙箱运行）；`expects` 的新写法写进说明的例子。
- 节点的说明不变（已经会让节点先运行 `oasis-tool list`）。
- 场景的经验写在手册里，内容是「一般怎么分工、用什么工具和软件、交付物长什么样、常见的坑」，和 5.4 的两份同一个写法。规划员可以不照做。各手册的要点：
  - **数据与看板**：数字只能从数据算出来，不能编；交一份「数据核对」（每个指标怎么算的、对应源数据哪几列）；看板是单文件 HTML（ECharts 内嵌）；Excel 用公式不写死结果。
  - **深度研究**：先拆问题，再按子问题或竞品并行查资料；每条资料记出处（网址或「文件名 第 x 页」、视频「mm:ss」），写成 `来源.json`；同一指标的不同来源数字不一致时，单独列「指标冲突」；报告里每个结论标 [n]，链接到来源；要 PDF 就用 WeasyPrint 从同一份 HTML 导出。
  - **合成数据**：先从资料里抽种子（主题、事实），再用 `text.batch` 生成，用 `jev.decide --in` 打分，用代码去重（近似重复）、按阈值过滤；交数据集文件和一份 HTML 统计报告（数量、过滤原因、分数分布、抽样 20 条）。
  - **营销内容**：先提炼卖点，再按平台并行写文案（每个平台 A/B 两版）；商品图用 `--ref` 以主图为参考；尺寸用 Pillow 按平台规范裁切；合规检查先用代码查禁用词，再用 Jev 判断夸大宣传，交一份检查清单；按平台分文件夹。
  - **文档类**（改写）：Word、PPT、PDF 用预装的软件；PPT 同时导出同名 PDF。
  - **图片类**（改写）：改图、换背景用 `--ref`；交付前用 `image.inspect` 自查画面和文字；批量出图时用 `expects` 写最少张数。

## 6. 验收矩阵

### 6.1 能力验收（自动测试，假供应商，不花钱）

| 能力 | 怎么算通过 |
|---|---|
| 沙箱镜像 | 镜像里能 import 全部预装的 Python 包；`soffice --headless --convert-to pdf` 能把 docx、pptx 转成 PDF，中文不乱码；`ffmpeg`、`pdftotext`、WeasyPrint 能用；`oasis-tool list` 列出软件 |
| `--ref` | 参考图按 `input_references` 传给供应商；不支持参考图的模型被跳过；超过 4 张、不是图片时报错 |
| `image.inspect` | 冻结、结算、记调用记录、计入任务；1–4 张图；地区不可用自动换模型 |
| `text.batch` / `jev.decide --in` | 每行一次模型调用，并发不超过 4，花费计入节点；出错的行写进结果并标出，其他行照常；超过 1,000 行报错 |
| `web.fetch --out` | 全文写进文件，命令只打印摘要；文件名安全 |
| 文字提取 | docx、pptx、xlsx、pdf 各一份带中文的样例，提取结果包含正文；坏文件跳过，不让关卡出错 |
| 关卡看图 | 交付物是图片时先看图再问 Jev；看图出错照常判断 |
| `expects` 个数 | `min` 不够时，关卡给出「只有 x 个，要 y 个」；老的字符串写法照旧 |
| 成果登记 | 只登记匹配 `expects` 的文件；交付消息同一批；`expects` 为空时全登记 |
| 手册 | 新手册格式正确；一次最多附 3 份 |
| 接需求 | 任务说明里有接需求期间用户的全部原话 |
| 网页预览 | HTML 的响应头带上述 CSP；页面脚本能跑，但读不到登录状态、发不出网络请求；其他类型照旧是 `sandbox` |
| Word / PPT / 表格预览、翻看、打包 | 组件测试 + 假后端截图核对；打包的 zip 里路径和同步到电脑的路径一致 |

### 6.2 场景验收（真实模型，在你电脑上跑，先问你）

每个用例都从私聊提需求开始，走完问题卡 → 任务单 → 工作流 → 交付 → 画布。「AI 团队的排法」不验收（不规定它怎么排），只验收交出来的东西。

## 7. 受影响模块、新增和清理

- **模块**：沙箱镜像、harness（文字提取）、model-gateway（工具目录：`image.inspect`、`--ref`、`web.fetch --out`，以及 `text.batch` 的登记）、task（关卡、`expects`、成果清单、手册上限、规划员说明）、agent（手册）、conversation（任务说明）、contracts（`expects` 的写法、工具目录字段）、canvas（打包下载、HTML 的响应头）、web（预览、翻看）、desktop（新窗口交给系统浏览器）。
- **数据库**：没有迁移。
- **新文件**：4 份经验手册；沙箱的 `requirements.txt`；web 的几个预览组件（Word、表格）。不新增服务、不新增表。
- **新依赖**（第一次用到时才装，精确版本）：harness `fflate`（读 docx / pptx / xlsx 这几种 zip 格式）、`unpdf`（读 PDF 文字）；canvas `fflate`（打包 zip）；web `docx-preview`、`read-excel-file`（按需加载，不进首屏包）。Node 自带的能力做不了这两件事，现有依赖里也没有。
- **清理**：沙箱镜像重建后删掉旧标签的悬空镜像；测试用的样例文件放在各服务 `test/fixtures/`，体积控制在几十 KB。

## 8. 需要用户确认

1. **沙箱装 LibreOffice。** 镜像大约增加 0.7–1 GB。换来的是 Word / PPT 能转 PDF、PPT 能在画布里看。不装的话，PPT 只能下载后看，Word 也转不了 PDF。（建议装）
2. **单文件网页允许运行脚本。** 来源不透明、碰不到登录状态、不能联网，5.7 再换独立预览域名。这样看板能切换图表，报告里的引用能点开。不允许的话，看板只能看静态截图。（建议允许）
3. **新增两个工具用法：看图（`image.inspect`）、批量生成和批量打分（`text.batch`、`jev.decide --in`）。** 看图按次收费（约 $0.002）；批量生成每行就是一次普通的模型调用。（建议加）
4. **场景验收约 $1.85**（营销短视频另加约 $1.00，可选）。到 5.6d 再问一次。

## 风险

- 视觉模型和支持参考图的生图模型，在开发机网络上可能被地区限制。实现时先实测可用的；都不行时，关卡退回只看说明，改图类用例要等部署到海外再验。
- `web.fetch`（Tavily）能不能读出 PDF 链接的正文，要在 5.6a 实测。读不出来时，财报这类文件只能由用户上传，第 3 节的边界不变。
- LibreOffice 转复杂的 PPT 偶尔版式有偏差。PPT 本身是用 python-pptx 生成的，PDF 只用来预览。
- 单文件 HTML 里内嵌 ECharts 会让文件大约 1 MB。可以接受，同步和下载都不受影响。
- HTML 的类别按扩展名算，报告和看板会出现在「网页和应用」下。5.7 有了真正的应用预览后再按「单文件 / 应用目录」区分。
- 批量生成的花费和行数成正比。预估按目录单价 × 行数算，超过 3 倍照常暂停。
