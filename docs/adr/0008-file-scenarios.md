# ADR 0008：场景 A——文件类（5.6）

- 状态：5.6a–d 已完成（2026-10-25）；九个必选场景经真实运行、修复和独立成品核验通过，自动关卡的历史提醒保留，具体限制见第 6 节。5.6a 预检结算 $0.050488；5.6d 账内结算 $2.861151，加未确认费用的保守预留共 $4.705739，未提高原 $5 测试预算。这些金额仅约束测试，不作为产品固定预算上限；保守预留不代表供应商实扣。
- 依据：`claude/business-scenarios.md`（场景 1、8、14、11、13）、ADR 0003 §10（5.6 的范围）、ADR 0005（进门和出门）、ADR 0006（工具与能力网关、经验手册）、ADR 0007（画布与预览）
- 范围：harness（沙箱镜像、文字提取）、model-gateway（工具）、task（规划、关卡、成果清单）、agent（经验手册）、conversation（任务说明）、canvas（打包下载、网页响应头）、web（预览）

## 背景

5.1–5.5 把一条任务从「私聊里说需求」走到「成果进画布、同步到电脑」，中间的规划、工具、关卡、交付都已经通了。5.6 要让五类「交付物是文件」的场景真正做得好：

| 场景 | 一句话 |
|---|---|
| 1 文档 / 表格 / 数据看板 | 把一批资料整理成报告、周报、PPT、Excel、交互看板 |
| 8 图片 | 文生图、图生图、改图、海报、批量配图 |
| 14 深度研究与情报简报 | 围绕主题或竞品查资料，写带引用、图表的报告 |
| 11 合成数据与微调数据集 | 用领域资料批量合成样本，去重、打分、过滤、出数据集 |
| 13 电商 / 营销内容 | 围绕商品批量出多平台、多版本的文案、商品图、素材包 |

## 原则

1. **不写场景模板。** 场景只出现在三个地方：经验手册（给规划员参考，不是硬规定）、通用能力（工具、沙箱里的软件）、按文件格式的预览。工作流照旧由规划员按任务单现排，代码里没有任何「场景 → 工作流」的映射。
2. **复用现有通路。** 问题卡和任务单、规划门、节点出口关卡、整体验收、交付消息、成果登记、桌面端同步都不另起一套，只补缺口。
3. **按格式写，不按场景写。** 文字提取、预览、成果登记都按文件格式处理：任何场景交出 Word，都能被关卡读到、在画布里打开。
4. **新能力先看能不能挂在已有入口上。** 批量生成复用沙箱模型入口和逐次计费；批次停止、恢复和不确定结果处理必须单独实现和验证，不能把已有记账幂等视为请求不会重复产生费用。

## 1. 五类场景的输入与输出

### 1.1 用户给什么、AI 怎么读

用户一律经上传给素材（ADR 0007：单个文件 100 MB，一条消息 10 个，进沙箱的 `materials/`），链接写在对话里。

| 场景 | 典型输入 | 沙箱里怎么读（5.6 之后） |
|---|---|---|
| 1 | Word、PDF、PPT、Excel / CSV、数据库导出（CSV、SQL 文本）、参考模板、链接 | python-docx、python-pptx、pdfplumber、pandas、openpyxl（都预装）；扫描件和图里的字用「看图」；链接用 `web.fetch` |
| 8 | 文字要求、参考图、待修改的图、品牌规范（PDF / 图片） | 参考图和待改的图交给 `image.generate --ref`；品牌规范用上面的文档工具读 |
| 14 | 研究问题、竞品官网和新闻链接、财报 PDF、行业视频、内部资料 | `web.search` / `web.fetch`（长网页、PDF 链接全文写进文件）；本地 PDF 用 pdfplumber；视频用 ffmpeg 抽音轨 → `audio.transcribe`，抽关键帧 → 看图 |
| 11 | 领域文档、手册、对话记录、示例数据；数量、格式、质量要求 | 同场景 1 的文档工具；示例数据用 pandas 读 |
| 13 | 商品主图、标题、卖点、价格、活动信息、平台规范、禁用词表、品牌调性 | 主图交给 `image.generate --ref`；规范和禁用词表用文档工具读 |

### 1.2 交付格式：怎么做、关卡怎么读、画布怎么看

按格式统一，不分场景：

| 格式 | 沙箱里怎么做 | 关卡怎么读 | 画布里怎么看（5.6 之后） |
|---|---|---|---|
| Markdown / 文本 | 直接写 | 原文 | 已有（渲染 Markdown） |
| Word（.docx） | python-docx；或先写 HTML / Markdown 再用 LibreOffice 转 | harness 提取正文 | 新增：Mammoth 在有界 worker 中转换，经清洗后预览正文；复杂原始版式以下载文件为准 |
| PPT（.pptx） | python-pptx；**同时用 LibreOffice 导出同名 PDF** | harness 提取每页文字 | 新增：显示同名 PDF；没有就提示下载 |
| PDF | HTML → WeasyPrint；或 Office → LibreOffice | harness 提取文字 | 已有（浏览器自带阅读器） |
| Excel（.xlsx） | openpyxl（公式、图表、多个工作表） | harness 提取单元格 | 新增：表格视图（分工作表，前 1000 行） |
| CSV / JSONL | pandas / 直接写 | 按所选成果读取有界正文，截断时标记未检查 | 新增：表格视图（JSONL 按字段成列） |

| 单文件 HTML（报告、看板） | 写一个离线 HTML；需应用内交互时附受校验的 oasis-dashboard JSON | 提取可见正文、来源链接及合法图表数据，排除脚本源码 | 清洗后的静态 HTML；应用受控图表提供切换，引用由父应用列出；原 HTML 脚本不执行 |
| 图片（PNG / JPG / WebP） | `image.generate`、Pillow 排字和改尺寸 | 新增：先「看图」得到描述，再判断 | 已有；新增同一任务的成果前后翻看 |

### G1 沙箱镜像预装

- 系统软件：LibreOffice（Writer、Calc、Impress，无界面）、ffmpeg、poppler-utils（`pdftotext`、`pdftoppm`），以及 WeasyPrint 需要的 Pango 库。中文字体已有。
- Python 包（精确版本，写进 `requirements.txt`）：pandas、openpyxl、python-docx、python-pptx、pdfplumber、pypdf、matplotlib（设好中文字体）、Pillow、pyarrow、weasyprint、jinja2、markdown。
- 构建时 pip 走根目录 `.env` 里的 `SANDBOX_PIP_INDEX_URL`（开发机用国内镜像站）。
- 完整镜像体积以构建实测为准，不能把 LibreOffice 本身的体积当成全部增量；Python 数据库和系统依赖也占空间。浏览器（Chromium）不在 5.6 装，5.7 定预览环境时一起定。
- 沙箱规格（2 核、2 GB、30 分钟）不变；LibreOffice 转大文件慢，在手册里提醒。

### G3 看图（`image.inspect`）

- 视觉模型列表 `TOOL_VISION_MODELS`，按地区可用性挑默认（实现时实测，候选是 Qwen-VL、GLM-V、Gemini Flash 这几类便宜的模型），地区不可用照样自动跳过。
- 按实际花费结算，目录单价约 $0.002 / 次。
- 关卡里每次最多看 4 张图；看图出错可继续按文字说明判断，但必须标记视觉检查未完成，不能算该项已通过。

### G8 单文件网页的预览安全

- 用户已确认本阶段支持交互；5.5 的禁止脚本策略在隔离验证通过前继续生效。不能直接用 `sandbox allow-scripts allow-popups` 替换现有策略。
- `connect-src 'none'` 只限制部分连接接口，不能据此声称弹窗、导航或下载到本地的 HTML 完全断网；`SameSite=Lax` 也不是通用的无凭据保证。
- 5.6c 先设计不携带应用登录凭据的预览边界（必要时提前使用独立预览来源），限制资源加载、导航、弹窗、表单、父窗口通信和 Electron 能力。外链由应用控制，用户主动选择后打开；预览内容不能自行触发系统浏览器。
- 浏览器和 Electron 均须验证：正常图表交互、fetch/图片等外发、frame 自导航、弹窗、父页面访问、伪造消息、应用 API/桌面 IPC 访问。不能仅检查响应头字符串。
- 单文件必须自带脚本、样式和资源以便离线使用。交互预览通过验证不表示下载后在其他浏览器打开的文件受到相同限制。
- 具体预览 URL、鉴权和外链契约在 5.6c 编码前冻结；多文件应用和服务型预览仍属于 5.7。

## 3. 边界（冻结）

### 5.6 做

- 第 2 节的 G1–G10。
- 五类场景都能从私聊里提出需求，经规划、执行、关卡、整体验收，交付到私聊和画布，用第 1.2 节的方式看。
- 第 6 节的验收矩阵全部通过。

### 5.6 不做（以及放到哪里）

| 不做 | 去向 |
|---|---|
| 批注、打回、批准、参数面板、「重新生成某一章 / 某一张」 | 5.11 修改成果 |
| 历史版本保留和版本对比 | 不做，沿用 ADR 0003：旧版本不保留 |
| 看板定时更新、表格在线改数 | 以后（不在第 5 阶段承诺内） |
| 多文件网页应用、要启动的原型、在画布里截图网页 | 5.7（预览环境） |
| 营销里的图生视频、剪辑、配音合成；5.6 的营销短视频只用现有的文生视频 | 5.8 |
| 投放数据回流、发布到平台、真正的 A/B 分流 | 不做；只出多个版本和分流建议 |
| 下载网上的任意文件、抓视频网站 | 不做；需要的文件由用户上传（网页和 PDF 链接的正文能读） |
| 直连用户的数据库 | 不做；只收导出的文件 |
| 桌面端本地文件夹自动上传 | 维持 ADR 0007 §10：以后再做，现在用上传 |
| 大规模多模态合成数据（图文配对上百组） | 5.6 只支持小规模（20 组以内），用生图和看图工具 |
| Parquet 在线预览 | 不做；看节点交的统计报告 |

## 4. 规划员和节点怎么用上这些（不写模板）

- 规划员的说明里只加一句：「先运行 `oasis-tool list` 看有哪些工具、沙箱里装了什么软件」（规划员本身就是一次沙箱运行）；`expects` 的新写法写进说明的例子。
- 节点的说明不变（已经会让节点先运行 `oasis-tool list`）。
- 场景的经验写在手册里，内容是「一般怎么分工、用什么工具和软件、交付物长什么样、常见的坑」，和 5.4 的两份同一个写法。规划员可以不照做。各手册的要点：
  - **数据与看板**：数字只能从数据算出来，不能编；交一份「数据核对」（每个指标怎么算的、对应源数据哪几列）；看板是单文件 HTML（ECharts 内嵌）；Excel 用公式不写死结果。
  - **深度研究**：先拆问题，再按子问题或竞品并行查资料；每条资料记出处（网址或「文件名 第 x 页」、视频「mm:ss」），写成 `来源.json`；同一指标的不同来源数字不一致时，单独列「指标冲突」；报告里每个结论标 [n]，链接到来源；要 PDF 就用 WeasyPrint 从同一份 HTML 导出。
  - **合成数据**：先从资料里抽种子（主题、事实），再用 `text.batch` 生成，用 `jev.decide --in` 打分，用代码去重（近似重复）、按阈值过滤；交数据集文件和一份 HTML 统计报告（数量、过滤原因、分数分布、抽样 20 条）。
  - **营销内容**：先提炼卖点，再按平台并行写文案（每个平台 A/B 两版）；商品图用 `--ref` 以主图为参考；尺寸用 Pillow 按平台规范裁切；合规检查先用代码查禁用词，再用 Jev 判断夸大宣传，交一份检查清单；按平台分文件夹。
  - **文档类**（改写）：Word、PPT、PDF 用预装的软件；PPT 同时导出同名 PDF。
  - **图片类**（改写）：改图、换背景用 `--ref`；交付前用 `image.inspect` 自查画面和文字；批量出图时用 `expects` 写最少张数。

### 实施前补齐的工程约束

- **批次**：稳定的行 ID 与输入摘要，逐行持久保存结果；恢复跳过已完成行。停止后不再派发，记录在途结果。不能确定供应商是否执行的行标为不确定，不自动无限重发。并发、行数、token 上限外置；运行 Key、付费人和任务费用归属仍由网关验证。原 `NodeTool.uses` 最大 50，与 1,000 行批次不匹配，5.6a③按下面的接口设计更新预估单位与契约；现有运行 Key 没有模型白名单，不把它误称为模型授权机制。
- **成果**：5.6b 区分规则检查与最终交付筛选，不能直接把旧任务的 `expects` 当成排他的交付清单。由 task 产生明确的最终文件清单，私聊、canvas、打包与同步统一使用；PPT 配套 PDF、来源清单和统计报告须可列入。新字段先兼容读取再启用写入，不改写已交付的历史任务；旧版本无法读取新 JSON 时不得宣称可直接回滚。
- **数量和质量**：区分至少数量与精确数量；只统计有效、非空且格式可解析的文件，图片还要验证尺寸。Excel 要重算并抽查缓存结果，不能只检查公式字符串。图片抽样检查须说明覆盖范围；看图失败要显示“未检查”，不能冒充视觉验收通过。
- **正文与引用**：Office/PDF 提取设置输入大小、解压体积、页数/单元格数量和时长限制；坏文件单独报告。PDF 保留页码。视频简报须提供带时间信息的转写或固定分段加起始偏移，当前仅返回文字的转写不能满足 14-B。
- **任务说明**：保留接需求期间原话和选择答案，明确最后确认的任务单优先于被用户撤回的旧要求，并遵守接口长度限制。
- **能力与价格**：参考图支持数量按供应商端点核验，最多 4 张是本产品上限；不可用的能力必须标为阻塞，降级不能算对应场景已验收。价格仅为估算，先核定实际模型再报预算与停止上限。

### 5.6a②/③ 接口与恢复设计（2026-10-24）

- `image.generate --ref 路径列表` 与 `image.inspect --images 路径列表 --question 问题` 仅接受本地 PNG/JPEG/WebP，CLI 编码成 `{mediaType,base64}`；网关验证数量（1–4）、格式签名和总大小（20 MiB）。生图参考图使用 `references` 参数，通过 OpenRouter 能力目录核对数量后传 `input_references`；看图使用 `images`，经配置的视觉模型调用 chat completions。仅对明确的地区拒绝自动换模型，不重试不确定请求。
- `web.fetch --out 目录` 请求 `format=files`；每个成功页面独立 Markdown，正文不再按 20,000 字裁剪；文件名使用序号与 URL 摘要，返回来源及失败列表。超过配置的总正文大小就明确失败，不能假装交出了全文。未带 `--out` 保持摘要模式。
- `text.batch --in prompts.jsonl --out out/results.jsonl` 每行 `{id,prompt}`，`jev.decide --in ...` 每行 `{id,question,context?,options?,scale?}`。文本批次只用当前节点的 `OASIS_MODEL`；拒绝行内覆盖模型、请求参数。`--resume true` 读取已存输入，可不再提供 `--in`；给出输入时必须与原摘要一致。`--concurrency`、`--max_tokens`、`--budget_micro`、`--row_budget_micro` 可向下覆盖环境默认/上限；默认最多 1,000 行、并发 4。费用均为整数微美元。
- 检查点保存在 `out/.oasis-batches/<输出路径摘要>/`，随现有产出 tar 保存和恢复；harness 不把该保留目录列入成果或传给下游。元数据保存完整输入、参数、摘要；各行先原子保存 `started` 再发请求，收到结果原子保存终态。恢复把遗留 `started` 当作 `uncertain`，跳过所有已发出的行。结果 JSONL 可由检查点重建。锁防止同一输出并行执行；新容器或已退出的进程可恢复旧锁，活进程的锁不能抢占。
- SIGINT/SIGTERM 停止派发并等待在途请求落盘；硬终止/节点停止可能留下不确定行，恢复不重发。已完成行不重跑；失败和不确定行如需重试，必须由调用方另建输入和输出，明确承担可能重复费用。输入文件留在其他目录也不影响恢复。
- Harness 的“停止并保存”先调用执行器 `pause()` 冻结容器，再归档、销毁；防止 tar 归档期间继续派发请求。Docker 实现使用 pause API；冻结失败则本次停止不能声称保存成功，不读取仍在变动的检查点。取消与超时仍沿用销毁语义，不承诺进度恢复。
- 非流式 chat 和工具调用可附 `max_cost_micro`；网关在冻结前检查预计冻结金额，不向供应商转发该字段。chat 在需要费用限制时返回 `oasis.costMicro`；批次派发前预留每行预算，结算后替换为实际值，失败/不确定保留整行预留。预算约束是保守的**派发限制**，供应商结算超过估算时停止后续派发，不能宣称外部费用绝对封顶。既有任务限额和逐次冻结/结算仍生效。
- 目录登记 `text.batch`（CLI 编排，不接受 `/tools/text.batch` 直接调用），`jev.decide` 用法包含批量入口。规划中的 `uses` 对批量操作表示行数，统一上限扩为 1,000，价格按行相乘；旧数据无需迁移。原有运行 Key 只绑定付费人和任务，没有模型白名单；本步 CLI 固定当前模型，不把现有鉴权误称为模型白名单。
- 受影响模块：model-gateway（适配、工具、计费前检查、配置）、harness（CLI、批次模块、检查点过滤和配置）、contracts、task 的规划说明与测试、Dockerfile 与本文。预计新增批次执行模块及针对性测试；它承担现有 CLI 没有的持久恢复职责，不新增服务、表或第三方依赖。

### 5.6b 接口与实施设计（2026-10-25）

- `expects` 兼容原字符串，同时接受 `{pattern,minCount?,exactCount?,width?,height?}`。至少数量默认 1；精确和至少互斥。图片宽高为精确像素值。路径只接受 out/ 下的安全相对路径，`*` 不跨目录；按有效、非空文件计数，图片必须完整解码，Office/PDF 必须可解析。数据集行数仍通过内容与统计报告验收，不冒充文件数量。
- 节点新增可选 `deliver: string[]`，是最终交付文件的路径/通配选择器，与 `expects` 独立。新规划必须给交付责任节点设置非空 deliver；手动提交的旧方案仍可省略。节点配置原有 JSON 保存选择器；整体验收时 task 将匹配的实际非空文件保存到已有 deliverables JSON 各项的可选 `files` 字段。TaskBody 增加可选 `deliveryFiles`（含 deliverable、nodeId、path、size）；显式空清单表示没有可交文件，不能回退到所有产出。旧任务未保存清单时沿用旧行为；conversation、canvas 消费同一清单，桌面同步继承 canvas 结果。
- 不新增表或 SQL 迁移。先兼容读取新增 JSON，再启用规划写入；旧历史数据不回填。启用结构化 expects/deliver 后，旧版本无法理解新规则或文件筛选，不能直接降级继续任务；需停止新任务并完成在途任务，或部署能够兼容读取新字段的回滚版本。
- 扩展现有 `/internal/runs/:id/texts`：保留 `files[].path/text` 与 `truncated`，增加每文件可选 `valid/error/width/height`，二进制图片可返回空 text 和校验结果；提取失败逐文件报告。DOCX 提取段落/表格，PPTX 标明幻灯片号，XLSX 标明工作表和单元格并包含公式与缓存值，PDF 保留页码。缓存缺失/错误或文本为空要明确提醒，不能声称已核对计算或扫描件正文。
- 解析在可终止的 worker 内运行，默认每文件输入 20 MiB、ZIP 总解压 50 MiB、ZIP 条目 2,000、PDF 页数 200、单元格 20,000、图片像素 25,000,000、每文件 10 秒；环境变量外置。请求总文件数和总耗时也设上限，输出总字符仍受 maxChars 控制并显式标记截断。只访问本地缓冲区，禁止 XML 外部实体和 PDF 外部资源。新增 fflate、unpdf 完成原计划的 ZIP/PDF 读取；另需 fast-xml-parser 做结构化 XML 校验、sharp 完整解码图片，现有依赖和 Node 内置能力不能替代这些职责，全部锁定精确版本。
- gate 在规则检查后使用真实文件内容，图片至多抽取 4 张经现有 `/internal/v1/tools/image.inspect` 检查再交给 Jev；重复运行引用去重。支付头保留 payer/task/node 归属。GateResult 增加可选 `unchecked: string[]`，用于提取失败、截断、视觉抽样范围和服务异常；未知不能记作通过，Jev 缺少答案也标记未检查。沿用用户已确认的“未满足也交付并提醒”，未检查只记录提醒，不为了检查服务故障自动重跑产生额外费用；节点 warning 和任务 acceptance 将其呈现给用户。
- 需求确认 brief 包含最初原话、接需求期间补充和问题卡答案，注明最终任务单优先。超过现有 20,000 字接口限制时明确拒绝确认并要求收拢需求，不能静默裁剪。提示词精确描述格式、至少/精确数量、平台和尺寸；有合理默认值时不增加询问。
- 新增四份手册，改写现有两份，最多附 3 份。Excel 交付前在沙箱重算并核对缓存；研究引用保留页码。视频采用 ffmpeg 分段并记录 CSV 实际起止时间、逐段转写后引用时间范围的路径；时间表生成已离线验证，真实视频引用准确性仍在 14-B 验收，不能把纯文字转写冒充秒级时间戳。
- 修改范围锁定为 contracts、harness 的提取与配置、task 的规划/关卡/交付、conversation 的原话与交付、agent 手册、canvas 的清单读取，以及对应测试和本文；不包含 5.6c 的新预览和打包界面。新增提取 worker、task 文件选择模块与测试属于现有模块没有的独立职责；测试样例生成在临时目录，结束清理，不保留平行版本。

### 5.6c 冻结设计与用户确认（2026-10-25）

- 用户确认采用**受控交互看板**，保持 5.6 范围：原 HTML 脚本不在应用内执行，单文件内的 `script#oasis-dashboard[type="application/json"]` 提供图表数据，由应用自己的受控图表组件切换显示。任意 JavaScript 网页的运行环境留到 5.7，不再把 allow-scripts + CSP 当作完全断网方案。下载的原 HTML 仍保留独立使用能力，应用内的隔离不延伸到用户下载后自行打开的环境。
- HTML 先用无浏览器副作用的 parse5 解析，按 HTML 标签与属性白名单重建：删除脚本、事件、表单、iframe/object、meta refresh、base、外部资源、链接导航属性；图片仅允许 PNG/JPEG/WebP 的内嵌 data URL。重建后放入 `sandbox=""` 的 srcdoc iframe，CSP 禁止脚本、连接、子 frame、表单及外部资源。保留静态 CSS 与排版；外链只提取 http(s)，在应用自己的区域展示，必须由用户点击打开，不接收预览 postMessage 指令。
- 图表数据契约为 `{title,charts:[{title,type:"bar"|"line"|"pie",labels:string[],series:[{name,values:number[]}]}]}`，限制图表数、标签/序列数量、数值和文本长度，数据长度必须匹配；只构造白名单 ECharts 配置，提示框使用 richText，不接受脚本、回调、HTML 模板、资源 URL 或任意 ECharts option。更新看板手册，使独立 HTML 与应用预览使用同一份数据。
- 复用鉴权和文件下载通路：前端从现有授权 URL 读取文件，`POST /api/canvas/v1/previews?name=文件名` 以 application/octet-stream 提交需要转换的 DOCX/XLSX/CSV/JSONL；canvas 只解析请求字节，不按用户提供的 URL 抓取文件，不持久化临时副本。回复为 HTML 内容或按工作表组织的表格 JSON。转换在可终止 worker 内运行，输入、ZIP 解压量/条目、时间、并发、工作表/单元格/输出大小均有上限；预览最多显示 1,000 行，并明确显示截断。公式显示缓存值，不在预览执行公式或外部连接。
- Word 使用 mammoth 在服务端转换后统一经过上述 HTML 清洗；替换草案 docx-preview 的直接 DOM 渲染方案，避免不可信文档在应用 DOM 中创建内容。XLSX 使用 read-excel-file，CSV/JSONL 只显示文本和数据；原始文件与格式下载不变。PPTX 优先预览同任务、同节点、同路径主文件名的 PDF；ArtifactBody 增加可选 nodeId 用于精确配对，旧数据无法唯一配对时提示下载，不猜测。
- 画布成果页按同任务成果顺序提供上一份/下一份；按任务全部下载调用 `GET /api/canvas/v1/tasks/:taskId/archive`。canvas 校验归属，ZIP 仅含已登记最终成果，条目使用现有 syncPath（与桌面同步完全一致），拒绝路径穿越、重复条目及超过总大小/数量限制；不新增 ZIP 存储对象或表。
- Electron 保持 contextIsolation/sandbox/禁用 Node；预览子 frame 无脚本、无 preload 权限。外链仅由应用用户操作打开，子 frame 导航/弹窗与非主 frame IPC 一律拒绝；浏览器及 Electron 都用实际恶意样例验证网络请求、导航、父页面访问、伪造消息、下载及 IPC，而非仅断言响应头。
- 影响范围：web 预览组件与画布页、canvas 转换/打包及契约、desktop 外链/IPC 边界、看板手册、对应测试与本文。新增解析/预览组件、转换 worker 和验收脚本，因现有实现没有这些职责；不新增服务、表或 SQL 迁移。依赖在首次使用时精确安装，fflate 跨工作区复用时迁入 catalog。临时转换/验收文件在结束清理；真实场景验收先另报预算，5.6a 的 $0.20 不作为 5.6d 授权。

### 5.6d 发现的关卡读取缺口与修正设计（2026-10-25）

## 风险

- Qwen3-VL-8B 和 Seedream 4.5 的本机调用已通过能力预检；其他候选模型与复杂输入仍可能遇到地区或参数限制。看图失败明确标记未检查，不能降级后冒充视觉验收通过。
- Tavily 已实测能读取一个 PDF 链接，不保证任意站点、受保护 PDF 或扫描件都能提取；失败时需要用户上传资料，第 3 节的边界不变。
- LibreOffice 转复杂的 PPT 偶尔版式有偏差。PPT 本身是用 python-pptx 生成的，PDF 只用来预览。
- 单文件 HTML 里内嵌 ECharts 会让文件大约 1 MB。可以接受，同步和下载都不受影响。
- HTML 的类别按扩展名算，报告和看板会出现在「网页和应用」下。5.7 有了真正的应用预览后再按「单文件 / 应用目录」区分。
- 批量生成的花费和行数成正比。预估按目录单价 × 行数算，超过 3 倍照常暂停。
