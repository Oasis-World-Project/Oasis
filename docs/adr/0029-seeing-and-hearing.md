# ADR 0029：看和听交给能看能听的型号

- 状态：已采纳（2026-11-11）
- 相关：ADR 0006（工具目录）、ADR 0026（做几版挑一版）、ADR 0027（只用国内模型）、ADR 0028（规则不带倾向）

## 1. 现象

2026-11-11 的小游戏任务，「做」的部分十来分钟全部顺利，卡的全在「判断」上：

- 两版配乐挑一版：一个只读文字的型号把音频转成频谱图，再让看图工具去读图，用了 14 分钟、49 次工具调用、$0.50；回答里版本号写成 `"v1"`，没被认出来，最后走了兜底。
- qa 节点要看浏览器检查的截图，拿不到，自己写了一个本地渲染器去还原画面。

用户的判断：国内能看能听的模型是有的，是系统没把它们接到该用的地方。查实如此。

## 2. 没接上的地方

1. **挑一版只认图片和视频**（`pick.ts`）。音频落到「其他产出」，固定交给规划员用的那个型号（只读文字）。规划员看到的规则只说「由视觉模型或 AI 挑」，它不知道这个 AI 听不了，也没有地方指定谁来挑。
2. **只有「看图」工具**（`image.inspect`）。没有听音频、看视频的工具；挑视频只抽第 1 秒的一帧当图片看。
3. **供应商目录里的能力被丢掉了**。网关读 OpenRouter 目录时把输入种类筛成只剩 `text`、`image`（`listPrices`），`video`、`audio` 在这一步就没了。
4. **给规划员的清单兑现不了**。清单写某型号「能直接读：image、video、audio」，这是 agent 里手写的；节点里的型号其实最多能直接看图（dsh 只有 `read_image`），视频、音频没有办法交给它。「快速」档的型号干脆没有这一项。

## 3. 决定

**不为每种文件各加一个工具，把原来的看图工具改成一个：`media.inspect`（看图、看视频、听音频）。**

- 参数 `files`：1–4 个本地文件，图片、视频、音频可以混着给，合计不超过 20 MiB；`question`；可选 `model`。沙箱里的 `oasis-tool` 按后缀认出种类（`localMedia`，原来的 `localImages` 改的）。
- 型号一份清单 `TOOL_INSPECT_MODELS`（原 `TOOL_VISION_MODELS`），只管先后。**每个型号读得了哪几种，照供应商目录**：网关保留目录里的全部输入种类，调用时只留读得了这次全部文件的型号；点名的型号读不了就明说它读不了、谁读得了，不调用也不冻结。目录还没拉到时不筛，照配置的先后试。
- 挑一版（`pick.ts`）：图片、视频、音频走同一条路，各版一起交给 `media.inspect`。图片先缩成宽 1024，视频先缩成宽 640（看的是整段视频，不再是一帧），音频直接给。文字、网页这类产出仍由 AI 读完再比较。版本号写成 `"v1"`、`"第 1 版"` 也认。
- 给规划员的清单：每个型号在节点里能直接读什么，由 task 照网关的目录填（各档次都有），agent 里手写的那一列删掉。清单开头写明事实：节点里的型号最多能直接看图；视频、音频不管哪个型号都读不了，要用 `media.inspect`。

三种文件各至少有三个国内型号。哪些真实调用验证过（2026-11-11）：

| 种类 | 真实调用过的国内型号 | 目录写着能读、没单独调的 |
| --- | --- | --- |
| 图片 | qwen3.8-max-prime（原来看图一直用它） | kimi-k3.1-pro、三个 mimo、minimax-m3、step-5-preview |
| 视频 | qwen3.8-max-prime、kimi-k3.1-pro、mimo-v2.6-pro | mimo-v2.6-flash、mimo-v2.5、minimax-m3、step-5-preview |
| 音频 | mimo-v2.6-pro、mimo-v2.6-flash、mimo-v2.5 | qwen3.8-omni-flash（有限制，见下） |

## 4. 验证

- 用那个任务里真实的两版配乐（各约 150 秒、5 MB 的 mp3），走工具自己的代码调真实供应商：`mimo-v2.6-pro` 24 秒、$0.0015 给出选择和听感上的理由（原来 14 分钟、$0.50）。`mimo-v2.6-flash`、`mimo-v2.5` 同样两段一起听，15–22 秒、约 $0.001。
- 视频（3 秒测试片）：`qwen3.8-max-prime`、`kimi-k3.1-pro`、`mimo-v2.6-pro` 都说得出画面和哪里在动，7–14 秒、$0.001–0.007。
- **目录说能听、实际有限制的一个**：`qwen3.8-omni-flash` 听 20 秒的单段正常，两段 5 MB 的 mp3 一起给时供应商报「The audio is empty」。所以它排在三个 mimo 后面。这也说明清单里的型号要真实调用过才算数，目录只能用来筛掉读不了的。
- 单元测试：网关（按目录挑型号、三种内容块的写法、点名读不了的型号、目录没拉到）、沙箱（按后缀认种类、参考图只收图片）、task（音频和视频怎么挑、`"v1"` 的解析、规划员清单的写法）。

## 5. 没做的

- 生音乐、生 3D 各只有一个型号（fal.ai）：同日已补，见 §8。
- 听音频的三个国内型号都是小米一家的，限流时没有别家可换。

## 6. 同日跟进：配音、转写、快速判断在「只用国内模型」下也能用

原来这三个工具在「只用国内模型」下，配音只剩一个型号，转写和快速判断整个不可用：配的全是国外型号。

- **配音和转写的型号不在供应商的默认目录里**，要按输出种类另取（`/models?output_modalities=speech`、`transcription`）。按它查到国内的配音型号 5 个、转写型号 2 个。
- **配音**（`audio.speech`）：清单改成 qwen-audio-3.0-tts-flash、minimax speech-2.8-turbo、qwen-audio-3.0-tts-plus、minimax speech-2.8-hd 在前。这四个真实调用过，念出来的中文再转写回来一字不差。
  - 它们不点名音色就拒绝（`An explicit voice is required`）。没写 `voice` 时，网关用供应商目录里这个型号的第一个音色。
  - 原来排第一的 seed-audio 是按描述生成声音的型号，只给要念的文字时出来的不是这句话（转写成「呜呜」），所以挪到最后。也就是说，原来国内用户的配音其实一直是坏的。
- **转写**（`audio.transcribe`）：加上 qwen3-asr-1.7b、qwen3-asr-0.6b。供应商目录里国内的转写型号只有这两个，凑不到三个。
- **快速判断**（`jev.decide`）：专用的决策模型是国外的。它用不了时，由清单里后面的聊天模型按同样的格式回答（`TOOL_DECIDE_CHAT_MODELS`：deepseek-v4.1-flash、qwen3.8-flash、glm-5.3-flash）。回答必须是要求的 JSON、选项和刻度必须是给出的原文，否则报错，不编一个结果。聊天模型给的「把握」不是校准过的概率。

验证：在跑着的网关上、以开着「只用国内模型」的账号实测。配音不写音色，用 qwen-audio-3.0-tts-flash 念出一句话；把这段语音交给转写，得到原句；快速判断三个国内型号各选一次都对，是不是、按刻度打分也对。

## 7. 同日跟进：节点自查把截图交回

规划员给 qa、fix 这类节点挑的是能看图的型号，说明里写「看报告和截图」；但 `app.check` 交给节点的只有步骤结论，报告里有截图的文件名、没有图。

- inspector 的节点自查原来写死不带截图。现在调用方要就带上（打开后的首屏、测试里 `screenshot` 步骤和没通过那一步的截图），仍然不留档。
- `app.check` 给了 `--out` 就连截图一起要回来，和报告一起作为文件交回。
- 沙箱存文件的规则改了一条：几个文件后缀不一样、只有一个和 `--out` 同后缀时，它是主结果，原样存到 `--out`；其余的放在旁边，名字接在后面（`检查报告.json`、`检查报告-opening.jpg`、`检查报告-step-2.jpg`）。原来这种情况会把主结果也改名成「-1」，工具节点按 `--out` 找不到它。

验证：在跑着的网关和 inspector 上实测一个最小网页，交回报告和两张真实截图。

## 8. 同日跟进：生音乐、图生 3D 各有三个以上型号

fal.ai 每个型号的入参、结果、价钱都不一样。这些差别现在各写在一张表里（`tools/audio.ts`、`tools/three-d.ts`），提交、查进度、取结果还是原来那一套。清单 `TOOL_MUSIC_MODELS`、`TOOL_GEOMETRY_MODELS` 只管先后，表里没有的型号不列。

| 工具 | 型号 | 标价 | 真实调用（2026-11-11） |
| --- | --- | --- | --- |
| 生音乐 | MiniMax Music 2.6（默认） | $0.15 | 10-27 验收过，这次没有重调 |
| | Lyria 3 Pro | $0.08 | 带中文歌词的歌 40 秒出，转写回来就是给的歌词；纯器乐 43 秒，听过没有人声 |
| | Lyria 3.5（`google/lyria/v3`） | $0.10 | 带中文歌词的歌，转写回来就是给的歌词 |
| | ACE-Step 1.5 | $0.072（固定 120 秒） | 纯器乐通过，要 5–8 分钟；给中文歌词两次都只有哼唱，所以只做纯器乐 |
| 图生 3D | Trellis 2（默认） | $0.25–0.35 | 10-27 验收过，这次没有重调 |
| | 混元 3D v3.1 Pro | $0.375 | 23 MB 的 GLB，约 3 分钟 |
| | Tripo H3.1 | $0.30 | 43 MB 的 GLB，约 3 分钟 |
| | Pixal3D | $0.30 / $0.42 | 9.8 MB 的 GLB |

跟着改的：

- **按型号记账**。提交时把型号和这次的标价记进任务号，取结果时按型号找 GLB、照这个价记账（fal 不按调用回报花费）。原来不管哪个型号都按一个配置价记，那两个配置项（`TOOL_*_MICRO_PER_GENERATION`）删了。目录里各型号也列自己的标价，原来都显示同一个兜底值。
- **只做器乐的型号**。不点名型号时，带歌词的歌跳过它；点名它就在提交前拒绝，不冻结。
- **供应商没生成时把原因原话交回**。Lyria 把一句普通的器乐描述判成内容违规，原样重发就过了；原来只说「生成失败」。
- **下载按速度判断，不设总时限**。每 15 秒收到的不到 512 KiB 就掐断，下次查进度时重新下载。实测结果刚出来时的第一次下载常常只有约 9 KiB/s（10 MB 要 18 分钟），重下 8 秒就完；原来要等满 120 秒才重下，而几十 MB 的 GLB 在慢链路上又可能被 120 秒的总时限误杀。
- **沙箱按实际格式存音频**。「按实际格式改后缀」从图片扩到音频（mp3、wav、flac、ogg），长任务下载下来的文件也核对。ACE-Step 回的是 FLAC（前面挂着一段 ID3 内容凭证，要看标签后面才认得出）：要 `.mp3` 会存成 `.flac` 并说明；工具节点照旧用 `oasis-op media.convert` 换回计划要的格式。

查过、不能用的：

- 混元 3D v3.1 Rapid：文档写「有 GLB 就给 GLB」，实际回的是 OBJ + MTL + 贴图，没有 GLB。换成 Pro。又一次：目录和文档只能用来筛，真实调用过才算数。
- ElevenLabs Music（$0.6/分钟，向上取整）、Meshy 7.1（带贴图 $1.2）：一次的价钱超过各自工具的冻结上限（生音乐 $0.5、图生 3D $1），没接。
- Sonauto v2：fal 的目录里已经查不到。

没做的：

- MiniMax、Trellis 这次没有重新真实调用，改动后的路径只有单元测试。
- ACE-Step 没试英文歌词。
- fal 的 Key 查不了账单，花费都是按标价算的。

验证：单元测试（各型号的入参、GLB 在结果里的位置、价钱、目录单价、只做器乐、拒绝原因、下载速度、沙箱认格式）；上表的真实调用走的是工具自己的提交和取结果代码；再在跑着的网关上用 ACE-Step 生成一首，交回的是 `music.flac`、按 $0.072 结算；重建后的沙箱镜像里用真实文件核对过，这份 FLAC 要存成 `.mp3` 时会改存成 `.flac`，Lyria 的 MP3 不动。真实调用共约 $1.85（含一次没用上的 Rapid $0.225 和一张参考图 $0.09）。
