# ADR 0010：5.8 音频、视频成品与可编辑工程

- 状态：5.8a 已实施并进行免费工程验证（2026-10-26），真实供应商成品验收待单独批准；5.8b 仍为设计。
- 依据：ADR 0003 §10 的场景 2/3、ADR 0006 的能力网关、ADR 0007 的画布与上传、ADR 0008 的遗留媒体范围，以及用户本次确认：包含完整音乐作品；视频编辑用户素材并交付可再编辑的 Shotcut 工程。
- 范围：agent、model-gateway、harness、canvas、task、Web/desktop、contracts、媒体运行镜像；不新增业务微服务。

## 1. 当前基础与缺口

已有 `audio.speech`、`audio.transcribe`、文生短视频 `video.generate`，沙箱有 FFmpeg，画布可以播放音视频并按 Range 下载。5.6 的深度研究也已有分段转写与时间范围引用。它们解决的是单次工具调用或单个文件交付，尚未形成可反复编辑的媒体工程。

设计时上传上限 100 MB，canvas 上传/登记使用整文件 Buffer；harness 素材进入、`out/` tar、上游传递、单文件提取使用 Buffer，整个产出 tar 上限 200 MB；视频工具经 JSON/base64 返回整段视频；桌面同步在渲染进程读成 ArrayBuffer 再通过 IPC 写盘。5.8a 已按 §4、§10 改为有界流式链路。5.7a 的真实模型成品验收仍待单独预算批准；5.8 不把它写成已验收事实。

原始 14 个业务场景的逐字材料不在当前仓库。场景 2/3 的详细验收以现存 ADR、本次用户确认和实际实现时的需求单为准；若找到原文，应先核对再冻结案例。

## 2. 产品范围与交付

| 需求 | 能力 | 最终交付 |
| --- | --- | --- |
| 语音作品 | 脚本、配音、多段剪辑、转写、降噪/响度处理、按真实时间轴形成字幕 | 可播放音频、脚本/转写、必要时 SRT、来源及检查报告 |
| 音乐作品 | 原创歌词或用户提供的歌词、器乐曲与演唱歌曲、段落安排、试听后定稿 | 完整 MP3、可行时无损母版、歌词与模型/来源记录；只有供应商实际返回分轨时才交付分轨 |
| 视频作品 | 用户素材剪辑、生成镜头、画面/配音/音乐/字幕合成、片段重排与过渡 | 可播放 MP4、SRT、Shotcut `project.mlt`、工程素材文件夹和完整工程 ZIP |

单段生成镜头是视频素材，不冒充剪好的影片。营销图生视频与配音合成从 ADR 0008 的 5.8 遗留范围纳入。小程序/小游戏的实时运行预览仍属 5.7；5.8 使用现有画布的媒体播放，不复用预览容器。首批不做实时直播、社交平台发布、长期在线协作剪辑或未经另行确认的声音克隆。

工程包把 `project.mlt` 与所有引用的 `media/` 文件放在同一目录树，采用相对路径，附字幕、脚本/歌词、素材来源、文件哈希和打开说明。`project.mlt` 必须在实际 Shotcut 中能打开、显示可编辑轨道并能重新导出；只有 XML 文件或可播放 MP4 均不算工程验收。Shotcut 工程文件引用媒体路径，不内嵌媒体，因此素材必须一起打包。

## 3. 一条任务闭环，两批实施

用户在私聊给目标和素材 → 规划员按实际需求安排脚本/歌词、素材分析、生成、剪辑与质检节点 → 节点用现有 `oasis-tool` 和本地媒体工具产出 → 确定性检查与人工可复核的试听/试看 → 原有 task 交付与 canvas 登记/同步。简单音频任务可由一个干活节点完成；复杂片子才拆脚本、素材、剪辑和审查。不得按“音频/视频”写死节点模板。

| 批次 | 一次交付的内容 | 完成门槛 |
| --- | --- | --- |
| 5.8a 媒体数据面与音频 | 有界流式传输/保存/同步；长工具结果持久化；复用配音/转写，接入音乐生成；音频手册与确定性检查 | 上传较大真实素材、完成完整配音/器乐/歌曲、播放下载与费用闭合；断连重试不丢结果、不重复结算 |
| 5.8b 视频与工程 | 素材分析、剪辑/合成、生成镜头、字幕、Shotcut 工程包、画布交付和视频手册 | 用户素材成片与生成素材成片均可播放；工程移到另一目录后在 Shotcut 打开并重新导出；最终真实场景验收通过 |

这两批使用同一套数据面和原有工作流；不新增独立“媒体任务服务”。每批先做离线/假供应商验证，再按 ADR 0003 先报案例和预计费用，取得用户同意后做真实模型验收。5.6 与 5.7 的预算不结转。

## 4. 大媒体文件的数据面

1. 扩展 `@oasis/service-kit` 的对象存储能力，提供有界流式写入、读取、失败中止和校验和；按本项目锁定的 S3 SDK 机制进行分段上传。对象键仍由所属服务生成，浏览器和沙箱都不拿对象存储凭据。
2. canvas 上传请求直接流向私有桶，限制单文件与单任务总量；写完并核对大小/哈希后才登记。成果复制也按流处理。下载和 Range 保持现有鉴权语义；ZIP 打包改为流式且先累计清单大小。
3. harness 流式读取 Docker 的 `out/` tar，逐条检验安全路径、类型、数量、大小和总量，并流式保存原有 `outputs.tar` / `session.tar`；`runs.outputs` JSON 清单增加可选哈希。实施时取消了原提案的“按文件改存对象”：保留同一归档格式即可实现有界内存，不需要新格式、历史数据迁移或长期双读。上游输入、用户素材、单文件提取和续跑恢复均按流处理。保存失败中止分段上传，只有成功保存归档后才提交对应运行成果。
4. `oasis-tool` 对较大工具结果只接收带归属和有效期的文件引用，再从入口代理允许的受鉴权工具路径分块下载并核对哈希；JSON/base64 仅保留给现有小文件结果。供应商临时 URL 不交给沙箱，不让沙箱直连供应商。
5. 桌面同步改为分块下载、受限 IPC 追加写入、哈希核对后原子改名；保持“只写用户选定目录、已有文件不覆盖”的规则。浏览器下载直接流式保存。

建议首先基准测试 1–3 分钟、最高 1080p 的短片与完整歌曲，再冻结初始数值；目标能力可按单素材约 500 MB、一次任务素材约 1 GB、工程包约 2 GB 做压力设计。实际公开上限以内存、容器磁盘、上传时长和完整链路实测结果为准，不只修改 `UPLOAD_MAX_BYTES`。旧小文件路径在新流式读写稳定后迁移/收束，不长期保留两套平行逻辑。

## 5. 供应商、长任务和计费

- 先复用 OpenRouter 的 `audio.speech`、`audio.transcribe`、`video.generate`。增加 `audio.music`，经 model-gateway 的 fal 适配支持器乐与带歌词的歌曲；具体模型、单价、输出时长、区域可用性、许可与账户额度在接入前实时预检，不能只凭文档宣称已接通。fal 的 MiniMax Music 2.6 API 是候选：它定义 `lyrics` 和 `is_instrumental`，返回音频文件；不据此承诺分轨。
- 视频若需参考图驱动，给现有视频能力加经验证的参考输入或新增有清楚语义的 `video.image-to-video` 工具；只有供应商当前接口、费用和可用性预检通过才开放。不要把用户素材偷偷拼进文生视频提示词冒充图生视频。
- 音乐与视频按长任务处理：提交 → 持久化供应商任务 ID → 查进度 → 先把完成文件复制到 model-gateway 私有对象存储并校验 → 幂等结算 → 提供受控下载。中间状态持久化，重启后从最后已确认状态继续；供应商文件 URL 只接受预检过的 HTTPS 来源，并限制重定向、大小和内容类型。重复轮询、供应商结果过期和“已接受但费用未知”必须可对账。现有 `tool_jobs` 的“完成后还向供应商取文件”不适合大媒体长期交付。
- 每次模型/工具调用仍由 model-gateway 冻结、结算或退回；算力经现有 harness → model-gateway 链路。规划预估按次数、秒数/时长与资源档位算，任务超过现有防失控阈值暂停。未知实际账单保留冻结预留并单独报告，不将超时自动退回当作供应商已免费。
- fal Key 只放 model-gateway 本地环境变量；不进浏览器、沙箱、日志或对话。本项目采用用户已配置的 `FAL_API_KEY`，通过原生 HTTP 显式设置鉴权，不依赖 fal SDK 的 `FAL_KEY` 自动读取约定；已确认本地变量存在，未发送账户验证或生成请求。是否能使用某段生成音乐进行特定用途，以实际供应商条款和素材权利为准；工程包记录来源，不声称自动获得所有权利。

## 6. 剪辑工程与质量关卡

采用固定、可复现的时间轴清单作为工程生成输入，明确每段素材哈希、源入出点、目标轨道、时间基、音量、字幕和转场。视频首批只承诺经验证的剪切、淡入淡出、图片/文字叠加、配音/配乐混合、字幕和基础音量处理；未实现的复杂特效不能写进交付说明。用同一时间轴生成 Shotcut/MLT 工程并渲染最终片，避免“成片一套、工程另一套”。FFmpeg 用于素材探测、必要的转码与客观检查。Shotcut 所需的 MLT XML 属性有其应用特定规则，必须用锁定版本的真实 Shotcut 打开、保存/重新导出验证。

确定性检查包括：解码成功、音视频流与时长、分辨率/帧率、画幅、首尾帧、静音/黑屏异常、音频峰值/响度、字幕区间与内容、音画长度偏差、所有工程引用的相对路径和哈希、ZIP 解压后重连素材。`ffprobe` 给机器可读流/容器信息，FFmpeg 提供混音、响度和静音/黑屏检测；阈值按交付类型设置，片头留黑或有意留白不能一概算失败。

语义验收必须实际试听/试看关键段：人声发音、歌词或旁白与画面、字幕时序、镜头顺序、转场和最后成片。可用视觉/语音模型辅助，但自动判断有疑点时保留“未检查”，不让模型仅凭脚本或单张截图宣布通过。转写若只返回文字，继续使用实际分段表给出时间范围，不能伪造词级时间戳。报告记录源文件摘要、检查工具版本、失败与修复记录和真实结算。

## 7. 安全、迁移与收尾

- 仍用现有隔离沙箱处理用户和供应商媒体。FFmpeg/MLT 输入有格式、尺寸、解码时长、CPU/内存/磁盘限制；不允许媒体中携带的外部 URL、字体或项目路径使沙箱直连外网/宿主机。Shotcut `.mlt` 中的媒体路径只允许工程根目录内相对路径。
- 不新增上传/成果表。canvas 现有表增加校验和与未完成上传状态，`runs.outputs` 增加可选哈希；`tool_jobs` 增加幂等键、结果、费用、阶段、租约与有效期，文件对象键由作业 ID/文件序号推导，不对外暴露。两项独立 expand 迁移均含 down 和 contract-plan。它们不替代旧列，无可删除旧结构；同一 tar 格式无需数据迁移，长任务旧的“每次向供应商重取并返回 base64”路径已移除。旧长任务结果通过同一恢复流程补存；已过期、费用不确定的旧任务必须保留核对记录，不能伪称已恢复成功。
- 中间代理文件、转码缓存、失败的分段上传和临时容器按任务归属清理；最终源素材、可编辑工程和成片属于交付物，不能随缓存清掉。跨服务对象清理由持久重试/对账负责，不能只靠一次 `finally`。

## 8. 最小验收与对接

免费验证：小文件兼容、接近上限的流式上传/登记/Range/下载/桌面同步、断连与重启、重复供应商回调/轮询、余额不足、恶意媒体/路径、Shotcut 工程跨目录移动后重开与重新导出。真实验收至少覆盖：① 多段语音配音与字幕；② 完整器乐曲；③ 带歌词的歌曲；④ 用户素材剪辑成片并交付 Shotcut 工程；⑤ 生成镜头参与剪辑的短片。实际供应商、每例时长和预算须在执行前另报，未获批准不发起付费调用。

对接事项：用户在本地 model-gateway `.env` 配置 fal Key 与可用额度；提供愿意用于真实视频验收且可打包的源素材（若没有，可先用明确标为测试用的自制素材）；确认最终片的目标时长、画幅和分辨率。默认验收采用短片以控制成本；需求更长时由用户任务单给出。真实工程应在用户选择的 Shotcut 版本或约定版本打开；实施时先预检版本兼容性。

## 10. 5.8a 实施冻结与验证记录

### 实施范围

- 复用 service-kit 的 S3 客户端，按 8 MiB 分段流式写入、计算 SHA-256、失败中止；服务启动及定时回收过期分段上传。canvas 先记录 `uploading`，完成后公开 `ready`，中断记录可重启回收。
- canvas 上传、成果跨 HTTP 保存、Range、ZIP；harness 素材/归档/续跑/下游传递；Web → Electron 分块同步均使用流。桌面每块不超过 1 MiB，先落私有临时文件，验证后独占完成，不覆盖已有文件；重启回收同步日志中属于本应用的未完成文件。
- 初始限制：单上传/工具结果 512 MiB、任务输入 1 GiB、harness 归档和成果 ZIP 2 GiB；上传并发 2、传输超时 10 分钟。512 MiB 是本轮已实测的单文件上限；1/2 GiB 是保护阈值，尚未用同等大小的真实视频工程验收。转写仍有 20 MiB 单次限制，长录音由手册要求分段。
- `audio.music` 明确区分器乐/演唱，歌词通过参数或本地歌词文件传入；候选固定为 `fal-ai/minimax-music/v2.6`，默认 MP3、44.1 kHz、256 kbps，只承诺实际返回的混合音轨。2026-10-26 核对[官方模型页](https://fal.ai/models/fal-ai/minimax-music/v2.6)，公开单价为 $0.15/首，配置按估算计费来源记录；实际账户账单仍需验收后核对。
- 长工具提交前持久化意图；同一节点、参数与输出位置生成稳定幂等键，重试沿用作业；`--new true` 才明确新建。后台租约续期，结果先入私有桶、再幂等结算；结算失败从已存文件恢复。默认保留工具结果 7 天，最终已交付成果另由 canvas 保存。提交断连/未知响应不自动重发，超时保留 `uncertain` 对账记录；冻结可能到期，不能据此认定供应商未收费。
- 已冻结的新增接口：`/run/v1/tools/jobs/:jobId/files/:fileId` 与对应内部接口按付费人及任务归属鉴权；`/internal/runs/:runId/audio-check` 返回可信文件检查；Electron 仅开放 begin/append/finish/abort 四项同步接口。供应商 URL 与凭据不进入沙箱，JSON/base64 只用于已有小文件工具。
- 新音频手册覆盖配音、分段转写、混音、器乐与演唱、来源和试听要求。确定性检查用已保存归档创建 root 所有的只读快照，通过 Docker 执行受信脚本与 FFprobe/FFmpeg 完整解码；报告和源文件摘要绑定，agent 自写报告不能替代。沿用原运行的算力计量，不另起未计费检查环境。解码通过不代表发音、歌词或音乐质量已试听通过。

### 免费验证

`pnpm media:smoke` 使用真实 S3、HTTP、Docker 与桌面文件写入，128 MiB V8 堆限制下测试 512 MiB 输入，Node RSS 峰值约 161.7 MiB。10 项通过：流式上传和摘要、鉴权 Range、成果保存、ZIP 解包逐字节核对、桌面同步、截断分段中止、未完成上传恢复、Docker tar 素材传入、90 秒音频完整解码及损坏 MP3 拒绝、检查快照只读。报告保留于 `out/media-foundation-acceptance-20261026/`。这是合成大文件与音频测试，未调用真实供应商，也未完成完整音乐作品的语义验收。
