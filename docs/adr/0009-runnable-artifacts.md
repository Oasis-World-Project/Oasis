# ADR 0009：可运行成果与独立预览（5.7）

- 状态：5.7a 预览、声明式交互验收及 5.7b 受控外站/Android 工具已实现；已完成真实模型网页、小游戏、外站和 Android 代表案例的自动验收。当前实现和已知限制以 §11–15 为准，前文保留设计时的背景。
- 依据：项目工程方向、AGENTS.md、ADR 0003 §6/§8/§10、ADR 0006 §6/§7、ADR 0007、ADR 0008。
- 交付拆分：只分 5.7a、5.7b 两批；各批包含自己的测试和清理，不另拆验收阶段。

## 1. 用户已确认的范围

1. 网页和小游戏交付前端作品及必要的临时后端；正式账号体系、长期数据库、正式上线托管不在本次范围。
2. UI 测试完整保留三类：生成的网页、外部网站、Android 原生 App。不能用移动端网页测试代替 Android 验收。
3. 预览默认仅本人访问，手动开启，闲置自动停止；再次打开可从成果重建，临时运行数据不保证保留。不做公开分享和长期存档。
4. 预览采用严格隔离，用户接受服务端画面回传带来的操作延迟。生成代码和浏览器都在服务端执行，客户端只呈现受控画面并发送操作。

小程序沿用 ADR 0003：交付代码和 H5 预览，不承诺平台真机环境、审核和发布。5.11 的批注、对话修改、成果替换仍留在 5.11。

## 2. 当前基础与真实缺口

- 5.6 已完成九个固定场景、44 个最终文件的独立成品验收。318 项测试及构建通过是 ADR 0008 的历史验证记录，本次设计审阅没有重跑这些测试。
- 本次重新执行工程检查通过，重复行占比 0.78%。当前收尾提交为 `773eb52`，开始审阅时工作区干净。
- 已有：需求澄清、动态规划、节点关卡、最终文件清单、canvas 独立存储、ZIP 下载、桌面同步、Docker 执行器、算力冻结和结算。
- 尚无：应用目录级成果、可验证的启动描述、浏览器执行环境、独立预览会话、外站浏览器能力、Android 设备适配。
- 现有 harness 的执行容器会在节点结束时销毁，重启恢复会清理遗留执行容器；不能把它直接留作长期预览。
- 现有算力调用 ID 和启动时间只在执行函数的内存中保存；task 的超预算暂停只在任务 `running` 时触发。预览发生在任务完成之后，必须单独持久化与限时，不能只接一个 iframe 或复用完成前的暂停条件。
- ADR 0008 的两条中断遗留记录及供应商对账风险保持原状；新预览的恢复设计不能视为已修复这些历史记录。

## 3. 成果：一个应用是一组文件

扩展现有最终交付清单，给可运行成果附一份受校验的应用清单，包含：应用根目录、源码/运行包、入口、运行环境、启动参数、健康检查路径和文件摘要。具体字段在 5.7a 编码前冻结。

- 首批运行类型为静态网页和必要的 Node 临时后端，覆盖多页面资源、SPA 路由、模块加载、同应用 API 及按需 WebSocket。技术栈由团队决定，不写“场景 → 固定工作流”映射。
- 源码、锁文件、运行说明和可重建的运行包都属于交付。资源文件必须随包；预览阶段不临时下载 CDN 脚本、不临时安装依赖。
- 有依赖的后端在构建执行阶段准备离线运行依赖；运行包按摘要固定。再次预览不重新调用模型，也不依赖原执行容器还活着。
- canvas 继续逐文件保存和下载，通过清单聚合成一张应用卡片，展开可查看文件；ZIP 和桌面同步仍使用同一最终文件集合。
- 成果类型由显式清单标识，不把所有 HTML 或任意目录自动判断为应用。5.6 的单文件受控看板继续使用原预览。
- 安全检查覆盖完整路径、解包大小/文件数、符号链接、入口存在性和成员归属；不允许把别的用户/任务的文件拼进运行包。
- 应用只能选择平台登记的运行镜像；启动命令只在隔离容器内执行。成果清单不得指定宿主机挂载、特权、Docker socket、任意镜像或宿主机命令。

## 4. 预览：新建无模型凭据的临时会话

工作流交付后，用户在画布点击“开始预览”，harness 从 canvas 取已登记的运行包，创建专用预览环境。执行节点的容器和 dsh 会话照常结束，不延长原运行 Key。

```text
画布（可信播放器、键鼠/触控输入）
  → gateway（校验本人身份、会话归属、到期时间）
  → harness（会话、计时、控制通道）
  → 隔离的预览环境（应用 + 浏览器）
  ← 视频/音频画面、状态；不返回待客户端执行的应用 HTML/JS
```

### 隔离边界

- 生成的应用及浏览器只能访问同一预览内的应用地址；不能访问外网、宿主机、内部微服务或其他用户的预览。
- 对外传输由可信控制端处理；应用不能选择画面流目标，也不能利用控制端发任意 HTTP 请求。公开端点不暴露 CDP、ADB、通用 Shell 或 Docker API。
- 预览环境不注入模型 Key、供应商 Key、Oasis Cookie 或用户原始素材目录，只装入本成果所需文件。
- 客户端只运行平台维护的播放器，画面与输入走 gateway 的 `/api/*`。生成应用的 HTTP 请求只在服务端隔离环境的回环地址发生；不把应用页面作为 iframe 加载进用户的浏览器。
- 控制通道校验身份、会话、Origin、消息类型、大小和速率；凭据短期有效且不可用于其他 API，不写入 URL 日志，不将随机 URL 本身当作私有权限。
- 浏览器渲染进程使用非 root 和浏览器沙箱；不为“能启动”开放 privileged、宿主网络/IPC、宿主目录或关闭沙箱。镜像统一 `oasis/<组件>:<锁定版本>`。
- 网页自导航和资源请求同样受服务端网络策略约束，不能仅靠 CSP、iframe 或 Playwright 路由拦截声称断网。
- 文件下载、外链、剪贴板、摄像头和麦克风不从远端网页透传到本机；下载成果沿用画布按钮。键鼠/触控只投递给所属会话。
- 视频/音频流和输入通道先做浏览器及 Electron 原型验证，再冻结具体协议；默认不开放公网点对点直连。小游戏须测按键持续输入、声音、重开、窗口尺寸和延迟，截图可交互不等于小游戏体验合格。

### 生命周期与费用

- 建议初始默认：闲置 5 分钟停止，单次最长 30 分钟，每用户最多 1 个活动预览，全部配置化。闲置按可信用户输入/播放器状态计算，不能由作品脚本心跳无限续命。
- 状态建议：准备中 → 运行中 → 停止中 → 已停止/已过期；启动失败单独呈现。开始、停止和重复点击都必须幂等。
- 开启前显示计费方式和最长费用预估；到期、余额不足、用户停止或客户端失联超过宽限时回收资源。关闭页面不能成为唯一的停止机制。
- 继续使用 harness → model-gateway → billing 的计量链路，整数微美元记账，预览费用单独标识并关联原任务；生成费用和后续预览费用在界面上分开显示。
- 预览上限独立于已完成任务的运行限额，不重新把任务变成“运行中”。按有界会话冻结，续开前重新校验；不引入产品固定美元预算。
- 持久保存容器/会话 ID、计量调用 ID、租约截止、起止时间和待结算状态。销毁、终止时间确认、结算可重试且幂等；恢复时对账容器与数据库，不因进程重启漏计、重复计费或留下永久环境。
- 明确销毁失败、供应商状态不明和待结算情形，不能把“冻结到期退回”当作运行成本已正确闭合。预览容器使用独立标签，避免被原执行器清理逻辑误删。
- 终止只删除临时运行数据，保留成果包和计费审计。重新开始创建新会话，不保证沿用上次的后端数据或游戏存档。

## 5. UI 测试：同一报告契约，三种目标

| 目标 | 执行方式 | 交付与限制 |
| --- | --- | --- |
| 本次生成的网页/小游戏 | harness 管理的隔离浏览器，测试时启动同一运行包 | 关键流程、断言、截图、控制台错误、请求失败、运行记录；手机尺寸模拟不称为 Android 原生测试 |
| 用户给出的外部网站 | 独立浏览器执行环境，经受控联网能力访问测试目标 | 来源和目标范围、可重现步骤、失败证据；不复用用户电脑的浏览器登录态 |
| Android 原生 App | 可替换的服务端 Android 设备/云设备适配，优先采用 Appium 兼容接口 | APK 安装启动、点击/输入/滚动、断言、截图/录像、设备及系统版本、可重跑测试材料 |

- 本地生成网页使用 Playwright/Chromium，首批不承诺全浏览器矩阵。浏览器与依赖在新运行镜像中按需安装并精确锁定，不把工具塞进所有基础镜像。
- 外站浏览器与私有预览使用不同网络策略及会话，不能通过“正在测试网站”为私有预览放开网络。
- Agent 仍只通过现有入口调用能力，外部浏览器/设备动作、长会话、费用均经 model-gateway 登记与计量。harness 管执行生命周期，model-gateway 管外部适配与计费，不在 gateway 执行业务脚本。
- 原 AGENTS.md B.3 禁止给 Agent 沙箱增加网络通路。因此不得扩大软件包出口白名单来访问测试网站；实施前应在规则和本 ADR 中明确独立浏览器执行环境的受控出口边界，原 Agent 沙箱网络保持不变。
- 外站出口以任务确认的目标及其必要资源域名为界，验证 DNS 解析和每次重定向，禁止回环、内网、链路本地和云元数据地址；失败明确报告，不自动退化成无限制代理。
- 登录测试用专用测试身份，凭据由受控配置注入，不写进提示词、日志或报告。验证码、MFA、目标站不可用等导致无法覆盖的项目标为未检查；不自动使用真实账号产生业务副作用。
- Android 不依赖开发机虚拟化能力或用户手机。云设备候选可使用 BrowserStack App Automate 等 Appium 兼容平台；账户、区域可用性、设备时长计价、APK 保留/删除与 API 能力须预检后再锁定供应商，不能把文档可用当成已接通。
- APK 等大输入先检查现有 100 MB 限额；如果需提高，须先改成有界流式上传，不只改配置放大内存使用。
- 自动测试用例可由 AI 生成，但通过结论来自实际运行断言。浏览器/设备执行端产出的测试证据绑定本次运行和文件摘要，不能信任应用自己写的“全部通过”。
- 关卡复用现有“确定性检查 + 语义判断 + 未检查提醒”。功能未满足按现有规则交付并说明；隔离检查失败则禁止启动预览，仍可交付源码和说明。

## 7. 受影响模块及数据库

| 模块 | 责任 |
| --- | --- |
| harness + infra | 复用 Docker API，增加浏览器运行环境、预览管理与持久恢复；执行环境的网络策略 |
| canvas | 应用清单、成果聚合、运行包读取；继续拥有最终成果，不转移所有权 |
| gateway | 所有用户鉴权、预览/输入通道授权、外部暴露边界 |
| model-gateway | 复用冻结/结算，标识预览和设备费用，接外部测试能力 |
| task + agent | 规划能力信息、交付清单与测试证据、经验手册；不增加固定场景工作流 |
| web + desktop | 应用卡片、可信播放器、开始/停止/状态/费用；桌面端维持 IPC 与权限隔离 |
| contracts | 应用清单、预览会话、控制消息和测试报告契约 |

不新增业务微服务；有新增隔离运行环境/镜像。billing 账本优先原样复用，conversation 只在现有需求收集不能表达这些限制时小范围修改。

预计需要数据库迁移，不能承诺“与 5.6 一样无迁移”：

- harness 新建 `preview_sessions`，因为一次已完成任务可多次预览、每次有独立租约和结算，现有 `runs` 强制携带模型/提示词且结束语义不同。把预览伪装成 AI run 会污染执行恢复和费用语义；这是新生命周期，不是替换旧表的捷径。
- canvas 优先给现有成果增加可空的应用描述/关联元数据，复用逐文件记录，不另建一套平行文件表。外部设备会话优先扩展已有长任务能力；是否需额外字段在接口冻结时确定。
- Expand：先加新表/可空字段及兼容读取；Migrate：启用新类型写入，不强制把历史 HTML 回填成应用；Contract：检查并移除实施中引入的临时双写/兼容路径，新功能没有替代的旧结构不强行删除。
- 每项迁移提供 down 和 contract-plan；回滚前停止活动预览并闭合费用。无法收束的兼容项必须列为未完成，不能以“以后再说”验收完成。

新增文件限于新职责（预览管理/执行、播放器、应用/报告契约、手册、迁移及验证）；具体数量和依赖在实施搜索及协议冻结后报告，不提前填虚构数字。

## 8. 后续对接与路线数量

产品范围与严格隔离方案已确认。真正还需要对接的事项是：

- Android 云设备的账户/API 凭据与可用额度；只填本地环境变量。先确定可用服务，不先购买长期套餐。
- 真实验收的目标网站/APK及是否覆盖登录；无自有样例可选测试专用演示对象，登录用专用测试账户。
- 实际模型、设备单价和运行包大小核定后，再报 5.7 的真实验收预算、预留与停止条件；本次没有付费调用。

依据 ADR 0003 §10，5.7 之后，第 5 阶段还剩四个子阶段：5.8 音频/视频，5.9 3D/渲染（云 GPU），5.10 数字人，5.11 修改成果。之后还有第 6 阶段（群聊、@、AI 设置、自带 Key）和第 7 阶段（基线扫描）。因此按目前已编号路线，是四个子阶段加两个大阶段，共六个后续里程碑；第 6、7 阶段尚没有同等详细的实施拆分。

工程方向文档的“四阶段”是粗粒度演进路线，不能拿来推算当前 5.x 的完成数量。CI/CD、K8s、知识库等属于以后方向，当前文档没有给它们完整的确定阶段数量。

文档完整性限制：现有 ADR 引用了 `claude/business-scenarios.md`、原型和 PRD，当前仓库未找到这些原文；本设计以现存 ADR 与本次用户确认范围为依据，不宣称已逐条复核缺失的原始 14 场景材料。

## 9. 技术核对来源

- [MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)：sandbox 分别控制脚本、导航、弹窗及来源能力；不能以应用 iframe 配置代替网络层隔离。这是本设计选择服务端渲染与受控网络的依据之一。
- [Playwright Docker](https://playwright.dev/docs/docker)：不可信页面需单独评估隔离，root 会影响 Chromium 沙箱；不直接照搬示例中的宿主 IPC/开发权限配置。
- [Electron Security](https://www.electronjs.org/docs/latest/tutorial/security)：不可信内容不获得 Node/Electron 能力，维持 contextIsolation、sandbox、权限和导航控制。
- [BrowserStack App Automate / Appium](https://www.browserstack.com/docs/app-automate/appium)：用于核对云 Android/Appium 方案存在，不代表账户、价格和本项目接入已经验证。

## 11. 5.7a 实施接口冻结（2026-10-25）

- 工作流最终 `out/` 内显式交付 `oasis-app.json`，与应用文件放在同一根目录。清单第一版：`{version:1,kind:"static"|"node",root:"site",entry:"index.html"|"server.mjs"}`。相对路径只允许安全组件，`node` 的入口须是 `.mjs`/`.js` 且存在于同一最终交付文件集合。平台负责静态服务或 `node <entry>`，应用监听环境变量 `PORT` 与 `127.0.0.1`。清单不可指定命令、镜像、网络、环境密钥或额外文件。
- canvas 把清单校验结果记在该成果的可空 `app_spec` 中，其余交付文件仍各是一行。旧成果 `app_spec=null`，不推断可运行。事件重放时即使所有文件都已登记，也会补做清单校验。清单和同根目录文件可从 canvas 内部接口按所有者/任务核对后取出，大小与数量有界。
- 用户入口：`POST /v1/artifacts/:id/preview` 启动，`GET /v1/artifacts/:id/preview` 查询，`DELETE /v1/artifacts/:id/preview` 停止，`GET /v1/artifacts/:id/preview/frame` 取图，`POST /v1/artifacts/:id/preview/input` 发送受限操作。canvas 每次先核对当前用户及成果；内部 harness API 只接受 canvas，使用成果 id 和属主 id 绑定会话。用户端不取得 Docker、CDP 或运行容器地址。
- 首版画面协议用 JPEG 帧与有界操作（鼠标、键盘、滚动、触控模拟），每次请求独立鉴权；流式音频在运行镜像验证声源采集后接入同一受控通路，不能以无声截图冒充有声音的小游戏完成验收。
- 预览容器 `NetworkMode=none`，平台控制端通过现有 Docker attach 的 stdin/stdout 传输操作、JPEG 帧和状态；应用和浏览器只走容器自身回环地址。预览容器无模型 Key、对象存储凭据或宿主机挂载，只有已验证的应用文件。镜像 `oasis/harness-preview:<锁定版本>` 独立构建。
- harness 的 `preview_sessions` 保存成果/属主、状态、容器 ID、算力调用 ID、最大与闲置截止、运行起止时间、最后交互时间、错误与最终费用。单用户仅一条活动会话，重复启动返回同一会话；重启时关闭原容器并按已确认的起止时间结算，不能因进程重启把活动会话无限保留。余额不足直接拒绝启动。
- 浏览器检查和预览使用同一个构建好的运行包。执行阶段可在无网络的预览镜像里打开、跑断言、截图和控制台检查，再把证据交付；不信任应用自己写出的“测试通过”。
- 旧 `/v1/artifacts/:id/content` 保持禁止脚本策略；即使是 `oasis-app.json`，该接口只下载文件，不执行代码。数据库先扩展兼容读取再启用清单写入；没有历史 HTML 回填或旧字段双写，Contract 阶段只清理引入过程中的临时兼容路径。
