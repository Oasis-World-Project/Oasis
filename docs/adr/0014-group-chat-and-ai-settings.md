# ADR 0014：第六阶段——群聊、@、AI 设置与自带 Key

- 状态：6.1 已实施并验收（2026-11-02）；6.2–6.4 仍为设计稿。当前实现与限制见 §11–12，其他建议不视为已经确认的产品决定。
- 依据：项目工程方向、AGENTS.md、ADR 0001 的「建群 → 拉 AI → 发任务 → 画布里改 → 定稿」、ADR 0002 的群主付费约定、ADR 0003 的阶段划分、ADR 0004–0007、ADR 0012。
- 本次授权：用户已要求开始执行 6.1；本轮实现群与成员边界，不启动 6.2 的模型调用、购买服务或新增常驻资源。

## 1. 要完成的用户闭环

用户建群，邀请已登录的人、选择多家 AI。群里可聊天、@ 某个 AI 回答，或提出任务；群主确认任务单后复用现有工作流，群成员可查看共享成果，群主可发起修改和定稿。个人在已有「AI」入口设置称呼、人设和回复偏好，在「我」里管理自己的模型 Key。

不新增一级页面。群聊、私聊均不显示未读数字和红点；群用珍珠雾面与现有群主题光。广场、游戏仍用既有主题。

第六阶段不包含公开群搜索、好友推荐、自动发邀请邮件、语音群聊、跨平台 IM、群主转让、成员分摊费用和自建任意模型代理。邀请由用户自行复制链接分享。

## 2. 已有基础与需要改造的地方

| 现有模块 | 可复用 | 缺口 |
|---|---|---|
| conversation | conversations 已有 dm/group，messages、SSE、任务单和交付卡 | 当前只用 ownerId 校验，不能直接开放为多人群聊；缺成员、AI 成员、邀请和持久回复队列 |
| agent | 模型目录、路由、人设、场景手册 | 只有全局目录，没有个人或群内配置 |
| model-gateway / billing | 所有调用的冻结/结算、payerId、临时运行 Key | 需要受信选择个人凭据、区分供应商账单和平台计费，不能把成员 ID 当付费人 |
| task / canvas / harness | 任务、成果、修订、预览、删除事件与回收 | 现有权限以个人为边界，需要明确群的共享读取授权 |
| Web / desktop | 群聊占位页、聊天组件、工作流和画布预览 | 群列表/群内页、成员与 AI 设置、@ 输入、多人实时更新、Key 管理 |

不新增微服务。群关系与对话由 conversation 负责，agent 负责 AI 业务配置，凭据只能由 model-gateway 使用，其他服务不能直接读其数据库。

## 3. 群权限与上下文

建议首版只有群主和成员两种角色。群主创建/解散群、邀请/移除成员、增删 AI、修改群配置、确认付费任务、修改/删除/批准群成果。成员发消息、@ AI、提交任务建议、查看有权限的消息和共享成果，可退出群。

邀请建议为单次使用、24 小时有效、可撤销的随机令牌；只存摘要，兑换和人数上限检查在同一事务完成。被移除者不能靠旧 SSE、下载链接或 taskId 保持访问；非成员返回 404。首版不转让群主，避免历史账单和 BYOK 归属不清。

6.1 按执行前已说明的默认方案冻结为「入群可看全部群历史」，在建群、邀请预览和加入前明确告知；兑换接口必须收到主动确认。后续附件、交付和 AI 上下文须使用同一可见范围。若以后改为「只看加入之后」，必须同时限制每位接收者对应的 AI 上下文，不能只过滤前端列表却由 AI 回放旧消息。

私聊内容、个人 Key 和个人画布不因加入同一群而共享。群文件读取由服务端核对资源所属群与当前成员资格；不能接受客户端提交的 ownerId、payerId 或「我是群成员」标记。退出/移除后中止流和下载准入；已下载到本机的副本不能承诺远程收回。

## 4. @、接话与防失控

输入框的 @ 项使用稳定成员 ID/modelKey；提交正文及结构化 mentions，后端验证它们确实是当前群的成员。正文里的普通 @ 字符不自行提升权限，也不交给 LLM 判断成员身份。

建议首版显式 @ 优先：@ 一个 AI 只由它回答；@ 多个 AI 最多 3 个，按群内顺序依次回答。没有 @ 时由轻量决策在当前群启用的 AI 中选 0 或 1 个，低置信度可不接话。决策失败不广播所有 AI；明确 @ 时不必调用决策模型。

一次人类消息只开启一轮，AI 回复不再触发新一轮。默认每轮最多 3 次回复、总输出有界，群主设置单轮预算、每日预算和暂停 AI 开关；预算检查同时覆盖接话决策和回复。余额不足或 Key 不可用只生成一条简短失败状态，不反复重试或自动换付费来源。

持久轮次由 conversation 记录 requestId、触发消息、上下文截止序号、配置版本、候选 AI、状态、租约与每个回复的消息 ID。单群顺序处理，人类消息可先入库；新消息不改变已经冻结的轮次上下文。数据库序号供多端按游标补拉，SSE 只负责通知，不作为唯一消息存储。

重试不能重复扣费或重复发言。已确认未提交的请求可重试；供应商已接受但响应丢失时保留中断/未知状态，不重发。服务重启后恢复队列并续上已存消息，不能把每个浏览器订阅变成一次模型调用。取消只停止未开始的回复，已产生的费用仍正常结算。

## 5. 群里发任务与付费

延续 ADR 0002：群内平台模型、工具、算力默认由群主付费。群主在启用 AI 时明确授权群内限额；成员的 @ 不可改成向其他成员扣费。钱包余额属于群主隐私，成员只能看到本群自己的费用和限额状态。

成员可提出需求，任务单先处于等待群主确认状态。只有群主确认后才能创建付费工作流；同一确认幂等。复用现有 intake、task、harness，任务 ownerId/payerId 均为群主，另保存受信的 conversationId 与发起者 ID，不能把普通聊天自动变成多人可操控的任务。

conversation 提供内部资源授权接口；task/canvas 在群任务的读操作中向它核对成员和可见范围。群主保留工作流编辑、继续付费、删除和修订权限。成员首版仅查看进度和共享交付，不能读取群主其他任务，也不能通过文件 ID 读取其他私有素材。个人素材发入群时必须有明确的共享动作和服务端归属核对。

解散群先禁止新消息/新调用，再停止进行中的轮次和任务；群任务按既有删除事件链清理成果、运行存档及工具中间文件。账单和必要删除标记继续保留。清理采用持久状态和幂等重试，不依靠浏览器关闭时发请求。

## 6. AI 设置

agent 存个人模型配置，conversation 存群内选用配置或覆盖项。建议优先级：平台不可覆盖规则 → 群配置（群聊）/个人配置（私聊）→ 模型默认值。人设属于业务数据，不可扩大工具授权、沙箱网络或越过付费策略。

首版允许改显示名、人设、回复长短和目录已支持的模型版本；参数由目录声明支持范围，不能允许任意 providerModel、baseUrl 或系统命令。全局模型目录不为每个用户复制一份。每轮冻结配置版本；正在回复时修改设置只影响下一轮。恢复默认删除覆盖项，不另建「旧版/新版」配置副本。

## 7. 自带 Key（BYOK）与当前规则冲突

建议一期仅支持 OpenRouter。用户 Key 只用于该用户的私聊，或该用户作为群主的群；成员自己的 Key 不会因加入群被使用。先不让任务规划、工具、媒体、云 GPU 或数字人隐式切换到 BYOK，这些维持平台计费；后续扩展需单独明确费用来源。

BYOK 模型原价不再从 Oasis 额度重复扣除，仍记录 token、已知供应商成本和「自带 Key，供应商直接计费」；无法查得成本时标未知。平台接话决策、工具与算力如仍走平台，须在开启前说明。自带 Key 失败不回退平台 Key，只有用户明确切换后才变更来源。

**需要在实施前裁定的规则冲突**：AGENTS.md 当前规定密钥只放本地 `.env`，而多人产品的持久 BYOK 需要按用户保管凭据。本设计不擅自放宽该规则，也不会先写明文落库实现。

推荐的待批准例外是：服务主密钥仍只在 `.env`；用户提交的 API Key 在 model-gateway 数据库中使用带独立随机 nonce 的认证加密保存，密文绑定用户、供应商与凭据 ID；保存 keyVersion 以便轮换。日志、错误、事件、任务单、群历史、沙箱环境和浏览器持久存储中均不得出现明文 Key；读取接口只返回标签/状态，永不回显密钥。删除后阻止新调用，已提交调用按实际状态收尾，不重发。

若不批准该例外，6.3 只实施不涉及凭据的 AI 设置，BYOK 留为明确未实现项；不能换成浏览器存储或内存模式来绕过密钥规则，也不得把多用户 Key 直接写进服务 `.env`、把一人的 Key 当成共享平台配置。凭据方案确定后才冻结加密字段和轮换接口。

## 8. 数据与接口草案

所有接口均经 gateway 的 `/api/<服务>/v1/*`，鉴权仍只在 gateway 做。以下为阶段整体设计边界；其中 6.1 已冻结的子集见 §11，其余未实现、未冻结：

- conversation：群创建/详情/列表、单次邀请兑换、成员与 AI 管理、群消息提交、按序号取消息/订阅事件、轮次取消；内部按 userId + conversationId + resourceId/action 核对资源授权。
- agent：本人模型配置读取/更新/恢复默认；群主可选用自己的配置，由 conversation 保存群覆盖和版本引用。配置不含明文凭据。
- model-gateway：本人凭据新增/状态/删除；只对预定供应商域名做有界有效性检查。内部请求由会话的受信配置决定费用与凭据来源，外部不能直接指定别人的 credentialId 或 payerId。
- identity：只为群成员返回所需的最少公开资料，不新增邮箱全文搜索或用户目录暴露。
- task/canvas：现有读取路径增加群资源授权，继续保留原来的私有路径；不通过扩大原 owner 判定来统一放行。

预期持久数据：conversation 的群成员、群 AI、邀请、回复轮次/子回复记录；messages 增加序号与稳定发送者信息；agent 的用户模型覆盖；获批后 model-gateway 的用户凭据。已有 conversations/messages 保留，不能另建一套群消息库；新表仅对应不能塞进现有行的多对多关系或独立生命周期。

每项实际迁移分别做 Expand（可空字段/新关系 + down 与 contract-plan）、Migrate（历史 DM 补序号和发送者、核对数量/归属/顺序）、Contract（所有读写切换后删除临时推导、双写和回退）。Contract 未做完就不能宣布第六阶段收尾；账单不做删除式迁移。

## 11. 6.1 实施接口与数据冻结

复用 conversation 的 conversations/messages、Web 的 Composer、贴底滚动、确认按钮、查询缓存与侧栏；不新增微服务、依赖或平行消息库。群内名由用户主动填写，快照只返回群内名、用户 ID、角色所需字段，不通过群功能暴露邮箱或建立全站用户目录。

以 `/api/conversation/v1` 为前缀：

| 接口 | 行为 |
|---|---|
| `GET/POST /groups` | 当前用户所在的群列表 / 创建群并加入为群主 |
| `GET /groups/:id` | 当前成员快照；默认最近 100 条，`before` / `after` 互斥游标分页，按序号正序返回 |
| `POST/DELETE /groups/:id/invites` | 群主管理邀请；生成新邀请会删除旧记录，撤销也删除记录 |
| `POST /groups/invites/preview` | 已登录用户携带邀请码查看群名与历史告知，不能读取消息 |
| `POST /groups/invites/redeem` | 明确 `acceptHistory: true` 后兑换；同一邀请只准一个用户使用，同一用户的成功请求可重试 |
| `DELETE /groups/:id/members/:userId` | 群主移除成员，或成员退出；群主不可退出 |
| `DELETE /groups/:id` | 仅群主解散，级联删除成员、邀请与消息 |
| `POST /groups/:id/messages` | 纯文字发送，客户端 UUID `requestId` 去重；相同请求号但内容不同返回 409 |
| `GET /groups/:id/events` | SSE 成员/消息快照；`Last-Event-ID` 或 `after` 接续，成员撤权时发送 removed 并关闭 |

邀请随机 256 位、24 小时有效，数据库只存 SHA-256 摘要，令牌只在 JSON 请求体中兑换。复制链接使用 `#invite=`；未登录时仍留在 fragment，不进入登录 redirect 查询参数；登录后填入表单并清除片段。兑换、人数检查、成员准入均在事务内完成。用户准入先锁用户，群内成员修改/消息序号分配锁同一群行，避免并发超限及撤权后准入竞态。

默认每群 50 人、每用户 20 个群、每群每用户每分钟 30 条消息、每用户最多 3 条 SSE；对应 conversation 的四项 `GROUP_*` 环境配置，范围由配置 schema 限定。SSE 每秒从持久消息补拉并复核成员资格，每次最多 100 条，60 秒主动重连以让 gateway 重验会话；每连接待写超过 256 KiB 即关闭，浏览器按序号重连。当前实现适合 MVP，不承诺高并发推送性能；多副本规模化时应替换轮询通知，不改变消息序号协议。

所有非成员读取/发送返回 404；普通成员管理其他人或解散群返回 403。原私聊 `findOwned` 显式限定 kind=dm，群主也不能把 group ID 传进旧 DM/接任务接口来绕过群任务权限。6.1 群没有 AI、任务、附件入口，不调用模型或扣费。

数据演进：

- Expand `20261102150000`：给 conversations 加消息计数器、messages 加可空 seq；数据库插入触发器统一分配新序号，原 DM 写入也自动兼容。新增 group_members 为用户—群的多对多关系，group_invites 为可撤销单次准入生命周期；均不能用 conversations/messages 的单行字段表示，不替换已有表。
- Migrate `20261102150100`：按 created_at/id 回填旧消息序号；迁移期间新插入从旧消息总数之后分配，避免冲突。down 保留已分配顺序，避免破坏线上消息身份；完全撤销新增字段由 Expand/down 完成。
- Contract `20261102150200`：落实非空、正序号约束及群内唯一索引，退出历史时间推导。三个迁移分别可执行 down；本地真实数据库已应用，独立测试库已验证全套 down/up 且原 DM 数据保留。本轮无遗留双写/兼容链路或待收缩字段。

## 12. 6.1 验收与收尾记录（2026-11-02）

受影响模块是 contracts、conversation、Web（含登录后的邀请延续）及本 ADR，共修改 25 个文件，其中新增 10 个：契约、repo/service/api 三层、群内页、3 个迁移和 2 个测试文件。新增只承接独立职责，不保留平行版本。群列表占位、侧栏禁用拉群与固定空群提示已被真实实现替换；Composer 保持复用，群模式只显示文字发送。
