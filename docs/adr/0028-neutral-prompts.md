# ADR 0028：给 AI 的规则不带倾向

状态：已采纳（用户 2026-11-10 决定：「我们不该给 AI 加上这种趋向性，应该让它自己判断。不存在“越少越好”或者“越多越好”。重新检查所有我们给 AI 上的规则/限制，找出所有“不中立”并修改」）

## 1. 背景

- ADR 0018 把提示减到只讲任务、资源和格式，但留了一句原则「用最简单能做好的方案，简单任务一个节点」，之后又加了「省钱靠少排节点、少做几版」。2026-11-10 的小游戏、3D 场景任务都只排出一个节点，讨论、单独的工具节点、逐条展开、做几版挑一版在自然说法下基本不出现。
- 这类句子不是事实，也不是硬约束，而是替 AI 预先定了方向（少排、少做、少问、早交）。把方向反过来写成「能分头做就分头做」同样是倾向。

## 2. 决定

给 AI 的话只有三种：**事实**（有什么、多少钱、各自看得到什么）、**硬约束**（格式、上限、系统做不到的事、角色边界）、**用户的要求**（任务单、修改意见）。不写「尽量 / 宁可 / 只在…时才 / 够用就 / 别再」这类把选择往一边推的话；原来这类句子背后有事实的，改成只写事实，没有的删掉。

### 2.1 改掉的

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| 规划员（`planner.ts`） | 用最简单的方案，简单任务一个节点就够，确实需要分工或并行才拆 | 排几个节点、用哪种、哪些同时做、要不要做几版、用什么模型和工具由规划员按任务判断，没有越少越好也没有越多越好 |
| 规划员 | 省钱靠少排节点、少做几版，不靠换弱模型；难活用旗舰或强力档 | 删掉；模型目录前写明三档各是什么（旗舰最强、强力次一档、快速是私聊用的轻量型号，复杂推理和写代码弱于前两档） |
| 规划员的预算段 | 按它挑模型和工具；没选档时「按常规质量安排」 | 只说预算是参考不是上限、预估花费会显示给用户 |
| 节点格式（`planner-rules.ts`）讨论 | 只在真要权衡取舍时用 | 适合要从几个立场权衡取舍的问题 |
| 节点格式 工具节点 | 机械活用 tool，便宜也不会跑偏；要看内容的用 work | 不调模型、严格照步骤执行，所以步骤和参数要事先定得下来；要看了内容才知道怎么做的事它做不了 |
| 节点格式 展开 | 条数事先知道而且很少时直接排几个节点 | 适合条数要等上游定下来的情况；条数事先知道时也可以直接排成几个节点 |
| 节点格式 做几版 | 只给看运气的生成步骤用 | 做几版就花几倍的钱、另加一次挑选；常见用法是结果看运气的生成步骤 |
| 节点格式 干活节点 | （没写） | 补一条事实：节点只看得到任务、任务单、自己的 goal 和上游交来的文件，看不到别的节点的过程 |
| 估价远超预算的退回（`budgetProblems`） | 让方案大致落在预算内 | 请核对各项数量，写错了就改 |
| 修改的规划（`revision-planner.ts`） | 接着原会话改只适合会话短、改动小的节点 | 会话里有上一版的全部过程，接得上原来的思路；会话越长每次调用越贵 |
| 干活节点的预算段（`kinds/work.ts`） | 花的是用户的钱、用户也在等：够用就交 | 预算和预计用时都是参考，不是上限 |
| 超支提醒（1.5 倍、2 倍各一次） | 请收尾，别再打磨 | 只报已花、份额和用时；接着做还是现在交付由节点判断 |
| 讨论发言（`kinds/discussion.ts`） | 不用调工具，除非需要看 in/ 里的材料 | 只说发言就是最后一条消息、不用写文件；查不查资料由参与者判断 |
| 做几版里的一版（`kinds/variants.ts`） | 走你自己的方向，不要做成最保守的那种 | 各版同时做、互相看不到，做完比较后选一版交给下游 |
| 接需求（`conversation/intake.ts`） | 能合理默认的也不要问，宁可少问；改任务单时尽量不问 | 已经清楚的不重复问；还缺的信息问用户还是自己定由 AI 判断 |
| 手册 3d | 用户没要渲染图就不用云渲染 | 云渲染出的是渲染图、按作业计费、要等几分钟；看效果另有沙箱里的 snapshot |
| 手册 web-apps | 能做成静态的就做成静态的 | 带后端的画布里不能运行、只能下载；静态的可以直接运行 |
| 手册 digital-human | 开场白要短 | 只留「按分钟计费」 |
| 手册 images、marketing | 要文字就先出无字底图再用 Pillow 排 | 生图模型写中文常出错；沙箱有 Pillow，可以排字 |

### 2.2 保留的（不是倾向）

- **角色边界**：规划员只排方案、不动手试跑；报价草案只估工具用量；接需求只问普通人听得懂的问题；私聊的 AI 不负责执行任务。
- **硬上限和格式**：自查最多 5 条、展开最多 24 条、做几版 2–4 版、每轮最多 4 道题、验收标准最多 8 条、展开节点不能直接交付、只输出 JSON 等。
- **忠实于用户**：交付物只列用户要的；修改时只动意见涉及的地方、没要求改的保持不变；修复时只修系统查出的问题。
- **不编造**：结论标出处、不编数据和引用；证据不足不声称满足；没读过的文件不假装读过。
- **产品定义**：三档预算的含义（省钱只做一次、精细允许多做几版）；私聊人设（自然、简洁）；数字人语音每次 1–3 句；手册里的格式默认值（Markdown、MP3）。

### 2.3 没动、但会影响规划的

报价仍按「规划员 + 每样交付物一个节点」估（ADR 0018 §12，用户当时同意不做先规划再报价）。它不是给 AI 的规则，但预算数字来自它，规划员看到的预算因此偏向节点少的方案。规划员提示里已写明预算是参考不是上限；报价算法要不要改另行决定。

## 3. 影响

- 取代 ADR 0018 §2 的那句原则和 §7 给规划员加的那句话；§6 的超支提醒保留，措辞改为只报事实。ADR 0026 §9 里「什么时候用」的写法同步改为描述特点。
- 省钱档报价仍按强力型号里最便宜的算（代码没动）。
- 超支提醒不再要求收尾，节点可能比以前多花；预算本来就是参考（ADR 0016 §2），余额不足时模型网关照常拒绝。
- 不改接口、数据库和节点种类。
