# ADR 0021：检查过的网页，画布里一定打得开

状态：已采纳（用户 2026-11-08 同意）。取代 ADR 0009 里「本机框加载不全时改用平台容器预览」「带后端的应用走平台容器预览」两处。

## 1. 起因

雨夜便利店任务（2026-11-07）：网页节点交出 11 个文件，用 ES 模块串联引用（`app.js` → `three.module.js` → `three.core.js`，`GLTFLoader.js` → `utils/`）。节点的 `app.check` 在 HTTP 服务器上跑，通过了；画布的本机隔离框把文件内联进一页，模块之间的相对引用解析不了，打开是黑屏。改用平台容器预览，画面糊、卡、不能正常操作。另外 `oasis-test.json` 放在了 `out/` 而不是 `out/site/`，检查只写了一句「未提供」，实际只做了启动检查。

问题不在网页本身（放在服务器上能跑），在于检查和用户看到的不是同一个运行环境。

## 2. 决定

1. **画布本机预览支持多文件 ES 模块。** 组装规则搬进新包 `packages/live-page`（`@oasis/live-page`），画布和检查共用。模块的引用（相对路径、importmap 里的裸名字和前缀、静态和字面量动态 import）改写成 `oasis-file:/<路径>`；框里第一段脚本把模块原文做成 blob 地址，再插一份 importmap 映射过去。循环引用、同一模块只加载一次都照常。用 es-module-lexer 的纯 JS 版解析，不需要 WebAssembly。
2. **`app.check` 和节点关卡按画布的方式打开静态网页。** harness 把入口换成一个只放隔离框的外壳，框里是和画布一模一样的文档（同一份 CSP、同一个 sandbox）；测试步骤对着框里的页面做。画布里加载不了的文件直接算没通过，原因里写明画布的规则（fetch/XHR 读本地文件、CDN、localStorage 不行）。
3. **画面检查。** 加载完后每隔 30 个动画帧截一次图，只要不是一整片纯色就算画出来了；最多等 300 帧。和最常见颜色差得明显的像素不到千分之一，才算纯色，少量文字、细线都能过。
4. **测试计划放错目录明确报错。** 关卡里 `oasis-test.json` 不在 `oasis-app.json` 同目录时直接没通过并说清楚位置；自查没有测试计划时，提示要和清单放在同一目录。
5. **删除画面转发式的平台容器预览。** 删掉成果页的按钮和提示、canvas 的 `/v1/artifacts/:id/preview*` 和 `/internal/applications/lookup`、harness 的 `/internal/previews*`、画面输入和声音转发。检查用的容器浏览器保留。带后端（`kind: node`）的应用画布里不运行，只能下载；经验手册写明能做成静态就做成静态。以后真有后端类需求，再做「容器只跑后端、网页经独立预览域名嵌进画布」。
6. **交付物只放用户要的。** 接需求的规则：为了做成果顺带产生的预览图、效果图、参考图、草图不单独列成交付物，除非用户要了。规划员规则：deliver 只放任务单上的交付物，过程文件只在节点之间传递。

## 3. 同步改动

- `AGENTS.md` 共享包一条加上 `live-page`。
- 经验手册 `web-apps.md`：画布怎么运行静态作品、`oasis-test.json` 的位置、带后端的作品只能下载。
- 检查镜像 `oasis/harness-preview:1.64.0` 里的控制端变了，要重新 `pnpm preview:build`。
- 配置删除 `PREVIEW_IDLE_MS`。

## 4. 验证

- 雨夜便利店的 11 个原文件：按画布的方式在 Chromium 156 里打开，没有缺文件、没有报错，场景和雨都画出来了；经 harness 在真实检查容器里跑 `app.check`，44 秒通过（1 核）。
- 反例（全黑页面 + fetch 读同目录 JSON）：7 秒没通过，原因列出 CSP 拦截和画面纯色。
- 注意：用独立脚本在开发机上跑真实检查时，正在运行的 harness 会把带 `oasis.component=preview` 标签、又不在它库里的容器当孤儿删掉，测试容器要换标签。
