# ADR 0007：前端主干（5.5）——私聊卡片、上传素材、工作流视图、画布框架

- 状态：5.5a 按本文实现（2026-10-23，待用户确认）；5.5b、5.5c 做到时补充
- 依据：ADR 0003 第 2 节（canvas 负责上传和文件夹同步）、ADR 0004（工作流控制面）、ADR 0005（进门与出门）
- 范围：web、conversation、task、harness、canvas、gateway（不新增服务）

## 背景

5.1–5.4 把接需求、规划、跑节点、用工具、交付都做成了接口，界面上只有文字气泡。5.5 把它们做成能看、能点的界面，分三步：

| 步骤 | 内容 |
|---|---|
| 5.5a | 私聊里的问题卡、任务单卡、任务卡、交付消息；上传素材 |
| 5.5b | 工作流视图（节点和连线、状态、编辑、整体或单个运行 / 停止）、节点详情（运行过程、工具、花费、关卡提醒、产出、追问） |
| 5.5c | 画布框架：成果登记进画布、在画布里打开和预览；桌面端把成果同步到本地文件夹 |

## 决定（5.5a）

### 1. 私聊卡片

- 卡片的数据都是 5.3 已有的（`messages.kind` + `data`），前端按类型画卡片；文字气泡照旧。问题卡和任务单卡多带一个 `intro`（AI 在卡片上方说的那句话，旧消息为空）。
- 任务卡只存 `taskId`，进度、花费、需要处理的原因由前端向 task 查；任务还在动时每 2.5 秒刷新一次，结束后不再刷新。任务状态一变就刷新消息（交付消息和提醒要等 conversation 收到 task 的事件才写进来，所以过 2 秒、6 秒各再刷一次）。
- 「需要处理」时按原因给选择，和 task 的规则一一对应：节点失败（再试一次 / 跳过它继续 / 取消）、超过花费上限（提高上限继续 / 取消）、预估超过用户设的上限（按预估做 / 取消）、规划失败（重新规划 / 取消）、连线断开（取消；接线在 5.5b 的工作流视图里做）。取消要再点一次确认。后面已经有这个任务的提醒消息时，选择放在提醒里，任务卡上只写一句原因。
- 交付消息按交付物列出文件，可以预览（图片、视频、音频、PDF、Markdown、文字、静态网页）和单独下载。

### 2. 成果文件的安全

成果文件是 AI 写的，可能是带脚本的网页或 SVG，又和应用同源：直接打开时脚本能借用户的登录状态调接口。所以下载接口一律加 `Content-Security-Policy: sandbox`（脚本不跑、来源变成不透明）和 `X-Content-Type-Options: nosniff`；PDF 例外（加了浏览器自带的阅读器就打不开，PDF 里的脚本浏览器本来就不执行）。`?download=1` 时让浏览器另存。预览网页用不带 `allow-same-origin` 的 iframe。能运行的网页和应用（场景 4、5）以后放到独立的预览域名，不在这个接口里跑脚本。这组响应头放进 service-kit，task 和 canvas 共用。

### 3. 上传素材：存在 canvas

- 按 ADR 0003 的分工，素材文件由 **canvas** 保存（自己的数据库表 `uploads` + 对象存储桶 `canvas`）。5.5c 的成果登记、文件夹同步接着用同一个服务。
- 对象存储的读写从 harness 挪进 service-kit（harness 和 canvas 共用，不各写一份）。
- 上传：`POST /v1/uploads?name=<文件名>`，请求体就是文件本身（不用 multipart，前端用 XHR 发，能显示进度）。单个文件最多 **100 MB**（`UPLOAD_MAX_BYTES`），一条消息最多带 **10 个**。返回 id、文件名、大小、类型。
- 下载：`GET /v1/uploads/:id`（只能下载自己的），响应头同第 2 节。
- 内部接口：`POST /internal/uploads/lookup`（按 id 查文件信息并核对是谁的，给 conversation）和 `GET /internal/uploads/:id/content`（取文件内容，给 harness）。
- 现在不做删除和过期清理；任务删除（以后）时再一起清理。

### 4. 素材怎么交给工作流

```
前端：选文件 → 逐个上传到 canvas → 拿到 id
     → 发消息时带上 attachments: [id…]
conversation：向 canvas 核对文件属于这个用户 → 记在用户消息上（显示成附件）
     → 接需求期间收到的附件记进 intakes.materials；问题卡和任务单阶段只把文件名和大小告诉 AI
     → 确认任务单时：任务单的「素材」= 这些文件名；把 materials（id、文件名、大小）交给 task
task：存在任务上（tasks.materials）；规划员和每个节点运行时都带上
harness：开沙箱前按 id 向 canvas 取文件，放进沙箱的 materials/ 下（和 in/、out/ 并列）
```

- 放在 `materials/` 而不是 `in/素材/`：`in/<节点名>/` 是上游节点的产出，节点名可以是中文，放在一起可能重名。同名文件自动加序号。
- 节点说明里写明「用户给的素材在 materials/ 下」并列出文件名。
- 素材不经过对象存储以外的地方复制：harness 每次运行时向 canvas 取。

### 5. 前端的上传

- 输入框「＋」里有「添加文件」，也可以把文件拖进对话区或直接粘贴。选中后立即开始上传，输入框上方显示文件条（名字、进度、可移除）；全部传完才能发送。
- 用户消息下面显示附件，点开就是 canvas 的下载地址。

## 后果

- harness 多依赖一个内部服务（canvas）。canvas 不可用时带素材的运行会失败并按 5.2 的重做规则处理。
- 素材按每次运行取一份放进沙箱；大文件（视频）会多花一些拷贝时间，不额外计费。
- 100 MB 的上限对视频素材偏小，场景 3、7 做到时按需要调 `UPLOAD_MAX_BYTES`（canvas 现在把整个文件读进内存再存，调大之前要改成流式）。
