# ADR 0007：前端主干（5.5）——私聊卡片、上传素材、工作流视图、画布框架

- 状态：5.5a、5.5b、5.5c 按本文实现（5.5a 2026-10-23，5.5b、5.5c 2026-10-24），待用户确认
- 依据：ADR 0003 第 2 节（canvas 负责上传和文件夹同步）、ADR 0004（工作流控制面）、ADR 0005（进门与出门）
- 范围：web、conversation、task、harness、canvas、gateway（不新增服务）

## 背景

5.1–5.4 把接需求、规划、跑节点、用工具、交付都做成了接口，界面上只有文字气泡。5.5 把它们做成能看、能点的界面，分三步：

| 步骤 | 内容 |
|---|---|
| 5.5a | 私聊里的问题卡、任务单卡、任务卡、交付消息；上传素材 |
| 5.5b | 工作流视图（节点和连线、状态、编辑、整体或单个运行 / 停止）、节点详情（运行过程、工具、花费、关卡提醒、产出、追问） |
| 5.5c | 画布框架：成果登记进画布、在画布里打开和预览；桌面端把成果同步到本地文件夹 |

## 决定（5.5a）

### 1. 私聊卡片

- 卡片的数据都是 5.3 已有的（`messages.kind` + `data`），前端按类型画卡片；文字气泡照旧。问题卡和任务单卡多带一个 `intro`（AI 在卡片上方说的那句话，旧消息为空）。
- 任务卡只存 `taskId`，进度、花费、需要处理的原因由前端向 task 查；任务还在动时每 2.5 秒刷新一次，结束后不再刷新。任务状态一变就刷新消息（交付消息和提醒要等 conversation 收到 task 的事件才写进来，所以过 2 秒、6 秒各再刷一次）。
- 「需要处理」时按原因给选择，和 task 的规则一一对应：节点失败（再试一次 / 跳过它继续 / 取消）、超过花费上限（提高上限继续 / 取消）、预估超过用户设的上限（按预估做 / 取消）、规划失败（重新规划 / 取消）、连线断开（取消；接线在 5.5b 的工作流视图里做）。取消要再点一次确认。后面已经有这个任务的提醒消息时，选择放在提醒里，任务卡上只写一句原因。
- 交付消息按交付物列出文件，可以预览（图片、视频、音频、PDF、Markdown、文字、静态网页）和单独下载。

### 2. 成果文件的安全

成果文件是 AI 写的，可能是带脚本的网页或 SVG，又和应用同源：直接打开时脚本能借用户的登录状态调接口。所以下载接口一律加 `Content-Security-Policy: sandbox`（脚本不跑、来源变成不透明）和 `X-Content-Type-Options: nosniff`；PDF 例外（加了浏览器自带的阅读器就打不开，PDF 里的脚本浏览器本来就不执行）。`?download=1` 时让浏览器另存。预览网页用不带 `allow-same-origin` 的 iframe。能运行的网页和应用（场景 4、5）以后放到独立的预览域名，不在这个接口里跑脚本。这组响应头放进 service-kit，task 和 canvas 共用。

### 3. 上传素材：存在 canvas

- 按 ADR 0003 的分工，素材文件由 **canvas** 保存（自己的数据库表 `uploads` + 对象存储桶 `canvas`）。5.5c 的成果登记、文件夹同步接着用同一个服务。
- 对象存储的读写从 harness 挪进 service-kit（harness 和 canvas 共用，不各写一份）。
- 上传：`POST /v1/uploads?name=<文件名>`，请求体就是文件本身（不用 multipart，前端用 XHR 发，能显示进度）。单个文件最多 **100 MB**（`UPLOAD_MAX_BYTES`），一条消息最多带 **10 个**。返回 id、文件名、大小、类型。
- 下载：`GET /v1/uploads/:id`（只能下载自己的），响应头同第 2 节。
- 内部接口：`POST /internal/uploads/lookup`（按 id 查文件信息并核对是谁的，给 conversation）和 `GET /internal/uploads/:id/content`（取文件内容，给 harness）。
- 现在不做删除和过期清理；任务删除（以后）时再一起清理。

### 4. 素材怎么交给工作流

```
前端：选文件 → 逐个上传到 canvas → 拿到 id
     → 发消息时带上 attachments: [id…]
conversation：向 canvas 核对文件属于这个用户 → 记在用户消息上（显示成附件）
     → 接需求期间收到的附件记进 intakes.materials；问题卡和任务单阶段只把文件名和大小告诉 AI
     → 确认任务单时：任务单的「素材」= 这些文件名；把 materials（id、文件名、大小）交给 task
task：存在任务上（tasks.materials）；规划员和每个节点运行时都带上
harness：开沙箱前按 id 向 canvas 取文件，放进沙箱的 materials/ 下（和 in/、out/ 并列）
```

- 放在 `materials/` 而不是 `in/素材/`：`in/<节点名>/` 是上游节点的产出，节点名可以是中文，放在一起可能重名。同名文件自动加序号。
- 节点说明里写明「用户给的素材在 materials/ 下」并列出文件名。
- 素材不经过对象存储以外的地方复制：harness 每次运行时向 canvas 取。

### 5. 前端的上传

- 输入框「＋」里有「添加文件」，也可以把文件拖进对话区或直接粘贴。选中后立即开始上传，输入框上方显示文件条（名字、进度、可移除）；全部传完才能发送。
- 用户消息下面显示附件，点开就是 canvas 的下载地址。

## 决定（5.5b）

### 6. 工作流视图和节点详情

- 地址 `/canvas/tasks/:taskId`（成果属于画布，侧栏亮「画布」）；私聊里的任务卡上有「看工作流」进来。照原型 ⑬：点阵底、节点卡片（谁在做、标题、一行说明、状态）、连线按下游状态分已完成 / 进行中（珊瑚色流动）/ 等待 / 断开（珊瑚色短虚线 + 小圈），右侧节点详情面板。
- 画图用 React Flow（`@xyflow/react`，只用平移、缩放、拖线）。节点位置不存库，每次按图自动分层排（最长上游链定列，同一列按上游位置排）；节点不能拖动。
- 能做的事和 task 的规则一一对应（前端只是不给出会被拒绝的按钮，最终以 task 为准）：
  - 整体：全部运行 / 全部停止；任务在跑时有新建节点，「把新节点加进来」（同样是整体运行）；取消任务（再确认一次）；需要处理时在图上方给出和任务卡一样的选择。
  - 单个节点：还没开始的能编辑、删除；新建、等待（上游都已完成）、已停止、失败的能单独运行（停止的叫「继续」，失败的叫「再试」）；运行中、检查中的能停止。
  - 接线：从节点右边拖到另一个节点左边；只能接到还没开始的节点。有断开的线头时，拖出来的线优先把它接上（改那条线），没有才新建。选中连线可以删除。拖线之外，详情面板里也能「加一个上游」、删掉某条进线（键盘可用）。
  - 加节点：干活或讨论；名字、要做的事、角色、模型、关卡（最多 5 条），干活节点选工具和预计次数，讨论节点选 2–5 位参与者和轮数；可以顺手接在某个节点后面。节点名（也是下游的目录名）从名字生成，不重名。新节点是「新建」，不会自动开跑。
- 节点详情：谁在做（讨论列出参与者、立场和写结论的模型）、状态和操作、关卡提醒、要做的事、关卡、上下游、你补的要求、工具（用普通话名字）和花费、产出文件（预览和下载）、讨论记录、它最后说的话、运行过程。
- 追问和补要求：运行中的干活节点直接送进它的会话；还没开始、已停止的节点和讨论节点记下来，开跑或继续时带上（5.2 的规则）。检查中、已结束的节点不给输入框。

### 7. task 为此补的三个接口

- `GET /v1/tasks/:id/nodes/:nodeId/runs`：节点的每次运行（第一次、失败重做、关卡退回修改、停止后继续、讨论的每次发言和汇总），按时间排。原来的运行过程接口只看节点当前这次，关卡退回或停止后继续时前面的过程就看不到了。
- `GET /v1/tasks/:id/nodes/:nodeId/events?runId=`：看指定那次运行的过程（只能是这个节点的运行）；不给 `runId` 时和以前一样看当前这次。
- `GET /v1/workflow/options`：编辑节点时能选的模型和工具，和规划员看到的一样（去掉当前网络用不了的模型、没配 Key 的工具）。
- 运行过程在前端写成普通话：AI 说的话、你说的话、「写文件 out/a.md」「调用工具『生成图片』」（从命令里认出 `oasis-tool`），失败的调用标出来。

## 决定（5.5c）

### 8. 成果登记进画布

- 什么算成果：任务**完成**（`succeeded`，包括整体验收有没满足但照样交付的）时，负责交付物的节点交出的文件，和交付消息里列的是同一批。失败、取消的任务不登记（节点产出在工作流视图里照样能看、能下载）；中间节点的产出不登记。
- 怎么登记：canvas 持久消费 `task.task.status_changed`（`canvas-task-succeeded`），收到完成就向 task 要任务详情，把每个成果文件经 task 新增的内部接口 `GET /internal/tasks/:id/files/:nodeId/*` 取来，**复制**进 canvas 自己的桶（`artifacts/<用户>/<成果 id>`），再写一行 `artifacts`。按（任务、节点、文件路径）唯一，重复收到事件不会重复登记；中途失败就抛错，事件重投时接着登记没登记上的。
- 为什么复制而不是引用 harness 里的运行产出：画布要能按段读（拖动视频进度）、要给桌面端同步、以后「让 AI 改」会用新成果替换旧成果——这些都不该依赖 harness 的运行存档还在不在。只复制最终成果，中间产物不复制（ADR 0004 §5 的原意）。
- 一行成果记：所属用户、任务（标题、私聊会话）、交付物名、节点、文件路径、大小、类型、类别、做它的模型（头像用），以及同步到电脑时的相对路径 `syncPath`。
- 类别照原型 ⑧：文档和图片 / 音频和视频 / 3D 和实景 / 网页和应用 / 数据和其他，由 canvas 按扩展名定。
- 现在不做：批注和「发给 AI 修改」、删除成果、新版本替换旧版本（都在「修改成果」那一步一起做）。

### 9. 画布页面和预览

- `/canvas`：照原型 ⑧，类别标签（带数量）+ 搜索 + 成果卡片（缩略图、名字、来自哪个任务、做它的 AI）。可以按任务筛选（`?task=`，交付消息和任务卡上的「在画布里看」用它）。
- `/canvas/artifacts/:id`：照原型 ⑨⑩ 的外观——点阵底，左上返回 / 任务名 / 文件名，右上工作流 / 回到私聊 / 下载，中间预览：图片、视频、音频、PDF、Markdown、文字、静态网页（沙箱 iframe）；其他格式提示下载。
- `GET /v1/artifacts`（列表，可按类别、任务筛选）、`GET /v1/artifacts/:id`、`GET /v1/artifacts/:id/content`。内容接口**流式**返回并支持分段请求（`Range` → 206），视频、音频能拖动进度；响应头同第 2 节（沙箱、nosniff、`?download=1` 另存）。素材下载也换成同样的流式读法。

### 10. 桌面端把成果同步到电脑

- 只做「成果同步回来」这个方向（用户 5.5 的要求）；「本地资料自动同步上去」以后再做（现在用上传）。
- 用户在画布页点「同步到电脑」，用系统对话框选一个文件夹（只能由用户选，页面不能指定路径）。之后桌面端每次打开画布、以及每 60 秒，把还没同步过的成果下载进去：`<文件夹>/<任务名>/<文件路径>`，路径由 canvas 算好（`syncPath`，去掉 Windows 不允许的字符，同名任务加序号）。
- 下载由页面做（它有登录状态），写文件由主进程做：preload 只暴露 `oasisDesktop` 的几个接口（选文件夹、看同步状态、写一个文件、打开文件夹）；主进程只往用户选的文件夹里写，路径不能跳出去，单个文件有大小上限。
- 同步记录（哪些成果同步过）存在桌面端自己的数据目录里。用户在电脑上删了某个同步下来的文件，不会再被下回来；成果有新版本时（以后）才会再下载。
- 顺带解决「找不到下载的文件」：桌面端里点下载，文件存进系统的「下载」文件夹（重名加序号，不弹框），存好后在文件管理器里选中它。
- 已经有同名文件（可能是用户自己改过的）时不覆盖，只记为同步过；先写临时文件再改名，写到一半断了不会留下半个文件。

## 后果

- harness 多依赖一个内部服务（canvas）。canvas 不可用时带素材的运行会失败并按 5.2 的重做规则处理。
- 素材按每次运行取一份放进沙箱；大文件（视频）会多花一些拷贝时间，不额外计费。
- 100 MB 的上限对视频素材偏小，场景 3、7 做到时按需要调 `UPLOAD_MAX_BYTES`（canvas 现在把整个文件读进内存再存，调大之前要改成流式）。
- 节点位置每次自动排，用户不能手动摆；节点多了（> 12 个，规划员的上限）以后再看要不要记住位置。
- React Flow 的署名按它的要求保留在右下角（免费版隐藏署名需要订阅）。
- 最终成果在 harness 和 canvas 里各存一份；交付文件不大（文字、图片为主），视频变多后再看要不要定期清理 harness 的运行存档。
- 登记时把整个文件读进内存再存，和上传一样受单文件大小影响；视频成果变大后改成边读边存。
- 桌面同步只在桌面端开着时进行；关着的时候完成的任务，下次打开画布时补上。
