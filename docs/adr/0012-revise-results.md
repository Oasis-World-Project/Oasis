# ADR 0012：5.11 修改成果

- 状态：已实施。2026-11-05 用户决定：修改在**原任务里接着原会话做**，不再新建修订任务（取代本 ADR 最初的“新建一条工作流、整体替换上一版”）。§8 之后的实施记录描述的是当时的旧流程，保留为历史。
- 依据：ADR 0003 §1（修改成果、旧版本不保留）、ADR 0004 §2（检查只提醒、不拦截）、ADR 0005（进门和出门）、ADR 0007（画布与桌面同步）、AGENTS.md
- 范围：contracts、task、canvas、conversation、web、desktop。不新增服务、不新增表（§15 给 canvas `uploads` 加了一列）。

## 1. 用户看到的规则

| 规则 | 内容 |
|---|---|
| 在原任务里接着改 | 用户在成果页批注（顶栏画笔图标）并在批注面板底部「发给 AI 修改」，可再补文字意见、附文件。原任务接着跑：负责交付的节点接着自己上次的会话按意见改，下游节点基于上游新产出接着自己的会话跟着更新。不新建任务、不重新规划、不重新问需求，画布上始终只有这一个任务卡片 |
| 发给谁 | 默认是做出这一版的私聊 AI；可以换成另一个 AI，修改意见和任务卡出现在那个私聊里。节点用什么模型仍由工作流决定 |
| 原地换成新版 | 改好后画布里的成果原地更新：链接、同步路径不变，登记时间更新；已经交给 AI 处理过的批注和截图一起清掉。没改的文件不动。旧版本不保留 |
| 没改成 | 节点断网停下时任务停在那里，用户点开节点「继续」；用户取消时成果保持上一版（内容只在新版交付时才替换），之后可以再发起修改 |
| 同时只改一版 | 任务正在改（没结束）时不能再发起修改，成果页顶栏的批注图标换成转圈图标，点开看进度 |
| 删除成果 | 以任务为单位：在画布任务卡片上点垃圾桶图标、原地确认「彻底删除？」。删除是真删除（§15）：数据库记录、对象存储里的文件、运行存档、聊天里的任务卡片一起删掉，不留回收站；只保留账本里的金额记录 |
| 电脑上的文件 | 已同步的旧版如果用户没改过就直接覆盖；改过的另存为「名字 (新版).扩展名」。删除成果不删电脑上的文件 |
| 批准 | 已从界面去掉（用户 2026-11-04 认为没有意义）；接口和 `approved_at` 列保留不用 |
| 按段重做 | 批注或修改意见只指向某一章、某一张、某一块即可，节点只改那里 |
| 参数面板 | 只影响观看的在页面上直接调；改成品的参数生成一条结构化修改意见，走同一条修改路径（5.11c） |

## 2. 数据流

```
成果页批注面板「发给 AI 修改」（标注截图在浏览器里合成后作为附件上传）
  → conversation POST /v1/conversations/:id/revisions {taskId, request, annotations, parameters, attachments}
      → task POST /internal/tasks/:taskId/revise {ownerId, request: 原话+每条批注一行+参数, materials: 附件}
          · 只有已结束的任务能改（正在跑、正在改的 409）
          · 附件并进任务素材（每次运行都放进 materials/）
          · 交付节点和全部下游：waiting，config.revision = 修改意见；任务回到 running，验收记录清空
      → 私聊里插入：用户的修改意见、同一个任务的任务卡（标成「修改」）
  → 节点开跑：接着上次的运行会话（continueFrom），提示词是修改意见；下游拿上游最新产出
  → 节点关卡、整体验收照常（只提醒、不拦截，ADR 0004 §2）→ succeeded
  → canvas 消费 task.task.status_changed(succeeded)：
      同一 nodeId/path 已登记且任务交付时间晚于登记时间 → 复制新文件，摘要变了就原地更新内容、
      记 replacesSha256、清批注与截图；新出现的文件照常登记
```

## 3. 节点怎么改

- **提示词**：`revisionPrompt`——用户看过成果，提出以下修改意见（附件在 materials/，截图编号和批注编号一致）；在你上次的成果基础上接着改，只改涉及的地方，其余内容、结构和风格不变；上游有更新以 inputs 里的最新产出为准；改完在 out/ 交齐全部成果。
- **会话**：交付节点和下游都用原会话（`reworkStep` + `continueFrom` 上次运行），不重读整份成果，不重新规划。节点的返工计数清零，修改那一轮之后的关卡最多再自动改一次（ADR 0004 §2）。
- **花费**：记在原任务上，任务卡片的“已花”累计。

## 4. 契约

- task：`ReviseTaskBody {ownerId, request ≤ 20000 字, materials ≤ 20}`；`POST /internal/tasks/:taskId/revise` 返回 `TaskBody`。节点配置 `revision?: string`。
- conversation：`POST /v1/conversations/:id/revisions` 不变（`request`、`annotations`、`parameters`、`attachments`）；任务卡 `data: {taskId, revisionOf: taskId}`（指向自己，卡片标成「修改」）。
- canvas：`ArtifactsRepo.replaceContent`（内容换新版、清批注与批准、更新登记时间）。`ArtifactBody.replacesSha256` 沿用，桌面端据此覆盖旧版。
- desktop：`beginSyncedFile` 的成果标识可以是「id@新摘要」：同一个成果原地换成新版后再同步一次，记录不和第一次重复。
- 删除：`POST /internal/revisions/materials`、`RevisionMaterialsBody/Result`、conversation 里拼修订任务单与说明的代码（`revisedSheet`、`revisionBrief`、`revisionCriterion`）。

## 5. 数据库与旧数据

- 不新增迁移。`tasks.revision_of`、`uploads.source_task_id`、`artifacts.replaces_sha256` 保留：2026-11-05 之前已经建好的修订任务仍按旧流程交付（canvas 整体替换上一版、task retire 上一版），之后不再产生新的修订任务。
- Contract 计划：确认库里没有未结束的 `revision_of` 任务后，删除 canvas 的旧替换路径（`replace`）、task 的 `retire` 接口与 `revision_of` 列、canvas 的 `uploads.source_task_id`，另起 contract 迁移。

## 6. 拆分

| 子步 | 内容 |
|---|---|
| 5.11a 修改闭环 | §2 的整条链：发起修改（文字意见、可附文件、选发给谁）、修订任务、整体替换、删除成果（含工作流与中间产物）、旧卡片标记、桌面端覆盖规则；成果页「发给 AI 修改」「删除」 |
| 5.11b 批注与批准 | 图片、PDF 页、视频暂停帧上圈画和编号点，时间轴红点；批注存 canvas、默认隐藏；发送时附带标注截图；「已批准」记号 |
| 5.11c 参数面板 | 播放器和 3D 预览的观看控制；音视频、3D 的成品参数表单生成结构化修改意见 |

## 7. 风险与边界

- 修订素材和上一版成果共用对象。替换和删除时，canvas 先删除来源是这个任务的修订素材行，再删对象；修订任务已结束（或已删除）后才会发生，所以不会删掉正在用的素材。「同时只改一版」保证不会有两个修订任务共用同一批对象。
- 新版和上一版的文件路径完全一样时，直接沿用同步路径；新版多出或少了文件的，多出的照常起名，少了的随旧版删除。
- 「已删除」不等于供应商侧也删除：已经交给外部供应商的输入（如生图提示词、渲染暂存）按各自的保留策略处理，暂存对象已有清理。model-gateway 的工具结果文件（`tool-results/`）本步不清理，记为遗留项。
- 删除是不可恢复的，前端二次确认。2026-11-04 起还没结束的任务也能删：先按取消停掉正在跑的运行（含规划员），再删除；harness 等运行结束后再清理存档（见 ADR 0005 §2026-11-04 重复任务与删除）。正在被修改的上一版仍不能删。

## 8. 5.11a 实施记录（2026-10-31，Claude）

按 §1–§5 实现了修改闭环、整体替换和删除。和设计不同的地方：

- 修订素材的上限按 §3 修订后的规则（不超过 10 个逐个交，否则打成一个 ZIP），记录来源用 `source_task_id`。
- 修订说明超长时截掉上一版说明的后部，开头（用户最初的需求）保留。
- 交付消息上加了「改一版」按钮（和成果页的「发给 AI 修改」是同一个对话框）；交付文字里「告诉我怎么改」的提示改为指向这个按钮，因为直接在私聊里说会被当成新任务。
- canvas 的 `/internal/uploads/lookup` 增加 `partial`，供再改新版时筛掉已删除的修订素材。

**改动**：contracts（task、canvas、conversation、events、desktop）；task（迁移 `add_revision_of`、建修订任务的检查、`DELETE /v1/tasks/:id`、`POST /internal/tasks/:id/retire`、`task.task.deleted`）；canvas（迁移 `revision_sources`、修订素材接口、新版替换、删除消费者）；conversation（新增 `revision-service.ts`、`POST /v1/conversations/:id/revisions`、卡片标记消费者）；harness（删除消费者：停预览、删运行存档和记录）；desktop（新版覆盖规则）；web（新增 `RevisePanel.tsx`，成果页「发给 AI 修改」「删除」，交付消息「改一版」，被替换 / 删除的卡片）。共 50 个路径，其中新增 6 个：本 ADR、两个迁移、`revision-service.ts` 及其测试（修订与接需求是不同职责，接需求要问模型、修订不问）、`RevisePanel.tsx`（成果页和私聊共用）。没有新增服务、表或依赖。

**验证**：

- ESLint、Prettier、`pnpm check:engineering` 七项、全仓构建通过。

**还没做**：
- 真实模型下的一次修改验收（§6，约 $0.1–0.3），要先报预算、用户同意再测。

## 9. 5.11b 设计：批注与批准（2026-10-31，Claude 定，待用户确认）

**用户看到的。** 成果页点「标注」进入标注模式：

- 图片：直接在图上圈（拖出椭圆）、画（画笔）或点（编号点），每画完一处写一句意见。
- PDF 和有配套 PDF 的 PPT：标注模式下改用 pdf.js 一页一页地画出来（翻页），在页面上同样圈、画、点，批注记下第几页。不标注时仍用浏览器自带的 PDF 查看。
- 视频：暂停在某一帧上圈画，批注记下时间；播放器下面有一条时间轴，批注处显示红点，点红点跳到那一帧。
- 音频：时间轴上「在这里加批注」，只记时间。
- 文档、表格、网页、文字等：写意见时可以带一段原文（先在页面上选中文字点「用选中的文字」，或直接粘贴）。
- 每条批注有编号；画面上只显示编号，点编号才显示意见（原型：批注默认隐藏）。批注列表里可以删（橡皮）。最多 50 条。
- 「批准」：成果页上一个开关，画布卡片上显示「已批准」。它只是记号，不挡修改；发起修改时会告诉 AI 这些文件已被批准，除非修改意见提到，否则原样保留。新版是新的成果，不带批准。

**发给 AI 修改。** 对话框里列出这个任务全部成果上的批注（可以不带）。发送时：

- 每条批注变成一行文字：编号、哪个文件、位置（第几页 / 几分几秒 / 画面的哪一块）、意见、引用的原文。
- 有画面的批注（图片、PDF 页、视频帧），由浏览器把画面和圈画、编号合成一张 PNG，作为附件随修改一起上传（按画面合并，最多 8 张，和用户自己附的文件合计不超过 10 个），文字里注明见哪张截图。
- 截图在浏览器里合成，因为画面只有浏览器里有（PDF 页由 pdf.js 画出，视频帧从同源视频取），不需要服务端再渲染。

**契约。**
- canvas：`Annotation {id, number, note, page|null, time|null, quote|null, shape|null}`，`shape` 为 `pin{x,y}`、`ellipse{x,y,w,h}`、`pen{points}`，坐标是相对画面的 0–1；`ArtifactBody` 增加 `annotations`、`approvedAt`（旧响应缺省为空）。`PUT /v1/artifacts/:id/annotations` 整份替换；`POST`、`DELETE /v1/artifacts/:id/approval`。修订素材结果的每个文件增加 `approved`。
- conversation：`RevisionBody` 增加 `annotations: [{file, number, where, note, quote?, snapshot?}]`（最多 100 条）；有批注时修改意见可以为空。修订说明增加「### 批注」和「### 已批准的文件」两节；有来源的要求原话里带上批注。

**数据库。** canvas `artifacts` 增加 `annotations jsonb not null default '[]'` 和 `approved_at timestamptz`。phase: expand，只新增带默认值或可空的列。批注随成果删除；新版替换旧版时旧批注一起消失（旧版本不保留）。

**依赖。** web 新增 `pdfjs-dist@6.4.299`（精确版本，2026-10-03 发布）。只在标注模式打开 PDF 时按需加载，worker 随应用打包、不走 CDN；6.x 本身已不用 eval，另关掉 XFA 表单渲染，PDF 里的脚本不执行。

**不做。** 文档、网页正文上直接画框（预览在隔离的 iframe 里，位置不可靠，用引用原文代替）；3D 模型上的空间批注（3D 的视角、材质在 5.11c 参数面板）；多人协作批注。

## 10. 5.11b 实施记录（2026-10-31，Claude）

按 §9 实现了批注与批准。和设计不同或补充的地方：

- 批注列表里点一条，会翻到那一页、跳到那一刻，并把那条批注滚到画面中间（浏览器实测时发现只翻页不滚动，看不到圈）。
- 窄屏（小于 1024px）时批注栏放到预览下面，工具条可换行（浏览器实测时侧栏挤压了画面）。
- 画面上的编号读作「第 N 条批注」，工具条上的列表开关读作「批注列表（N 条）」，避免重名；「批准」按钮不加提示文字，以免读屏时名字被提示文字盖掉。
- 修改文字里的批注按用户看到的顺序（文件、编号）排列，不再按文件名重新排序。
- pdf.js 6.x 已不用 eval，没有 `isEvalSupported` 这个选项；只关掉 XFA 表单渲染。

**改动**：contracts（canvas 的批注、批准、修订文件的 `approved`；conversation 的 `RevisionNote`、修改意见可为空）；canvas（迁移 `annotations_approval`、`PUT /v1/artifacts/:id/annotations`、`POST/DELETE /v1/artifacts/:id/approval`）；conversation（`revisionText`：批注并进任务单、说明和私聊消息；说明里列出已批准的文件）；web（新增 `annotations.ts`、`pdf.ts`、`AnnotationLayer.tsx`、`AnnotatedPreview.tsx`、`ArtifactReview.tsx`、`snapshots.ts`，成果页「标注」「批准」，修改对话框带批注和标注截图，画布卡片角标）；desktop（替换旧版时改名覆盖遇到 Windows 短暂占用会重试）。新增依赖 `pdfjs-dist@6.4.299`（精确版本），按需加载，构建后是单独的分块和 worker 文件，不进主包。没有新增服务或表。

**验证**：
- 全仓类型检查和测试（turbo 27 项）、ESLint、Prettier、全仓构建、`pnpm check:engineering` 七项通过；本步新增 10 项测试（canvas 2、conversation 3、web 5）。
- 迁移在真实 PostgreSQL 上执行。
- 在浏览器里（内置浏览器 + Vite 开发版 + 真实服务）实测：
  - 图片上圈、点、写意见、保存；点编号显示意见；删除；「批准」开关；画布卡片角标。
  - PDF 标注模式由 pdf.js 分页画出，第 1 页上圈画、翻页后批注随页隐藏，点列表跳回并滚到那条。
  - 修改对话框默认带上 3 条批注。
  - 截图合成：在页面里调用合成函数，PDF 页和图片各合成一张，圈和编号位置正确，共 545 毫秒。
  - 数据库里的批注和批准与页面一致。测试数据随后删除。没有调用模型，费用 $0。

**还没做**：
- 视频暂停帧标注、音频时间轴批注只有代码和组件逻辑，没在浏览器里用真实音视频走过。
- 带批注真正「发给 AI 修改」没有在真实链路上走（会产生模型费用），由接口测试覆盖。
- 5.11c 参数面板。

## 11. 真实链路验收（2026-10-31，Claude；用户预算 $5 以内，实际约 $0.41）

**音视频批注（浏览器 + 真实服务，不调用模型）**：12 秒视频停在 0:05 圈出画面右上的标识，批注记为「0:05 画面右上」，时间轴 5/12 处出现红点；跳到 0:10 时这条批注隐藏，点红点跳回 0:05 并暂停；视频帧标注截图取到第 5 秒的画面，圈和编号位置正确。20 秒旁白停在 0:03「在 0:03 加批注」，红点跳转正常。数据库里两条批注的时间和形状与页面一致。顺手把音频的空列表提示改成和按钮一致的说法。

**带批注修改的全链路（真实模型）**：
1. 私聊 DeepSeek 发任务「小木屋民宿宣传图」→ 问题卡选默认 → 任务单确认 → 交付 1920×1080 PNG（$0.049，约 4 分钟）。
2. 成果页标两处：圈天空「加一轮满月」，在门前雪地点一下「加一串通向门口的脚印」；「发给 AI 修改」只带批注、不写意见。私聊里出现两行批注和合成的标注截图（2.7 MB），修订任务的素材是「上一版-…png」（沿用成果对象）和标注截图，任务单最后一条要求的来源是 `revision`。
3. 第一次修订：规划员把说明里的「其余与上一版保持一致」理解成像素不变，要求用 Pillow 抠图合成、禁止参考图改图；节点反复分析像素，30 分钟超时后自动重做。手动取消（$0.143）。上一版成果和批注都保留，可以再次修改，验证了「没做成不替换」和取消后解除「同时只改一版」。
4. **修复**：修订说明加一条——「保持一致」指内容、构图、主体和风格不变，不要求像素相同；生成的画面优先用支持参考图的工具在上一版上改（把上一版和标注截图作为参考图）。加了对应测试。
5. 第二次修订：规划员改用 `image.generate --ref 上一版,标注截图`，限定最多重画 3 次；节点读懂了标注截图的位置。识图被上游限流，节点反复重试自查；用「停止 → 补一句要求 → 继续」让它直接交付（接着原会话，产出保留），再整体运行让下游验收继续。新版里满月出现在圈出的天空，门前多了一串脚印，其余画面一致（$0.213）。
6. 整体替换：新成果沿用原同步路径并记下被替换文件的摘要；上一版成果、上一版任务都返回 404；私聊里上一版的任务卡和交付卡显示「这一版已被修改后的新版替换，旧版本不保留」；新版不带旧批注，交付卡上可以「改一版」。

**发现并修复：识图没有限流备用**。`image.inspect` 只在「地区用不了」时换模型，默认列表里第二个（gemini）在开发机网络被地区挡掉，所以 `qwen/qwen3-vl-8b-instruct` 在 OpenRouter 共享额度上被限流（429）时没有可换的。两次交付的整体验收都因此写「证据不足」，节点也读不了标注截图。改为：上游返回限流时也换下一个（上游拒绝时冻结已退回，不会重复收费；指定了模型时不换）；默认列表加入 `qwen/qwen3-vl-30b-a3b-instruct`（比 8b 便宜）和 `z-ai/glm-4.6v`（另一家，分摊限流）。实测连续 4 次调用中第 3 次 qwen-8b 返回 429，自动换模型后正常返回，4 次合计不到 $0.0003。

**还没做**：修订说明里的「修改意见已落实：…」验收点直接带了全部批注文字，较长；整体验收在识图恢复后的效果没有再跑一次真实任务确认。

## 12. 5.11c 设计：参数面板（2026-11-01，Claude 定，待用户确认）

按 §2 的分法：只影响观看的在页面上直接调、不改成果；要改成品的在面板里填好，变成结构化的修改意见，走同一条修改路径。

**观看控制（不改成果）。** 3D 预览的工具条增加：视角（等轴、正面、侧面、俯视）、线框开关、灯光亮度（暗、标准、亮）、灯光色温（冷、中性、暖）。这些都发给隔离 iframe 里的查看器，只改当前画面；聊天里的预览和成果页都能用。低负载结构预览（SVG）没有材质和灯光，只给视角。音视频的音量、倍速用播放器自带的控件。

**成品参数（走修改）。** 成果页工具条上多一个「参数」，打开侧栏表单，每项默认「不变」：

- 视频：字幕字号（小、中、大）、字幕位置（底部、中间、顶部）、配音音量和背景音乐音量（-12 到 +6 dB）、亮度（-30% 到 +30%）、色温（冷、中性、暖）。
- 音频：语速（0.8 到 1.25 倍）、音量（-12 到 +6 dB）、语气（平稳、热情、温柔、严肃）、背景音乐（保留、调低、去掉）、导出格式（MP3、WAV）。
- 3D：主体材质（木纹、金属、哑光塑料、玻璃、布料，或自己写）、主体颜色（取色器）、地面材质（自己写）、灯光色温（冷、中性、暖）、面数（更少、不变、更多）、导出格式（GLB、OBJ、FBX）。
- 图片：输出尺寸（宽 × 高，像素）、导出格式（PNG、JPG、WebP）。

能在浏览器里近似预览的，改了就立刻看到：视频亮度和色温用 CSS 滤镜套在播放器上，音量（只能调低）用播放器音量，音频语速用倍速（保持音调）。表单上写明「预览是近似效果，做出新版才是真的」；字幕、分轨音量这类预览不了的只记下来。

填好后点「按这些参数改一版」，打开「发给 AI 修改」对话框，参数作为单独一组带上，可以再写意见、带批注。

**契约。** conversation 的 `RevisionBody` 增加 `parameters: [{file, name, value}]`（最多 40 项）；意见、批注、参数至少有一样。修改文字里加一节「参数：」，每项一行「「文件」名称：新值」；验收点按有什么写成短句（如「修改意见和 2 项参数都已落实」）。参数不存库：面板里的值只在这一页有效，发出去后就在修改意见和任务单里。

**不做。** 分轨重做（拆画面、配音、配乐、字幕分别让 AI 重做；现在整条修改已能覆盖，单轨重做以后按需要再加）；在页面里直接改成品文件（例如用浏览器重新编码视频）；3D 的批注与测量。

## 13. 5.11c 实施记录与 5.11 收尾（2026-11-01，Claude）

## 14. 工具中间文件随任务删除（2026-11-02）

此前 §7/§13 的 `tool-results/` 遗留已补齐。model-gateway 现在持久消费既有 `task.task.deleted`（包含新版替换旧版），先持久记录任务删除状态，再复用工具作业租约回收文件；定时巡检重试删除失败、在途写入和后续终态的清理。新消费者会重放仍保留在 TASK stream 中的历史删除事件；已经不在事件保留范围内的历史任务不会凭猜测删除。

作业写对象前记录数字文件 ID，任务删除与供应商完成竞争时继续核对费用但停止归档。旧版未保存清单的部分写入按既有数字键范围 0–31 回收（历史工具最多 11 个结果），新输出也限制在 32 个文件内。结果到期复用相同的租约清理，不保留两套删除逻辑。终态后清除结果及含原始输入的回执；调用/费用/供应商句柄保留审计。未知费用继续标为未知，不删除账单或把取消当免费。

新增 `tool_task_deletions` 仅记录 taskId/删除时间：既有 `tool_run_controls` 按 runId 管取消，无法表示「任务删除先于第一个作业」；单靠现有 job 行也无法挡住迟到插入，因此不能安全地塞入旧表或用对象扫描代替。删除与准入持有同一任务事务锁。迁移为 Expand、有 down 和 contract-plan；没有被替换的旧结构或双写，无需后续 Contract 删除旧列。回滚前须停止消费者并排空作业，不能在旧版本上继续接收新删除事件。

验证：网关单测 95 项通过；另显式启用真实数据库/对象存储测试 7 项通过，包括并发插入/删除、先删后插、迁移 down/up、对象删除与审计保留。真实 NATS 事件到网关到对象存储的集成探针通过。对象测试两轮及事件探针各写入并删除 128 KiB，合计逻辑回收 384 KiB，不将它表述为宿主磁盘实测释放量。隔离测试 schema、对象和合成审计行已回收；本轮不调用付费模型或供应商生成任务。

新迁移已在本地 model-gateway 应用，持久删除消费者已启动并核对实际事件链。收尾关闭本轮网关进程、移除本轮 7 个中间件容器与网络；不删除持久卷或用户已有文件。定向本地临时清理 0 项、磁盘释放 0 B，无新增镜像标签或悬空镜像。工程门禁通过，重复率 0.58%。

本轮实现改动集中于 model-gateway 的启动接线、repo/schema、tool-service 和两份既有测试，新增一份 SQL 迁移；无新服务、依赖或平行清理脚本。第六阶段设计另见 ADR 0014，不在本轮实现群聊或放宽凭据规则。

## 15. 删除是真删除（2026-11-05，用户要求）

用户原话：「如果用户在我们的系统删除了这个任务/成果/聊天/任何能删除的东西，我希望它是真正的删除（数据库，缓存，Oasis 的存储）……系统不需要回溯机制，我不希望用户在用我们的产品会导致硬盘空间越来越大。」用户自己下载到电脑上的文件不管。

| 用户删除 | 真删除的内容 |
|---|---|
| 任务（画布卡片垃圾桶图标） | task 库的任务、节点、消息；canvas 的成果记录、对象、批注截图、旧修订素材；harness 的运行记录、存档、工作区、检查报告、预览会话记录（结束的直接删，运行中的先停、结算再删）；model-gateway 的工具中间文件（§14）；**聊天里这个任务的卡片、交付消息、提醒整条删除**（原来只标「已删除」） |
| 聊天消息 | 消息和 AI 的回复；**随消息发的附件在 canvas 里删除记录和对象**（先删文件再删消息，删文件失败整个删除失败、可重试） |
| 没用上的上传 | 添加了又移除、没发出去的文件：上传被消息、批注用上时记「认领」时间（`uploads.claimed_at`），从没被认领的超过 24 小时由 canvas 清扫删除对象和记录 |
| 事件 | 发件箱里已投递的行留一天后删除；NATS stream 设 `max_age` 7 天，过期由 JetStream 删除 |

保留的：billing 账本和 model-gateway 的调用/费用记录（只有金额、模型、ID，没有内容）——它们是钱的凭证，删掉会让余额对不上。Postgres 删除后的空间由 autovacuum 回收复用，SeaweedFS 删除对象后的空间由它自己的 vacuum 回收，磁盘不会因为删除后的残留持续增长。

本地旧数据：旧流程留下的 2 条「已删除」标记消息已直接删除；已有上传在迁移里全部视为已认领，不会被误删。

验证：canvas 41、conversation 51、harness 105、web 106 项单测通过（新增：附件随消息删除且发送时认领、未认领上传清扫与真删除、任务删除后预览记录不留、任务卡片整条删除）；typecheck、eslint、工程检查通过。
