# ADR 0011：5.9 3D 模型、场景与云端渲染

- 状态：设计草案，尚未实施或真实验收（2026-10-27）。
- 依据：工程方向 §2/§3、ADR 0003 §6/§10、ADR 0006 的能力与算力计费、ADR 0007 的画布与本地写入边界、ADR 0010 的媒体数据面，以及自主规划集中验证记录。
- 目标：AI 根据目标、素材和限制，自行选择建模、资产生成、组装、渲染和检查能力，交付可预览、可取得和可继续编辑的成果。补通用能力，不建立“3D 场景名称 → 固定工作流”的映射。
- 本次仅设计。旧集中修复批次按用户选择维持 $5，不追加真实调用；本阶段没有获得新的付费测试、云资源创建、镜像发布或账号操作授权。

## 1. 承接状态与阶段边界

5.9 是下一阶段；之后仍为 5.10 数字人、5.11 修改成果。5.7 的真实验收、外部网站/Android 等遗留独立跟踪。集中修复实现已到 `5707513`，免费检查通过，但最终版本原六例真实复测未完成；该状态继续保留，不作为 5.9 已通过的前提事实。5.9 不能宣称解决了旧案例仍有的虚假附件承诺。

现有代码核对：

| 已有基础 | 5.9 必须补的缺口 |
| --- | --- |
| 通用 intake、来源要求、规划、节点依赖、关卡及最终清单 | 3D 能力目录、素材参数和几何/工程证据；继续使用通用任务入口 |
| model-gateway 的 fal 适配、长任务租约、幂等、结果存储与流式取回 | 3D 模型生成、云渲染适配、上传大工程、供应商取消与费用核对 |
| harness 的 Docker 执行器、CPU 计量和文件检查 | Blender 环境、受信 3D helper、几何检查、云渲染请求桥接 |
| canvas 已按 glb/gltf/obj 等扩展名分类，已有媒体播放和正式文件存储 | 真实交互预览、预览衍生物与原成果关联、无 WebGL/超限时降级 |
| 桌面显式选择全局同步文件夹 | 保持默认不下载；本阶段不新增按任务授权的本机目录 |

产品目标覆盖文本或参考图建模、组合资产形成场景、已有模型布光出图、短转台动画等。首批工程支持的格式和渲染特性必须在能力目录明确，但它们不是业务任务白名单。新主题、新房间用途、新产品展示不应要求开发新流程。

精密 CAD、可制造尺寸、拓扑/绑定、可打印性、扫描精度不是普通“生成一个模型”默认包含的保证；用户提出时应形成明确要求，检查现有能力是否足够。摄影测量/视频重建、超大实景、任意第三方渲染器没有在本批承诺完成。不能把概念模型冒充工程设计或真实空间测量。

## 2. 用户得到什么，电脑承担什么

| 层次 | 执行位置与交付 |
| --- | --- |
| 理解与规划 | 服务端模型调用；用户只给业务目标、材料和限制 |
| 模型生成 | 优先供应商 API；规则几何、精确相对布局可由服务端隔离 Blender/代码生成 |
| 场景组装和离线渲染 | 服务端 CPU 用于轻量组装/验证；生产 GPU 渲染调用云资源，不要求用户安装 Blender 或拥有显卡 |
| 展示 | 浏览器/Electron 渲染轻量模型；弱设备、超限或 WebGL 不可用时展示服务器生成的多视角图或转台视频 |
| 保存 | 正式成果在现有服务端私有存储；默认预览。只有主动下载或已明确选择桌面同步文件夹才导出本地 |

“云端执行”不等于用户电脑完全没有影响：网络、浏览器内存、视频解码和交互帧率仍受终端条件影响。静态图/视频降级必须能展示内容，不能只剩一个要求下载的按钮；降级不自动发起新的付费 GPU 作业。

最终交付按需求包含：标准 GLB、可编辑 `.blend` 工程及其真实资源闭包、PNG/JPEG/必要的 MP4、来源/检查说明。GLB 是交换和预览载体，不承诺保留 Blender 所有节点、修改器或参数历史；生成网格也不冒充参数化源工程。若声称参数可改，应交付实际参数/构建脚本和可复建工程。其他格式只在真正导出并检验后列为支持。

模型、场景与渲染结果作为一组相互关联的成果呈现；用户从同一成果入口切换交互模型、成品图/视频和文件清单，不新建一级页面。实时预览与最终离线渲染的光照/材质可能不同，不能拿预览截图替代成品验收。批注、对话修改及成果替换继续属于 5.11。

## 3. 两条能力路线，AI 自行选择

**生成资产路线。** 拟通过既有 fal 适配新增 `3d.generate` 长任务，首个候选为 `fal-ai/trellis-2` 图生 3D。文本目标若适合该模型，由 AI 决定是否先调用已有生图能力；参考图来自用户时不能擅自换图。目录明确它是图生模型，不能把中间生图成本隐藏成直接文生 3D。首批仅对已验证选项开放，模型 ID、尺寸、面数/贴图参数与费用全部配置化。

截至设计核对日，官方 API 给出 `model_glb` 输出，模型页列 512/1024/1536 档为 $0.25/$0.30/$0.35 每次。它们是接口当前报价，不是本项目端到端预算，也不是多边形数或最终纹理尺寸；实施前再核对并冻结价格来源。[fal API](https://fal.ai/models/fal-ai/trellis-2/api)、[模型及价格页](https://fal.ai/models/fal-ai/trellis-2)。

**可控场景路线。** harness 新增 Blender 软件环境和 `oasis-3d` helper。AI 可在原有隔离 CPU 沙箱内写建模脚本、处理网格、编排对象/材质/相机/灯光，然后产出标准资源与场景说明。对布局、数量、相对尺寸等强约束应走可核对的几何构造，不能只靠图片外观判断。helper 提供 build/inspect/pack；生产渲染由 `3d.render` 异步工具承接。

GPU 侧只接受经过验证的几何资产及声明式场景参数，由镜像内固定入口构建和渲染；不接收任意 shell、任意 Python、任意镜像或外网地址。首版参数支持相机、变换、基础 PBR 材质/贴图、灯光、背景和限定关键帧；网格不局限于几个预置形状，复杂几何可由 AI 在原隔离沙箱生成再导入。

自带 `.blend` 先在受限 CPU 容器禁用自动脚本执行并检查/转换；仅能将已支持内容送往 GPU。驱动脚本、插件和不支持节点不能静默忽略或声称保真；若无法保留需求，则明确能力不足。本阶段不通过远程执行任意建模代码扩大权限。禁用 autoexec 只是措施之一，不能替代容器、网络和资源隔离。[Blender 命令行参数](https://docs.blender.org/manual/pt/latest/advanced/command_line/arguments.html)。

首批不把整个 dsh 会话搬到 GPU，也不为异步渲染伪造 stdio 型 `Executor`。Agent 继续由 harness 隔离执行；重计算作为可取消、可恢复的工具作业调用。ADR 0003 的 `cloud-gpu` 目标由这一资源作业路径实现；若以后确有完整 GPU Agent 会话需求，另行设计执行器，不在本批搭第二套工作流控制面。

## 4. 云 GPU 供应商及部署前决策

拟选 **Runpod Serverless 的自建 Blender worker** 作为首个适配，理由是可提交异步作业、查询/取消、配置执行上限，并支持自定义容器；不是因为现有系统已经集成。接口能满足需求时仍优先现成 API。供应商适配只留首个可替换实现，不同时开发多云调度或常驻 GPU 集群。[作业 API](https://docs.runpod.io/serverless/endpoints/send-requests)、[worker 部署](https://docs.runpod.io/serverless/workers/deploy)。

部署前必须通过一个短技术核验：目标区域可用性；锁定 Blender/CUDA/驱动兼容组合；指定 GPU 池及最高单价；无作业时缩至零；取消/超时后终止核对；可信镜像取用；进程隔离与网络边界；账单/worker 用量可追溯。未通过就保持 `3d.render.available=false`，不能用 CPU 渲染冒称云 GPU 已接入，也不能仅凭 API 返回成功算验证完成。

有一项现行规则冲突必须先报告：AGENTS.md B.10 要求镜像命名 `oasis/<组件>:<标签>`、Compose 本地构建且“绝不从镜像仓库拉取”；云 GPU 的 worker 必须取得远端可用镜像。建议由用户明确批准一个**仅限云 worker 的私有仓库发布/拉取规则**：保留 `oasis/` 组件路径和精确标签，云端绑定不可变摘要；本地 Compose 继续 `pull_policy: build`，绝不使用不归用户所有的 Docker Hub `oasis` 命名空间。未经确认不更改 AGENTS、检查脚本，不推送镜像或部署。私有仓库鉴权能力及命名路径也需用目标供应商实际验证。

工程方向“不提前引入云平台”的原则继续约束整体部署；这里仅按 ADR 0003 已列明的 5.9 云 GPU 目标设计一个外部计算依赖，不引入 Kubernetes、CI/CD、服务网格或全服务上云。若采用方式需要扩大为基础设施迁移，先报告并重新对齐。

新账号、充值/余额、云 worker、可远程访问的临时对象存储和私有镜像仓库均是部署前置条件。本设计不假定它们已经存在，不读取/展示密钥，也不要求用户此刻完成账户操作；实施到相关步骤时应说明具体资源、费用和缺失配置。

## 5. 服务职责和数据流

| 模块 | 职责 |
| --- | --- |
| agent / task | 展示真实可用能力和估价；AI 规划；校验要求、证据、依赖与交付选择器；任务取消向运行传递 |
| harness | 唯一 dsh 接入；CPU 建模和受信检查；CLI 将授权文件提交到网关并把结果放回 `out/`；停止时请求取消归属作业 |
| model-gateway | 供应商适配；受限文件暂存；持久提交意图、作业恢复/取消；冻结、结算、费用归属、临时结果保留与清理 |
| GPU worker | 固定 3D 转换/渲染入口、进度与设备/用量报告；无模型 Key、业务数据库凭据或对象存储长期凭据 |
| canvas / web / desktop | 保存正式成果与受信预览关联，鉴权交付；展示交互模型和降级媒体；用户授权后才本地写入 |

文件通过既有入口代理进入 model-gateway，不为沙箱开放云 GPU、对象存储或宿主机网络。网关生成随机对象键和只针对本作业输入/输出的短期传输凭证。GPU 不接触内部服务；结果先保存、核对摘要，再结算和提供给 harness；正式交付仍按 task 最终清单进入 canvas。

当前本地 SeaweedFS/localhost 不能被云 worker 直接读取。需要配置可从云端经 HTTPS 到达的私有临时存储，按对象签名读写；不开放本机端口、不搭匿名公网下载、不把内网 URL 发给供应商，也不把长期 S3 Key 放进请求。临时存储只负责交换，最终归档仍由现有服务拥有。待正式结果已核对或超期后删除临时副本，记录失败重试。存储地域、费用和供应商保留策略必须在实际启用前核对。

GPU 调度外壳可访问供应商队列和本作业传输对象；Blender 子进程使用独立受限工作目录、无秘密环境和无出站网络的执行隔离。是否支持所需隔离必须在目标 worker 实测；不能把业务代码的 URL 白名单冒称网络隔离。无法实现时，不启用接收不可信资产的渲染能力，先更换后端方案。每作业清理工作区，不复用用户文件、插件缓存或模型上下文。

## 6. 契约草案与原地复用

优先扩展现有 `ToolEntry`、`ToolCallBody`、`ToolResult`、`ToolJobBody` 和 `tool_jobs`；不新增任务服务、独立云 GPU 业务库或平行长任务恢复器。

1. `3d.generate` 参数包含图像输入、模型及已验证的质量选项；返回实际 GLB、来源和检查信息，费用记 `kind=tool`。
2. `3d.render` 参数包含所有权已验证的输入文件 ID/摘要、场景参数、输出类型、分辨率、帧范围、samples 和预算上限；GPU 型号/设备数量/价格由服务端 profile 决定，不能由客户端任意指定供应商 endpoint。
3. 大文件不走 JSON/base64。为已有工具作业补“准备 → 流式上传 → 幂等提交”路径：小 JSON 请求创建归属作业并冻结可接受上限；`PUT /run/v1/tools/jobs/:id/inputs/:fileId` 有界写入并核对大小/摘要；全部输入齐备后提交同一作业。初始 `phase=uploading`，过期未提交则释放冻结并清理。`oasis-tool` 封装该过程，AI 不操作存储签名地址。小图生成沿用现有受限输入，不强迫所有工具改为三步。
4. 复用 `GET /run/v1/tools/jobs/:id` 取状态和已有文件内容接口；补 `POST /run/v1/tools/jobs/:id/cancel` 与只供 harness 的“按 run 取消归属作业”内部接口。实际路由名称应在实施前与现有 routes 对齐冻结，不能绕开 run-key 所有权检查。
5. 返回可选进度阶段（上传、排队、渲染、归档、费用核对）和原始/预览/工程文件角色、摘要。拿不到真实帧进度就只显示阶段，不编百分比。`ToolEntry.available` 必须考虑账号配置、运行 profile 和关键部署核验，不是配了 Key 就一律可用。

云渲染调用记 `kind=compute`，沿用同一 meter 和结算事件；生成 API 记 `tool`。`tool_jobs` 只是作业生命周期，不意味着必须另收一次“工具费”；同一个 GPU 成本不得再调用旧 CPU compute 路径重复结算。真实存在的 CPU 组装/等待时长仍单独透明计量，实施时应控制长时间空等。

现有 compute 按 `cores × elapsedMs`，必须扩展为服务端资源 profile 报价/用量，保留旧 CPU 请求兼容。GPU 冻结保存 profile、价格快照、最高秒数和其他成本边界；结算使用可验证的账单/worker 用量，区分 provider 与 estimate，不能信任 agent 填的秒数。规划目录给参考价，实际提交按具体参数报价并检查 `max_cost_micro`；不得把单张参考价当作全动画价格。

优先用 `tool_jobs.call/result/cost` 的版本化 JSON 保存作业输入清单、取消意图、报价和用量证据，新增 phase 不扩大数据库 status 枚举；旧作业读取兼容，旧 `uncertain` 不重发。需补待取消作业的扫描/租约条件，不能只加字段而旧恢复器永远忽略。并发限制和总预算预留需跨实例原子控制，复用已有数据库事务/作业租约，不能只用内存 Map。

如实现证明确需可索引列或改变状态约束，先更新迁移设计，再做独立可回滚 Expand → Migrate → Contract；不得为维持“无迁移”承诺把查询和并发正确性藏进不可管理 JSON。本草案不新增表，也未授权生产迁移。

## 7. 费用、恢复与取消必须形成闭环

Runpod 官方说明计费覆盖 worker 启动、执行和空闲阶段，并有存储成本。因此不能直接用作业 `executionTime` 冒充全部账单。初始建议：最小常驻 worker 为 0，最大 worker 为 1，每 worker 单 GPU、单作业，限定一种已验价 GPU 池、短 idle timeout；执行时限和 TTL 配置化。其为成本控制方案，不是供应商零超额保证。[计费说明](https://docs.runpod.io/serverless/pricing)、[端点设置](https://docs.runpod.io/serverless/endpoints/endpoint-configurations)。

冻结要覆盖执行上限、启动与回收尾部、传输/暂存上界和风险缓冲。冷启动、平台空闲及共享基础设施的非作业成本需明确分摊规则；首批独占串行便于核对，不能把整个账号账单随意分摊给当前用户。无法追溯部分作为平台风险保留，用户实际扣款不得越过已批准上限。不能承诺分布式取消能把供应商账单精确截断在某一微美元。

状态保持：`uploading → submitting → queued/running → stored → completed`；取消走 `cancel_requested → 核实终态/费用 → settled`；提交、取消或用量无法确认进入 `uncertain` 并保留原预留。已失败/取消但实际发生的计算可有非零费用，费用未确认不能自动全额退回，更不能自动重发。生命周期状态与费用是否闭合分别记录。

- 提交前写入幂等意图与输入摘要；请求断开没拿到供应商 ID 时先核查，不自动创建第二次付费任务。供应商自身重试也要纳入用量与幂等输出核对，不能宣称端到端 exactly-once。
- 网关独立恢复作业，终端页面关闭不取消用户已确认任务；用户明确停止任务、运行超时或额度保护触发时，harness 请求取消所属 GPU 作业，网关继续核实到终态。run Key 撤销不能让后台取消和费用回收也失去权限。
- 供应商“已接受取消”不是确认停止；404/TTL 到期也不是已免费。核对作业、worker 与费用，必要时保持待对账。独立看门狗在恢复进程中检查超时、未确认取消与遗留 worker，针对明确所属资源止损，不能清空共享队列或杀其他用户资源。
- 结果须在供应商保留期内归档到本系统；官方异步状态结果只保留有限时间，不能依赖第三方结果 URL 长期作为正式交付。按摘要恢复下载，重复事件/结算不重复扣款。
- 冻结有效期、续期/核对时限和持久化顺序需配合，防止 hold 过期自动释放但 GPU 仍运行；无法续保时停止提交新工作并取消在途，保留平台风险记录。

5.9 免费工程验证不扣供应商费。真实验收的案例、单例上限、全批预留、启动/存储/取消风险须先冻结，再按已有项目约定另行取得预算授权。旧集中修复 $5 的余额不结转，本设计不请求立即充值或追加额度。

## 8. 3D 预览与检查

**预览载体。** 首版交互预览使用经过检查、资源自包含的 GLB，前端按需加载 Three.js 与 GLTFLoader，解码器随应用打包，禁止从 CDN 拉取。GLB 并不天然保证无外部 URI，必须检查 JSON、buffer、image 和扩展引用；仅有扩展名不能信任。[glTF 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)、[GLTFLoader](https://threejs.org/docs/pages/GLTFLoader)、[资源请求控制](https://threejs.org/docs/pages/LoadingManager.html)。

canvas 在已有文件预览接口增设受信 3D 描述：绑定原文件摘要、预览 GLB、poster/转台媒体、检查覆盖与限制。由服务端生成关联，不能因为 README 写一个 URL 就加载。复杂原模型可以派生轻量预览，保留原件，明确“预览已简化”；不能让简化文件替换正式高质量成果。预览衍生物归 canvas 管理或登记为明确角色，私聊/桌面最终清单和默认下载行为不能因此悄悄增加文件。

基础交互为旋转、缩放、平移、复位、适配画面和已有动画播放；可显示尺寸/单位但未知单位不能猜。按模型字节、面数、贴图解码后像素/内存、动画复杂度设服务端和客户端双重限制，真正的资源界限待免费夹具测量后冻结。关闭详情页或切换模型时中止请求、释放 GPU/对象 URL；列表只显示 poster，不能每张卡片都启动 WebGL。

浏览器仅从 gateway 的授权路径取受信文件，资源解析在隔离预览容器/受限 worker 及独立 iframe 中处理，使用严格 CSP 和受信 viewer，禁止任意模型嵌入脚本/任意 HTML。GLBLoader 的 URL 拦截只是纵深措施，另需网络/CSP 兜底；测试实际没有请求第三方纹理、插件或相对越界路径。该预览不是 5.7 通用应用执行会话，不启动 npm 项目或新的付费常驻环境。

**机器检查。** 复用 harness 文件检查和 gate 三态结果，新增格式结构、索引/数值合法性、非空几何、包围盒/单位、对象数量、资源闭包、贴图尺寸、限制与摘要。依赖 Khronos validator/Blender 时精确锁版本，进程隔离和超时；安装时才引依赖。模型可打开不等于好看；无孔洞、流形或可打印性只有用户提出且实际检查才可标通过。

**内容与视觉检查。** 从独立冻结文件渲染多视角/关键帧，检查目标对象、数量、布局、材质与需求一致性，必要时调用计费的视觉模型；不能仅信任创建节点自述。质量、不可见背面、尺寸未知、缺乏参考的部位如实标未检查。PNG 完整解码，MP4 完整解码及帧数/时长/关键帧检查；CPU 降级验图不能作为 GPU 使用证据。

**工程及交付检查。** 从正式清单或正式 ZIP 重新取得工程，移到新目录、禁自动脚本打开、确认对象可编辑且资源齐全，再重新渲染；核对声明附带的脚本/贴图/源工程均实际存在。不因单独交一个 GLB 就声称交了可复建工程。自动重做沿用原上限，仍失败则保留质量提醒；不能为凑通过无限尝试或人工补制作步骤。

## 10. 验收矩阵与完成定义

免费测试先覆盖：旧契约读写；文件越权/超限/外部 URI/路径穿越；超大贴图与畸形几何；脚本/插件执行拒绝；同输入并发提交；上传断连；提交无响应；完成后下载失败；归档后结算失败；取消竞争与终态丢失；重启接管；冻结将过期；供应商自动重试；不重复扣费；孤儿回收；默认不下载；WebGL 失败/页面关闭释放资源。无需为静态文案堆测试。

真实验收只给用户目标、素材和限制，不指定节点、模型、命令或建模步骤。候选为三组对照，具体原话及独立答案在调用前冻结：

| 对照 | 要观察的通用能力 |
| --- | --- |
| 同一参考物体：外观概念资产 / 改为有明确尺寸与结构关系的用途 | 是否选择合适生成或程序建模路径；尺寸能力不足能否识别；不强制必须调用生成 API |
| 同一虚构空间：仅要布局模型 / 增加固定相机、夜间布光与成品展示 | 是否保留原几何约束、增加渲染依赖，工程与成品一致，不能只给漂亮图片 |
| 同一已有模型：透明底静帧 / 改为固定时长转台视频及不同预算 | 是否复用素材，合理改变渲染参数/组装步骤；输出、费用及等待时间真实记录 |

至少一个真实付费样本需要有生成 API 证据，至少一个需要有云 GPU 实际设备、worker 生命周期和费用证据；它们可作为单独的工具探针验证，不能向自主案例强塞“必须调用某工具”来制造自主规划通过。GPU 探针与预算授权也独立计入阶段总预留。样本数量和画质范围必须与获批预算一致，不把预算不足造成的取消算质量通过。

完成需同时满足：通用接口与隔离/计费检查通过；无独显的终端能预览和取得成果；真实 GPU 使用与停止可证；正式工程搬移后重开并重渲染；说明与最终清单一致；取消/中断费用和残留资源核对；新样本无需人工改节点或补制作代码；免费与真实证据分别归档。未检查项、供应商不确定费用、旧集中复测未完成及 5.7 遗留分别列出，不用某个样本的成功覆盖它们。
