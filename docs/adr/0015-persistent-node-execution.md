# ADR 0015：节点作为持续子任务执行

状态：第 1–6 项及旧归档兼容已实现并完成本次验收（2026-11-03）；适用边界与验证范围见 §9。2026-11-08 起续跑只用持久工作目录，会话包（§8 的归档恢复）已删除，见 §16。

## 1. 问题与边界

真实任务 101958ec-9d79-4341-800d-4e340a298a46 暴露了能力元数据丢失、输出截断、节点只等一轮、内部代理控制关闭、估价被当成预算以及运行寿命被当成算力冻结期限的问题。原生 DSH 成功不能证明所有输入都可靠，但说明 Oasis 不能继续削弱底座后再靠重试补救。

本决定取代 ADR 0003/0004 中与下述执行策略冲突的默认值。原真实任务、历史账单和人工停止状态不修改、不重跑。账户余额、每次调用冻结结算、鉴权、资源调度及沙箱网络隔离保留。

## 2. 受影响模块与数据设计

- model-gateway：供应商模型能力目录；运行凭据续租；按窗口冻结、结算算力。
- harness：适配层复用精确版本的官方 JSON-RPC 传输；完整模型目录及推理配置；原生 goal、子代理及其会话树；长期运行的计费/凭据租约；失败仍保存可恢复状态。
- task：估价与显式预算分离；工作节点请求持续目标；失败重试恢复现有会话；移除方案节点/工具数量的任意上限及对应提示。
- conversation/canvas：移除修订任务的素材总数限额，沿用已有逐文件/ZIP 的素材交接方式；不再因为上一版素材加附件超过 20 个而拒绝修订。
- contracts、service-kit 的可选归档总量约束、配置示例、前端预算操作说明及既有测试随接口原地修改。

复用 tasks.budget_limit_micro 的 nullable 语义、node_runs.request/meta 和 runs 的现有归档。会话树归属随 run_events.data 保存，DSH 会话仍是内部目标/代理树的事实源，不增建第二套子工作流表。凭据续租仅更新已有 expires_at。不需要新表和数据库迁移。

## 3. 模型和底座

从供应商目录传入 context window、最大输出、输入模态与 reasoning 能力；缺失能力必须明确报错，不能静默退回 32768/text。节点 model 是启动模型，不是内部唯一可用模型。子代理可从计费网关实际可用目录选模型，所有调用仍归属同一 payer/task/node/run。

底座及协议精确锁定同一 DSH 版本。官方高层 SDK 拥有本地子进程，不适合直接接管 Docker attach；复用其公开的流式 JSON-RPC 协议实现，删除自写协议解析。适配层只负责产品与底座的边界，不复制 Agent Loop。

本次锁定 0.2.1-rc.5。以原生 openrouter provider 路由保留已知模型的厂商推理回放兼容性、档位和单次请求策略；物理最大输出容量不等于默认请求输出量，不能把前者一律覆盖到后者。供应商新增、原生目录尚未收录的型号才使用显式能力回退。默认使用该型号原生声明的最高思考档位，调用方明确指定的选择保持原样。模型目录经文件挂入沙箱，避免大目录超过单个环境变量的操作系统边界。目录或启动型号不可用时，在创建运行、冻结费用之前报告具体原因。

## 4. 生产执行与验收约束分开

新任务不再把 estimate × 3 转为预算。只有用户或验收调用显式提供的 budgetMicro 才是任务预算。并发是排队容量，不是任务失败条件。

运行不因固定 30 分钟到期销毁。凭据有效期、算力冻结周期是可以续期的租约，不是任务总寿命。续租/冻结失败须保存状态并暴露可处理原因，不能假报完成。显式验收超时/预算必须由验收调用携带，不能成为默认生产策略。

删除任务规模和工具数量的任意硬上限；保留类型、路径、环路、引用完整性等正确性校验。网络请求和文件解析的资源边界与任务总量不同，不能用删除它们来冒充完成率修复。

归档及输入总字节上限改为可选显式配置；删除 Blender 启动时强制压低分辨率/采样的补丁。批处理预算、单行预算、token 和超时仅由本次调用显式提供，逐行保存实际费用和不确定状态；截断的部分正文不能作为完成。并发、单文件解析和预览协议的资源边界继续保留。

## 5. 持续子任务与完成语义

工作节点由 DSH 原生持久 goal 驱动，同一会话内规划、分工、执行、自查和续跑；讨论发言仍是一轮消息，不强制变成长目标。恢复使用原会话和已有产物，不从头重复消耗。

原生子代理通知保留 parentSessionId/childSessionId；子会话结束不能把根会话标成完成。节点成功须根目标明确 complete 且根会话及托管后代收尾。blocked、paused、协议断开、max-tokens 均不能伪装成成功。原生驱动的有限轮次参数如不能表示无总上限，必须用公开生命周期接口续期而非伪造 Infinity 或自行再写调度循环，并验证续期不会重放任务。

原生 preset 启用 plan/workflow/jobs、创建/分叉/控制/列出子代理及跨模型选择。内部委派深度沿用 provider-managed 策略，不另设 Oasis 数字深度限额。SDK 根会话创建/恢复时挂载同一 preset；恢复已有会话不虚构历史模型选择授权。交互式审批/向用户提问插件不挂载到后台执行，避免已授权节点等待不存在的交互入口。

适配策略只续期原生 goal 的轮次授权和投影原生激活状态。续期放在 turn/end 后的微任务，避免中途修改 revision 使当前原生轮次授权失效。输出截断后由原生 resume 继续已有目标。SDK 的 idle 必须结合 goal phase/activation 判断，不能把中间空闲或子代理终态当成功。

删除外层 MAX_NODE_RETRIES/MAX_NODE_REWORKS/MAX_PLAN_ATTEMPTS。实际执行失败不再盲目从头重跑；节点关卡未通过则在同一归档会话继续修复，不再“一次返工后带警告当成功”。规划文件结构不合法时继续同一规划会话纠正；实际规划执行失败仍报告需要处理。计数保留为观测指标。手动重试优先恢复已有 out/ 与 DSH 会话归档；没有归档才重新开始。

第 1–3 项实施时，常规失败和优雅停服先保存归档再销毁沙箱，但尚未解决硬崩溃接管和完整工作目录恢复；当时 out/ 之外的依赖可能需要重建。第 4–6 项对这些缺口及最终验收 fail-open、环境准入的处理见 §9；不能据此宣称所有失败路径均已修复。

## 6. 验证与收尾

先验证模型目录、子代理事件归属、目标多轮、显式预算与无预算、凭据/算力跨窗口、失败归档和会话恢复；再做受控真实验收（单次不超过 US$5）。旧任务不进入验收。完整跑类型、测试、lint、工程门禁；只能以通过的证据声明完成。

临时下载的官方包源码、测试文件及本次临时 Docker 资源在收尾删除；不保留平行实现或备用补丁。镜像按 Oasis 命名，不清理他人/历史任务资源。

## 8. rc.2 归档恢复兼容（2026-11-03）

范围仅为旧归档在新运行时继续，受影响模块为 harness 的现有适配策略、原生回归和本 ADR；不改公共接口、数据库、调度或重启接管。测试使用隔离、断网的 rc.2 运行时和合成供应商生成两份最小归档（正常完成、输出截断），不读取或重跑用户真实任务。旧运行时与临时资源验证后清理。

rc.2 与 rc.5 实际都使用 Session 格式 V4。rc.5 SDK 的 `initialize` → `session/resume` 已通过原生 agentOptions 使用当前模型路由，同时保留原会话身份和历史；不应新增旧 provider 别名或自行改写日志。支持更早历史格式的转换也继续交给原生 JSONL backend 的静态迁移链。

复现的产品兼容缺口在权限衔接：旧 Oasis profile 禁用了子代理，不存在原生 preset 和 model-selection-policy。新策略只 mount preset，原生 DSH 会正确地保留“未授权选择子模型”的历史状态，导致旧任务恢复后缺失本次新运行允许的能力。修复在首次新请求前，对历史路由为 oasis、没有 preset、没有既存模型选择策略的旧会话，追加当前 Host 设置明确允许的原生 subagent/model-selection-policy 事件。已有策略不扩权，关闭当前授权时不授予；不伪造旧 seq、不修改原归档、不复制原生迁移或 Agent Loop。后续再次恢复复用已记录策略。

原生委派工具在 Agent 创建时捕获策略，而 SDK 适配策略在该通知内才绑定 preset。修复将旧会话的首次授权放到更早的 session/created 同步发布边界；绑定完成后发出原生 tools/change 通知，补上旧通知快照未覆盖的作用域安装。这个通知也修复已带 preset 的 rc.5 会话再次恢复时委派工具没有安装的问题。

二次恢复回归还复现了前一实现的记录错误：把 oasis/goal-status 用普通 append 写成未知且不可忽略的事件，原生读取器会正确拒绝它。现在改用公开 appendPluginRecord 写入 plugin:oasis/goal-status，携带原生 ignorable 标记，适配层只读取这个合法记录。2026-11-03 只读核对，库中此次升级后的存留会话归档数量为 0（前一验收任务已清理），没有现存错误记录需要回填；不增加绕过原生校验的通用日志改写器。

缺失、损坏、未来版本或原生不支持的归档必须明确拒绝，不能降级为新建空会话、丢失上下文或自动重做。恢复能力只涵盖旧系统实际保存的会话和 out/；从未归档的工作目录不能凭空找回，仍属于后续第 4 步。

验证：两份原生 rc.2 V4 夹具分别覆盖 completed 与 max-tokens。rc.5 恢复相同身份、原消息与工具结果、旧文件、最高思考档位、跨模型子代理及孙代理，完成新的持续目标；将新日志再恢复一次，新增目录型号不扩大既有授权，授权记录仍只有一条，旧日志字节前缀不变。缺失/损坏/未来版本均在模型调用前被拒绝。最终基础与 3D 镜像都在无源码覆盖、断网条件下运行上述 6 项验证，费用 US$0。

全仓测试通过（502 项，未启用的 PostgreSQL/S3 等专项保持明确跳过），15 个工作区类型检查、lint 及全部工程门禁通过；重复率 0.54%。最终镜像的策略文件 SHA-256 均为 331afc4e4aaef2b0843e598a479e5a21fd04c0b1ec7fc8822cfdeee010e2c3d8，与源码一致。变更 8 个文件，其中新增的 3 个仅为两份合成旧日志及其来源说明；没有新依赖、新表或数据库迁移。原真实任务与历史账单未改动，第 4–6 步未启动。

构建说明：全量镜像构建因 Debian 软件源失败而取消。本次仅改变镜像里的适配策略文件，因此复用现有精确 rc.5 镜像层，原地替换同一路径的文件；原生版本、profile 和软件栈不变。两张最终镜像内文件摘要须与源码一致。临时增量构建描述与 rc.2 夹具运行时不进入产品代码；今后全量构建仍使用现有 Dockerfile。

## 9. 第 4–6 项实施（2026-11-03）

4. **稳定执行与接管**：harness 的开发启动不再使用文件监视重启。每个原生会话的工作目录和 sessions 分别使用带 Oasis 归属标签的 Docker named volume；保留脚本、项目依赖、权限和链接，不通过普通交付 tar 复制工作目录。新运行的完整启动请求与运行行在同一事务内存入既有 run_events 的内部准入事件（不含运行密钥，对外隐藏请求正文），用于恢复排队和在途运行，不增加跨数据库/对象存储写入间隙。重启先停止旧沙箱、撤销旧凭据，按 Docker 实际停止时间结算未完成算力窗口，再以原 runId/sessionId 和原目录恢复；不发布中间失败、不新建节点重试。优雅关闭同样挂起而非失败。暂时不可达的恢复依赖保留待接管状态并周期检查；等待期间的用户停止/取消意图持久化。新登记到内存挂接之间使用同一会话锁，防止定时接管重复派发。已完成原生目标接管时不重建目标、不再次调用模型。恢复缺少原目录/请求时明确失败，不虚构状态。任务删除级联删除请求记录、本任务独占的持久卷及原有归档。

5. **环境准入**：执行器按实际镜像摘要探测软件版本与能力，规划与执行复用同一份结果；节点声明所需本地能力，harness 在登记和冻结之前复核。模型也必须在实际执行能力目录中。浏览器交互检查使用已有隔离预览和可用的 website.test 通路；不能把包可安装等同于 Chromium 和系统库已具备，不扩大沙箱网络通路。规划及工作节点收到完整确认任务单；应用和浏览器断言的 JSON Schema 从已有契约生成到运行目录，不复制第二套协议。清单校验返回实际错误字段和路径，避免泛化报错造成反复猜测。新 AI 规划的强制检查须绑定已确认的 requirement id 或 criteria:N/style:N 数组索引，由代码还原来源原文；实施建议写入 goal，不成为额外验收门槛。保留历史方案及用户直接提交方案的原有读取方式，不回写或伪造任务单来源。

6. **交付完成语义与验收**（2026-11-05 按 ADR 0004 §2 改为只提醒、不拦截）：最终缺文件或明确未满足时，在已有交付节点原会话修复 1 次，并按依赖顺序更新下游后重新验收；仍未满足就带着未满足项交付。检查未知或服务异常记成“没检查到”的提醒照样交付，不停下等用户，也不误当品质失败反复重做。最终检查同时覆盖已确认的 criteria、style 与 requirements。受信几何/音视频报告的范围说明单独保存，范围外要求仍须独立证据，不能把说明一概当失败。平台浏览器实际报告和输入摘要同时进入节点与最终语义验收；最终验收复用已绑定该运行的报告，不重复启动浏览器。专用 Jev 明确地区不可用时，只对兼容的 noul 问题回退到配置的可用模型，仍经现有 ChatService 冻结/结算，保留实际型号与归属；拒绝截断或无效结果，其余异常不伪造通过。

边界：沿用单 harness 实例，不宣称多实例分布式接管；持久卷丢失不能补出未归档文件。旧系统仅保存 out/ 与原生会话的运行仍走 §8 的归档恢复。复用 task/node JSON、run_events、已有检查报告，无新表、迁移或生产依赖；没有额外 Agent Loop 或平行调度系统。付费验收预算只属于验收调用，原真实任务与历史账单不改、不重跑。

### 9.2 变更与清理报告

本轮修改 57 个文件：38 个运行实现/契约/配置、17 个测试/夹具和 2 份文档。跨模块变更用于把相同运行身份、目录、计量、事件和验收证据接通。仅新增 2 个测试文件：真实控制进程恢复测试与它使用的工作进程；运行实现均在已有模块原地修改。无新生产文件、生产依赖、新表或数据库迁移，Expand/Migrate/Contract 不适用。移除旧的“重启即失败”、检查异常放行及流中断被改写成普通模型错误的路径，没有并存第二套执行器或补丁版本。

收尾发现临时验收程序无正文 DELETE 仍发送 JSON Content-Type，被服务拒绝，旧轮次仅清掉隔离数据库和进程，未实际触发任务删除。该错误属于临时夹具，已修正并另做零费用真实 API → outbox → TaskDeleted 验证：运行记录、2 个持久卷、3 个对象全部删除，模型调用 0。早期夹具的参数类型和对象桶配置错误结果作废，不计为产品通过证据。随后按卷标签、会话归档路径、测试时间及测试 taskId 交叉确认归属，排除原库 270 条运行，清掉本轮遗留的 36 个持久卷、58 个 harness 归档、8 个 canvas 成果与夹具错误桶中的 3 个对象；卷文件逻辑大小 28613571 字节，对象合计 4183274 字节。仅删除本轮 8 封本地测试验证邮件。没有做全局 Docker prune，没有新增生产镜像标签；本轮中间镜像已移除，原有最终基础/3D 镜像保留。

最终核查：8 个服务数据库均无验收 schema 残留；本轮沙箱、探测、临时消息队列容器及持久卷残留均为 0。原库运行仍为 270 条，原真实任务仍为 cancelled，未触发恢复。7 个共享中间件恢复到本轮开始前的停止状态，保留其原数据。运行 `pnpm cleanup --scope=.tmp/execution-recovery` 删除本轮验证脚本、日志和报告，释放临时文件 203.0 KB；上述卷与对象大小为逻辑数据量，不冒充对象存储已物理回收的空间。收尾悬空镜像为 0；已有构建目录和其他任务临时目录保留。

## 10. 长上下文入口及原生附件持久化修复（2026-11-04）

### 10.1 原因与设计

失败来自 Oasis 的 HTTP 接入层：沙箱入口允许 50 MiB，但 model-gateway 聊天路由沿用 Fastify 的 1 MiB 默认值，解析时先返回 413，尚未进入鉴权后的模型计量。模型 token 容量、HTTP JSON 字节及图片 base64 大小是不同边界。

对精确 rc.5 镜像的 profile 展开和原生日志复核证明，自动历史压缩已经启用：继承 `token-meter`、`compaction-basic`（auto 默认 true）、工具结果裁剪及图片卸载。原根会话记录 3 次 compaction/start、1 次成功摘要、2 次摘要失败；两次摘要失败同为本地 413，对应 requestId `3c7be818-9927-45ad-ba1b-f96186fafcdc`、`07d90e33-6170-470e-9808-1435b8c3f2c6`。贴图库子会话已有 6 次成功摘要。随后根会话普通续跑请求也两次被拒绝。不能将此归因为“没有利用 DSH 压缩”；入口甚至挡住了原生压缩请求本身。

模型网关新增外置 `MODEL_REQUEST_MAX_BYTES`，默认且最高为 52428800 字节，与现有入口代理一致；仅四条 internal/run 的聊天及决策路由使用此容量，其他接口保留原边界。仍由原有凭据、冻结、结算和网络隔离控制访问，不截掉历史、不另写压缩器，也不放宽为无限请求体。

真实恢复进一步暴露附件生命周期缺口：原生 attachment-local 默认写在容器临时层 `/home/node/.dsh/attachments/v1`，而执行器只持久化/归档工作目录和 sessions。因此会话里仍有图片引用，跨容器后对象已丢失。复用原生公开配置，将 attachment-local 的 dshHome 指向 `/home/node/.dsh/sessions`；附件对象及请求图片缓存随现有 sessions 卷和 tar 一起保存，日志位置不变。不增建附件服务、表或卷，不复制底座实现。

## 16. 续跑只留持久工作目录（2026-11-08，重构阶段 1）

§8、§9 留下了两条续跑路径：持久工作目录（Docker named volume），和对象存储里的会话包（每次运行结束上传 `runs/<id>/session.tar`，工作目录不在时放回 dsh 的 sessions/）。生产里所有运行都有持久工作目录，会话包只在卷丢了的时候才用得上，却每次都上传；两条路径并存也是「重启后丢进度」一类问题反复出现的原因之一。

- **只留持久工作目录**：harness 不再上传会话包，`runs.session_key` 列删除（contract 迁移 `20261108150000_contract_session_key.sql`）；对象存储只存产出快照。执行器的 `workspaceExists`、`purgeWorkspace` 改成必须实现，每次运行都挂这个会话的持久卷；「不持久」的运行方式（`persistent` 标记）删除。`resumable` 只看持久卷还在不在。
- **卷不在了**：harness 拒绝接着原会话（409 `workspace_unavailable`，契约常量 `WORKSPACE_UNAVAILABLE`），不拿对象存储里的产出冒充恢复。task 收到后把这次运行记成失败（写明原因），这一步改成重新开一个会话做：给节点的完整说明，节点上一次交出的产出放进 `in/_previous/`（ADR 0022 的「重新做」），关卡发现的问题或用户的修改意见附在后面；讨论发言带上完整题目和之前几轮的发言。不算节点失败，不占重做次数。节点从没交过产出（例如第一次运行中途停下）就从头做。
- 已开始的运行在重启接管时卷不在了，仍按 §9 明确失败（不能从空目录恢复）。
- 验证：harness、task 单元测试覆盖接着原会话、卷不在时拒绝、重新做带上上一版产出、讨论发言重新开会话；回归场景 `workspace`（第一版交付后删掉卷，再要求接着原会话改）通过。
