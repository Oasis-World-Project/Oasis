## 导入项目：没做的（2026-11-19）

做了的见《工具与沙箱》§1（放行的站、缓存卷、`oasis-setup.sh`、数据库程序、技能 `projects`）。

- 私有仓库：没有给 AI 凭据的办法，只能让用户打成压缩包发来。
- 改动不推回用户的仓库：AI 交补丁或压缩包，用户自己合。
- 沙箱里不能跑 Docker / docker compose，不能装系统软件包（没有 root）。
- 沙箱是 2 核 2 GB：大项目的全量构建可能跑不动，真遇到了再调 `SANDBOX_CPUS`、`SANDBOX_MEMORY_MB`。
- 缓存卷不随账号删除：产品里现在没有「删账号」；做的时候要把 `oasis-cache-<用户>` 这个卷一起删。
- 缓存卷是一个人的所有沙箱共用的：同时开着的两个沙箱会同时写同一份缓存（各包管理器自己的缓存都允许这样用，没有另外加锁）。

## 桌面版安装包：没做的（2026-11-19）

做了的见《架构》§6（`pnpm desktop:dist`，只有 Windows）。

- 没有应用图标：安装包和窗口用的是 Electron 默认图标，等用户给图标文件。
- 没有签名：安装时 Windows 提示「未知发布者」，SmartScreen 可能拦一下；要签名得买代码签名证书。

- 只有 Windows x64；macOS、Linux 没做。
- 安装包约 200 MB、装好约 900 MB、两万五千个文件，在开发机上装一次要 3 分半（已经去掉了类型声明、源码、源码映射这些运行时用不到的文件，去之前是 300 MB、六万多个文件、7 分半）。还想快，得动 dsh 自带的依赖（它带了 60 份 zod、一个 180 MB 的文档转换程序）。
- 没有地方下载：安装包怎么发给用户（放到网站上还是别处）部署时定。

## 线上：没做的（2026-11-19 第一次部署后）

做了的见《部署》《云服务器》。现在只是用户自己试用。

- 云端沙箱租 E2B 的执行器做好了（2026-11-26，`CLOUD_EXECUTOR=e2b`，见《部署》《工具与沙箱》），线上还没切：要用户在服务器上填 Key。切之前服务器同时只跑一个沙箱（`MAX_CONCURRENT_RUNS=1`）。没做的：E2B 沙箱 24 小时后销毁、工作目录存进自己的库再重建；Hobby 档一个沙箱连续运行最长 1 小时，更长的一轮会在到点时被暂停。
- 没有备份：数据库、文件、会话的工作目录都只在这台机器的数据卷里。
- 没有监控和探活：容器挂了会自动重启，但没人知道；日志只在 Docker 里（每个容器留 5 个 20 MB 的文件）。
- 更新时会断一下：`up` 直接把变了的容器换掉，没有「先起新的、健康了再停旧的」；也没有自动换回上一版。
- 每次更新所有服务镜像都要重新构建（约 15 分钟）：镜像构建时拷的是整个仓库，改一个文件全部失效。
- gateway 看到的来源地址都是入口容器的：按来源地址做的限制（如果以后要做）得先让入口把真实地址带过来。
- 安装包放在服务器上，由入口从官网页的「下载 Windows 版」发出去（见《部署》「发安装包」）。从开发机往服务器传很慢（2026-11-20 实测 20–60 KB/s，214 MB 要一个多小时）；以后可以让 CI 在 GitHub 上打包、发到 Releases，服务器自己去下。
