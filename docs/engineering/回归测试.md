# 回归测试、对话追踪与验收模式

- 日期：2026-11-08（阶段 0「安全网」）；2026-11-14 第 2 阶段改成私聊里的一轮。
- 目的：以前没有一条自动化测试从「用户说一句话」跑到「画布里打开成果」，单元测试用假实现全过，真链路第一次跑就是用户手动验收。现在本机一条命令就能把整条链路跑一遍；以后每次验收失败，先写成回归用例再修。
- 规矩：每个阶段（见执行方案）回归全绿才进入下一阶段；改了 harness、model-gateway、inspector、canvas、conversation 的行为，提交前跑一次 `pnpm e2e`。

## 命令

| 命令 | 做什么 | 花钱 |
|---|---|---|
| `pnpm e2e` | 跑全部回归场景（假模型、真容器、真画布） | 不花 |
| `pnpm e2e web revise` | 只跑这几个场景 | 不花 |
| `pnpm e2e --keep` | 跑完不停服务、不删私聊，方便用 `pnpm trace` 和日志排查；Ctrl+C 结束 | 不花 |
| `pnpm e2e --real` | 真模型、真工具跑 5 个场景，每个场景花费上限 $1（小游戏 `real-game` 放宽到 $3），超了当场停下这一轮、判失败 | 改造前（11-08）实测：网页约 $0.08、修改约 $0.07、生图约 $0.28；11-13 小游戏三次：$1.66、$3.02、$0.44，见下面的对比 |
| `pnpm trace <对话 ID>` | 一个私聊里每一轮的运行、模型和工具调用、算力、费用来源、画布成果，并标出异常 | 不花 |
| `pnpm accept` | 验收模式：服务从当前代码启动后不再跟着代码改动重启，Web 用构建好的版本 | 按实际使用 |

`pnpm e2e` 和 `pnpm accept` 都要先停掉 `pnpm dev`（端口冲突时会直接说）。需要 Docker、`pnpm env:init` 生成的 `.env`，以及沙箱和检查浏览器镜像（`pnpm sandbox:build`、`pnpm browser:build`）。

## 回归里哪些是真的

- 真的：9 个服务（直接用 node 跑 `src/main.ts`，和 `pnpm dev` 同一份代码和 `.env`）、PostgreSQL / NATS / SeaweedFS / Mailpit / Valkey、沙箱容器和 dsh、浏览器检查容器、画布、Web 前端（Vite 开发服务器）、桌面外壳（Electron，隐藏窗口）。
- 假的：模型供应商。`scripts/e2e/fake-provider.mjs` 是一个 OpenRouter 兼容的本地服务，按场景脚本回答；生图、生视频交固定的测试图片和测试视频（JPEG 和视频由沙箱镜像里的 ffmpeg 现做一次，缓存在 `.tmp/e2e/fixtures/`）。生图有两个假型号：`fake/image-1` 交 PNG；`fake/image-jpeg` 像 Seedream 一样要 PNG、声明 PNG，实际回 JPEG。每张图要做 1.5 秒，视频 12 秒。Tavily、FAL、Runpod、BrowserStack、LiveAvatar 的密钥在回归里置空。
- 用户：只经 gateway 的 `/api/*` 说话（Cookie 登录、Origin 校验照真的来）。每个场景一个新测试账号（`e2e-xxxx@example.test`），验证码从 Mailpit 取；开私聊 → 说一句话 → 等这一轮做完 → 看消息和画布。
- 收尾：删私聊（真删除），并确认画布里这个私聊的成果都清掉了。上一轮中断留下的私聊，下一轮开头用当时的测试账号删掉。

一轮回归的顺序：检查镜像和端口 → 中间件（都健康就不动）→ 构建共享包和桌面端 → 起服务（模型网关指向假供应商）→ 核对开发库表结构和迁移文件一致 → 起 Web → 清理上一轮遗留 → 普通场景并行跑、会重启服务的场景排在后面一个个跑。沙箱和检查容器各限 1 核，同时最多 4 次运行。

输出在 `.tmp/e2e/<时间>/`，只留最近 5 轮（开跑前删掉更早的，同时删 7 天前的构建缓存）：`logs/<服务>.log`、`calls.jsonl`（假供应商收到的每次请求，边跑边写）、`report.json`、`canvas/<场景>-<成果>/`（桌面端画布回归的 `electron.log` 和隔离框里的页面）。

## 场景

| 场景 | 覆盖 | 断言要点 |
|---|---|---|
| `chat` | 说「你好」 | AI 回一句话、这一轮成功；只聊天不出任务卡；花费写在 AI 的话上 |
| `web` | 多文件网页（ES 模块互相 import）：AI 交之前用 `app.check` 自查，发现计数错了自己修好再查一次 → 桌面端画布里打开 | 自查经沙箱 → 模型网关 → inspector 跑通，没过时能照着报错改；两次自查的算力结算在这一轮上；AI 的消息里有做完的 4 步；画布里文件齐全、`counter.js` 是修好的；任务卡列着交的文件；在真的桌面外壳里按测试计划点一遍（隔离框只给脚本权限） |
| `solo` | 一个 AI 从头做到交付：`model.ask` 问另一个模型 → 生图做插图 → 写网页 → 在沙箱里用浏览器打开点一遍 → `app.check` 自查 | 问另一个模型拿到了回答；生图请求到了供应商并扣费；AI 自己的浏览器读到点完后的计数、插图加载成功、截到图；自查通过；任务卡的花费含生图；画布里网页和插图齐全（插图和测试图一致），按测试计划点一遍 |
| `media` | 生图工具一次交两个画面（`--prompts`），再写一份插着海报的 DOCX | 两个画面各调一次供应商、几乎同时到（假供应商每张要做 1.5 秒，一张张调的话第二张要等第一张做完）；画布里的海报、横幅和测试图一致；DOCX 里嵌着图；任务卡列着三样成品；生图那一步带着工具名、起止时间和两张图，进度页读得到这一轮做出的图 |
| `video` | 长任务工具：两段视频都加 `--wait false` 先交上，再 `oasis-tool wait` 一起等 | 第二段在第一段做好之前就交上了；两段都提交、取回，画布里的 MP4 和测试视频一致；任务卡列着两段；一起等的那一步带着起止时间和两段短片 |
| `revise` | 让 AI 改：画布里挑一样成果发进私聊，它还在这个会话的工作目录里 | 第二轮接着原会话（同一个会话、`continue_from` 是上一轮）；说明里写着「直接改：out/…」；画布里原地换新（还是 2 个、ID 不变）；第二轮的任务卡只列改过的那样 |
| `interject` | AI 跑一条慢命令时用户插一句 | 插话标成插话、在同一轮里做完；AI 做完那条命令就看到、按它改；消息顺序是「用户、AI、插话、AI」：慢命令留在插话前面那条，按插话改的那步在后面那条，都标成做完 |
| `stop` | AI 跑命令时用户停下，再说「继续」 | 停下的那条标着停下了、没做完的步骤标成没做完；两轮：停下的和接着原会话做完的；报告进画布 |
| `topic` | 开新话题后改之前话题的成果 | 之前话题的工作目录删掉；新话题这一轮是新会话、AI 不记得之前的事；成果连同用到的文件拷进 `materials/canvas/…`；改好的另登记一份，原来那份不动 |
| `workspace` | 第一版交付后会话的持久卷被清掉，再让 AI 改 | harness 拒绝接着原会话，这一轮改开新会话，AI 的消息里告诉用户工作目录不在了；要改的成果拷进来，画布里是在上一版基础上改的 |
| `fault` | 流断在半路、上游临时出错 | 不当成做完；出错了说「继续」接着做完，两段都交付；流断掉的调用按供应商实际花费结算，不按字数估 |
| `takeover` | AI 跑命令时 harness 崩溃重启 | 还是原来那一轮、同一个会话；AI 收到「已恢复」接着做，被打断的命令重做一次 |
| `gateway` | 模型回答到一半 model-gateway 崩溃重启 | 这一轮照样做完（出错了说「继续」）；卡住的调用（快进 31 分钟后）被收尾、冻结退回 |
| `real-chat`（`--real`） | 真模型说「你好」 | 回了话、不出任务卡 |
| `real-web`（`--real`） | 真模型做计数网页 | 做完、画布里有可运行的网页、桌面端画布里点一遍 |
| `real-revise`（`--real`） | 真模型写短文 → 在画布里挑它让 AI 改标题 | 画布里的短文改好了 |
| `real-image`（`--real`） | 真的生图工具 | 画布里有一张真图片（格式和大小），有任务卡 |
| `real-game`（`--real`） | 对照场景：和 dsh 对比用的同一句小游戏需求；花费上限 $3 | 做完、画布里有可运行的游戏（另存一份到回归目录，质量由人看）；记下用时、花费、工具调用次数和其中用到浏览器的次数，和 dsh（24.4 分钟）、改造前对比 |

### 小游戏的真实对比（`real-game`）

同一句话：「做一个网页小游戏：一只橘猫在雨夜屋顶上躲雨滴，两关，难度递增，像素风。要有背景音乐和跳跃、被淋到、过关的音效。」原话里不提怎么排。成果质量由人看，这里只记数字。下面几次都是改造前（还有规划员和工作流时）跑的；第 2 阶段之后私聊里的 AI 自己做到底，再跑一次补上。

| 哪次 | 怎么做的 | 用时 | 花费 | 结果 |
|---|---|---|---|---|
| dsh（用户电脑上） | 一个 AI 做到底 | 24.4 分钟 | — | 交付 |
| 改造前（11-11） | 规划员排了几个节点接力 | 48.1 分钟 | $1.56 | 交付 |
| 11-13 第一次（沙箱有了浏览器，只排一个节点） | DeepSeek V4 Pro 一个 AI 做到底，自己用浏览器校验；79 次模型调用，看图 3 次 | 34.5 分钟 | $1.66 | 交付，关卡没退回 |
| 11-13 第二次（方案按成果排之后） | 规划员排成一样成果、一个 AI；型号选了当前网络用不了的 Claude，引擎换成 DeepSeek V4 Pro | 52.8 分钟 | $3.02 | 没交付：到回归的 $3 上限被取消 |
| 11-13 第三次（沙箱预装像素字体之后） | 同上；AI 读了环境说明，计划用预装的 Unifont 取子集，不再自己画字 | 29 分钟 | $0.44 | 没交付：手动取消。AI 要一次写出整个游戏，这一次回答连续 4 次在 311–313 秒被上游断开，每次重来都一样 |

第二次没交付的原因（查的是运行事件和调用记录）：

- 147 步里有 48 步在做像素字体。AI 要一套内嵌的像素字体，沙箱里没有、又上不了网，就自己一笔一笔画了几十个汉字，再反复出图核对。改法：沙箱镜像预装点阵字体 Unifont，环境说明里写明字体在哪。
- 看图核对（`media.inspect`）10 次花了 $0.66，占 22%：默认型号 qwen3.8-max-prime 一次约 $0.07。DeepSeek V4 Pro 自己看不了图，每次看截图都要走这个工具。
- 会话越长每步越贵：124 次模型调用共 1688 万输入 token，平均每次 13.6 万，后半段每步 2 到 5 美分。
- 被取消时游戏的文件已经齐了（页面、脚本、背景音乐、三个音效），AI 在自己的浏览器里跑过一遍完整流程后还在调难度。没做完的那份和第一次交付的那份都另存在 `.tmp/real-game/`。

第三次卡住的原因（查的是调用记录和 model-gateway 日志）：

- 同一次回答（AI 在一次工具调用里写整个游戏）4 次都在 311–313 秒结束，model-gateway 看到的是上游正常关了连接、没有完成标记；dsh 把它当传输失败原样重试，所以一直重来。前两次对比里最长的一次回答 224 秒，都没碰到。
- 直接问 OpenRouter 做对照：同一型号写一个很长的单文件游戏，166 秒写完 15 万字，正常结束（OpenRouter 转给了 DigitalOcean）。DeepSeek V4 Pro 在 OpenRouter 上有好几家在跑，各家限制不同，断开的那几次转给了哪家当时没有记。
- 改了：model-gateway 记下 OpenRouter 转给了哪家，以及供应商在流里报的错（以前只记「未收到完成标记」）。下次再断就能看到是哪家、什么原因。
- 没改：要不要给这个型号固定用哪几家、要不要告诉干活的 AI「一次回答超过约 5 分钟会被断开」，等确认是哪家的限制后再定。
- 11-14 查明不是供应商：直连 OpenRouter 时 Novita、百度两家，Node 和 curl 两种客户端，都在 303–304 秒被正常关掉、没有完成标记；同一家走开发机上的代理（出口在新加坡）连续输出 11 分钟正常结束。model-gateway 的 `.env` 配了代理和 `NODE_USE_ENV_PROXY=1`，但服务用 `--env-file` 读 `.env`，这个开关要在 Node 启动时就在环境变量里，写在文件里不生效，所以一直直连。改了：`pnpm dev`（`scripts/dev-service.mjs`）和 `pnpm accept`、`pnpm e2e`（`scripts/e2e/stack.mjs`）都把 `.env` 当真正的环境变量交给服务，优先级和 `--env-file` 一样。

每个场景同时检查假供应商的「协议违规」：请求的输出上限超过模型真实上限（65,536）、看不懂的请求，都算回归失败。

## 回归第一次跑就发现并修好的问题（2026-11-08）

1. **开发库表结构和迁移文件不一致**：task 库少了 `nodes.retired_version`——迁移记成已执行，文件却在执行后改过（dbmate 只记版本号）。确认任务单时 502。已补列；回归和验收模式开头都做表结构核对（每个服务在临时库里跑一遍迁移，逐列比较）。
2. **停止后马上继续会失败**：那次运行还在收尾（停沙箱、存会话），harness 当成「还没结束」拒掉。改为等它真正停好再接着（`services/harness/src/service/run-service.ts`）。
3. **几个人同时发任务会把 conversation 的连接池占满**：会话锁用的是会话级 advisory lock，持锁期间一直占一条连接。改成 `conversation_locks` 表里的租约行（持有期间每 10 秒续一次，进程崩了 30 秒后失效），持锁不再占连接（迁移 `20261108130000_conversation_locks.sql`，真实数据库测试覆盖）。
4. **网页交付了画布里却打不开**（真模型回归）：网页没配 `oasis-app.json`，画布里不能运行。平台说明和网页的技能里写明可运行应用要交齐清单，`app.check` 没找到清单时明确报错。
5. **桌面端画布回归自己的竞态**：外壳先打开首页、失败会每秒重试，测试紧接着跳画布会被它打断（ERR_ABORTED）；改为等首页加载完再跳。改过的成果在画布里换新有延迟，断言改为等内容更新。

还记下、没改的：

- 交付时当场检查（文件齐不齐、网页打不打得开、音视频能不能播）还没做，现在靠 AI 自查（见《待办》）。
- 一次回答太长被上游断开时，这一轮出错，用户说「继续」接着做；告诉 AI「回答太长被断开，分几次写」和自动重试的上限还没做（见《待办》）。

## 写新场景

场景按类分在 `scripts/e2e/scenarios/`（网页和聊天、图文和视频、让 AI 改和插话、故障），在 `scripts/e2e/scenarios.mjs` 登记：假模型对用户每句话怎么做（`says`）、用户怎么操作和断言（`run`）。`shared.mjs` 里有开私聊说第一句话（`start`）、等这一轮做完（出错了说「继续」，`settle`）、按一轮找 AI 的话和任务卡、查 harness 里的每一轮。假供应商读 dsh 对话的部分在 `fake-dsh.mjs`，生视频型号和看图挑选的回答在 `fake-media.mjs`。

- 用户每句话带标记 `[[e2e:场景@本轮编号/第几句]]`（`marker(场景, 第几句)`）。假模型找会话里最近一句带标记的话，按 `says[第几句]` 的脚本做；上一轮的编号直接拒单，旧对话不会混进来。
- 脚本是一组步骤（`steps`）加做完说的一句话（`reply`）。步骤：`{ bash }` 跑命令（`writeFiles` 帮你写文件）、`{ tool, args }` 调别的工具、`{ text }` 直接回答（这一轮就结束了）；也可以是函数，按这句话的内容（比如接在后面的文件说明）或上一步的结果决定怎么做。
- 一个会话攒着之前每一轮的往来：调用记录里的 `says` 是会话里有几句用户的话，大于 1 说明是接着原会话做的。harness 接管后的「已恢复」提示接着前面那句话的脚本做（`segment: 'recover'`），做过的步骤照算，被打断的那一步重做（最多三次）。
- 故障：步骤上加 `fault: 'disconnect' | 'length' | 'error500'`（流断、截断、上游 500）或 `hang: true`（不回答，等调用方断开），每个位置只触发一次。
- 会重启服务的场景加 `serial: true`，排在最后一个个跑。

## 对话追踪

`pnpm trace <对话 ID>` 只读本机开发库和 Docker，不改任何东西。列出私聊的话题、正在进行的一轮、harness 里的每一轮（状态、用时、是不是接着上一轮的会话、产出数、工具调用数、是否经历过接管、错误、调用按种类和费用来源汇总、失败调用的原因）、画布成果。开过新话题的，之前话题的运行记录已经真删除，只看得到现在这个话题的。标出的异常：

- 模型或工具调用按估算扣费（算力本来就按核数 × 实际时长计价，不算异常）；
- 调用卡在「进行中」超过 5 分钟；
- 调用结束了冻结还没退回；
- 一轮结束了沙箱容器还在；
- 消息上记的这一轮花费和调用合计对不上。

有异常时退出码是 1，可以接在脚本里用。

## 验收模式

`pnpm accept` 起中间件、构建共享包和 Web，再从当前代码起 9 个服务，Web 用 `vite preview` 跑构建好的版本（`/api` 照样转到 gateway）。之后改代码、改共享契约都不会让服务重启，进行中的一轮不会被打断（11-08 改契约让 `pnpm dev` 全部重启、丢下了在途的调用）。要换成新代码就 Ctrl+C 后重新 `pnpm accept`。桌面端照常 `pnpm desktop`。模型走真实供应商，花的是真钱。日志在 `.tmp/accept/<时间>/`。
