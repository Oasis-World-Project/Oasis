#### 与原生 Harness / Codex 的区别（用户追问，只读比较）

1 MiB 是 Oasis 自建 HTTP 服务的框架默认值，不是 DeepSeek Harness 的目标执行上限、模型 token 上下文上限，也不是所有 Agent 产品统一的请求上限。

- `services/harness/src/adapter/profile/cordis.patch.yml` 复用原生 `openrouter` provider，但明确将 baseURL 替换为 `OASIS_MODEL_BASE_URL`；`dsh.ts::sandboxEnv` 注入该地址。当前调用链为 DSH → 沙箱入口代理（50m）→ model-gateway（该聊天路由默认 1 MiB）→ 供应商。最小的入口限制会先拒绝请求。
- 原生 Harness 直接连接其配置的供应商时，不经过这条 Oasis 路由，因此不会碰到 **Oasis 的** 1 MiB 默认值；这不等于断言原生客户端或供应商没有其他限制，也未对用户原生成功会话做请求字节级比较。
- Codex 使用其自身客户端/服务链路。OpenAI Docs 的[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference) 公开了自动历史压缩阈值 `model_auto_compact_token_limit`、模型上下文与工具输出 token 预算；[Compaction 文档](https://developers.openai.com/api/docs/guides/compaction) 解释压缩长会话的机制。本次没有查到能确定 Codex 所有入口统一 HTTP 字节上限的公开证据，不能回答成“无限制”或臆造一个数值。
- token 上下文、HTTP 原始字节与本地文件大小是不同约束。举例：0.8 MiB 的原始图片编码成 base64 后约 1.07 MiB，尚未计算 JSON 和消息文字；图片 token 预算尚未满时也可能被过小的 HTTP 请求体限制挡住。此为编码大小示例，不是已还原的本次失败请求组成。
