# 部署（一台服务器，Docker Compose）

线上和本地是同一份编排（`infra/compose/docker-compose.yml`），差别都在服务器上的根目录 `.env`。镜像只在服务器上构建，不从镜像仓库拉。服务器是哪台、怎么连，见《云服务器》。

## 线上比本地多什么、少什么

|             | 本地 `pnpm stack:up`       | 线上（`.env` 里填了 `OASIS_DOMAIN`）                                                                                                   |
| ----------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 入口        | 没有，网页由 `pnpm dev` 发 | `oasis/entry`（Caddy）：80 / 443 对公网，自动申请和续期 HTTPS 证书，发网页的静态文件，`/api` 转给 gateway，`/avatar/v1` 转给数字人入口 |
| 验证码邮件  | Mailpit（假邮箱）          | 真的发信服务（`SMTP_URL`），不起 Mailpit                                                                                               |
| 会话 Cookie | 不要求 HTTPS               | `COOKIE_SECURE=true`                                                                                                                   |
| 中间件      | 不自动重启                 | `OASIS_RESTART=unless-stopped`，服务器重启后自己起来                                                                                   |

## 第一次部署

1. **准备服务器**（一次）：加交换分区、装 Docker（官方 apt 源）、装 Node（只用来跑仓库里的脚本，版本和服务镜像一致）、建 `/opt/oasis` 交给登录用户、把登录用户加进 `docker` 组。腾讯云控制台的防火墙放行 80、443（TCP）和 443（UDP）。
2. **DNS**：给网站的域名加一条 A 记录指到服务器。入口第一次启动时要靠它申请证书，记录没生效证书申请不下来（Caddy 会自己重试）。
3. **拉代码**：`git clone https://github.com/Oasis-World-Project/Oasis.git /opt/oasis`。
4. **配置**（都在服务器上，不进仓库）：
   - `node scripts/init-env.mjs` 生成根目录和各服务的 `.env`（数据库、NATS、对象存储的密码是随机生成的）。
   - 根目录 `.env` 里按 `.env.example`「线上」一节填：`OASIS_DOMAIN`、`GATEWAY_ALLOWED_ORIGINS`、`COOKIE_SECURE=true`、`SMTP_URL`、`MAIL_FROM`、`OASIS_RESTART=unless-stopped`、`MAX_CONCURRENT_RUNS`；`DOCKER_SOCKET_GID` 填 `getent group docker` 的数字；沙箱的三项包仓库换回官方源，删掉 `SANDBOX_APT_MIRROR`。
   - `services/model-gateway/.env` 里填供应商的 Key（OpenRouter、Tavily、fal 等）；用数字人的话 `AVATAR_LLM_HOST=0.0.0.0`、`AVATAR_PUBLIC_BASE_URL=https://<域名>/avatar/v1`。
5. **构建沙箱和检查用的镜像**（慢，各一次；改了它们的 Dockerfile 才要重做）：`node scripts/sandbox.mjs build`、`node scripts/sandbox.mjs build-3d`、`node scripts/browser.mjs build`。
6. **起整套**：`node scripts/compose.mjs up --services`（构建 9 个服务和入口的镜像并启动，全部健康才返回）。线上是一个一个镜像构建的（同时构建会把小机器的 CPU 和网络挤到装依赖超时）。

2026-11-19 在 2 核 3.7 GB 的机器上实际的情况：

- 沙箱基础镜像约 15 分钟，3D 镜像和检查浏览器镜像各 2 分钟；9 个服务加入口从头构建约 20 分钟，之后只改代码的更新也要全部重新构建（每个镜像都是从整个仓库拷进去的），约 15 分钟。
- 硬盘：镜像约 13 GB，构建缓存也有十几 GB。紧张时 `docker builder prune -af` 清掉构建缓存（下次构建要重新下载依赖），`docker image prune -f` 清掉换下来的旧镜像。
- 全部起来后空闲时占内存约 1.1 GB；每个沙箱最多再占 2 GB，所以 `MAX_CONCURRENT_RUNS=1`。
- **云端沙箱改租 E2B**（小机器上只能同时跑一个沙箱，群里的 AI 会排很久的队）：在开发机上 `pnpm sandbox:e2b` 把模板建好（在 E2B 那边构建，约 8 分钟；Key 读开发机 `services/harness/.env` 的 `E2B_API_KEY`），服务器根目录 `.env` 里加 `CLOUD_EXECUTOR=e2b`、`E2B_API_KEY=<Key>`、`MAX_CONCURRENT_RUNS=10`（Hobby 档同时 10 个），重启 harness。沙箱里的 dsh 经 `https://<OASIS_DOMAIN>/api/run/v1` 调模型和工具。之前在本机 Docker 卷里的会话接不上（旧对话开新话题）；第 5 步的两个沙箱镜像这时不用在服务器上构建，检查用的浏览器镜像照旧要。

## 更新

```bash
cd /opt/oasis && git pull && node scripts/compose.mjs up --services
```

镜像重新构建，变了的容器换成新的；数据库迁移在服务启动时自己跑。harness 重启后接管原来的运行。看状态 `node scripts/compose.mjs ps`，看日志 `node scripts/compose.mjs logs <服务名>`。

## 发安装包

官网页（没登录时在浏览器里打开网站看到的那一页）的「下载 Windows 版」指向 `/download/Oasis-Setup-x64.exe`，入口容器从服务器的 `/opt/oasis/downloads/` 发文件。出新版：

1. 在 Windows 上打包：`$env:OASIS_RELEASE_WEB_URL = 'https://<域名>'; pnpm desktop:dist`。
2. 传到服务器：`scp apps/desktop/release/Oasis-Setup-<版本>-x64.exe tarot-tencent:/opt/oasis/downloads/`。开发机往服务器传很慢（2026-11-20 是 20–60 KB/s，200 多 MB 要一个多小时），先传成 `.part`、传完核对 SHA-256 再改名，免得有人下到半截的文件。
3. 在服务器上把固定的名字指到新文件：`cd /opt/oasis/downloads && ln -sf Oasis-Setup-<版本>-x64.exe Oasis-Setup-x64.exe`。

安装包没有签名：浏览器下载时可能提示「不常下载」，安装时 Windows 提示「未知发布者」，都能点过去（官网页上写了怎么点）。

## 数据在哪

都在 Docker 的数据卷里：`oasis_postgres-data`（数据库）、`oasis_seaweedfs-data`（文件）、`oasis_nats-data`（事件）、`oasis_entry-data`（证书）、`oasis-workspace-*` / `oasis-sessions-*`（每个会话的工作目录）、`oasis-cache-*`（每人的包缓存）。`node scripts/compose.mjs down` 不删数据卷；带 `-v` 才删。
