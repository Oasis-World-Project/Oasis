## 2. 怎么连

在用户 Windows 上（Claude 通过 Desktop Commander 执行 PowerShell）：

```powershell
# 只读验证：成功时输出 ubuntu。-n 不能省：不把标准输入关掉，ssh 在 Desktop Commander 里跑完也不退出
ssh -n -o IPQoS=none -o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=10 tarot-tencent whoami
```

- 保持严格主机密钥校验。提示主机密钥变了时，先请用户在腾讯云控制台终端运行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 核对指纹；不要关校验、不要删 known_hosts 里的记录。
- 偶发连接被关：保留 `-o IPQoS=none` 再试一次。

### 往服务器传脚本（Windows 端的坑）

命令写在一行里时，引号和 `$` 会被 Windows 吃掉；正确做法是先把脚本写成文件，再经标准输入交给远端 bash，输出写进文件再看：

```powershell
cmd /c "ssh -o IPQoS=none -o BatchMode=yes -o StrictHostKeyChecking=yes tarot-tencent bash -s < .tmp\某脚本.sh > .tmp\某脚本.out 2>&1"
```

- 脚本文件用 LF 换行、UTF-8；**写进服务器文件的内容（nginx 配置、systemd 单元等）只用英文**。曾经因为中文被换成 `?` 把一行注释写坏，连带下一行的 `server {` 丢失，`nginx -t` 失败。
- Desktop Commander 会拦下命令文本里含 `sudo` 的命令：把 `sudo` 写进脚本文件里再传。
- 以 root 做的大改动（装软件、建 systemd 单元），自动执行可能被安全检查拦下：把脚本准备好，请用户本人在 PowerShell 里运行。

## 3. 服务器上现在有什么（2026-11-19 部署后）

- Oasis 整套在 `/opt/oasis`（从 GitHub 克隆的仓库），用 Docker Compose 跑：9 个服务、入口（80 / 443）、PostgreSQL、NATS、SeaweedFS、沙箱的两个代理。怎么部署、怎么更新见《部署》。
- 部署时装的：Docker（官方 apt 源）、4 GB 交换分区（`/swapfile`）、Node 24（`/opt/node-v24.21.0-linux-x64`，只用来跑仓库里的脚本）；`ubuntu` 在 `docker` 组里。
- 线上的配置和密钥只在服务器上的 `/opt/oasis/.env` 和 `/opt/oasis/services/model-gateway/.env`（权限 600），不在仓库里。
- 机器是 2 核 3.7 GB，比部署设计里要的（8 核 16 GB）小很多，现在只给用户自己试用：`MAX_CONCURRENT_RUNS=1`，同时只跑一个沙箱。用户 2026-11-19 定：以后把沙箱换成租厂商的，这台先不升级。

以前靠服务器上的一个站点加开发机的 SSH 反向隧道，把 LiveAvatar 的回调转到开发机；站点随服务器清空没了，隧道脚本也删了。数字人的回调现在走线上的入口（`https://oasis.elysiumgrid.space/avatar/v1`），真实对话只能在线上试；开发机上只能用沙盒模式看界面。

## 5. 本机开发环境的开关（和服务器无关，常一起用）

- Oasis 的中间件跑在 Docker Desktop 里（WSL2 后端，任务管理器里显示为 `VmmemWSL`）。开发前先打开 Docker Desktop，再 `pnpm infra:up`、`pnpm dev`；不开发时 `pnpm infra:down`（保留数据卷）、`docker desktop stop`、`wsl --shutdown` 可以把 `VmmemWSL` 占的内存全部还给系统。
- WSL 里有两个系统：`docker-desktop`（Docker 自己的）和 `Ubuntu`（只跑系统后台服务，Oasis 不用它）。
