## 2. 怎么连

在用户 Windows 上（Claude 通过 Desktop Commander 执行 PowerShell）：

```powershell
# 只读验证：成功时输出 ubuntu
ssh -o IPQoS=none -o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=10 tarot-tencent whoami
```

- 保持严格主机密钥校验。提示主机密钥变了时，先请用户在腾讯云控制台终端运行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 核对指纹；不要关校验、不要删 known_hosts 里的记录。
- 偶发连接被关：保留 `-o IPQoS=none` 再试一次。

### 往服务器传脚本（Windows 端的坑）

命令写在一行里时，引号和 `$` 会被 Windows 吃掉；正确做法是先把脚本写成文件，再经标准输入交给远端 bash：

```powershell
$OutputEncoding = New-Object Text.UTF8Encoding $false
(Get-Content D:\Workplace\Project-Internship\Oasis\.tmp\某脚本.sh -Raw -Encoding UTF8) -replace "`r","" | ssh -o IPQoS=none -o BatchMode=yes tarot-tencent 'bash -s'
```

- 必须先设 `$OutputEncoding` 为 UTF-8，否则中文会被换成 `?`。曾经因此把一行中文注释写坏，连带下一行的 `server {` 丢失，`nginx -t` 失败。
- **写进服务器文件的内容（nginx 配置、systemd 单元等）只用英文**；脚本里的 bash 注释可以写中文。
- 管道末尾总会多一个 `bash: line N: $'\r': command not found`，无害。
- Desktop Commander 会拦下命令文本里含 `sudo` 的命令：把 `sudo` 写进脚本文件里再传。
- 以 root 改共用 nginx、建 systemd 单元这类操作，自动执行会被安全检查拦下：把脚本准备好，请用户本人在 PowerShell 里运行（2026-11-01 的 oasis-dev 站点就是这样建的）。

## 3. 服务器上有什么（不要动别人的东西）

用户另外四个项目在线上运行：tarot、buddyup、kong、orchestrai（都是 `*.elysiumgrid.space`）。它们由一个共用的 nginx 容器统一对外：

| 项 | 位置 |
|---|---|
| 共用入口 | Docker 容器 `shared-ingress-nginx-1`（`nginx:1.29.3-alpine`，host 网络，占 80/443），编排在 `/opt/shared-ingress/compose.yml` |
| 站点配置 | `/opt/shared-ingress/conf.d/`，每个站点一个文件：`sites.conf`（tarot）、`kong.conf`、`orchestrai.conf`、`video-host.conf`，以及我们的 `oasis-dev.conf` |
| 改动前备份 | `/opt/shared-ingress/backups/<UTC 时间>-<说明>/`（照这个惯例：改之前先整体复制 `conf.d`） |
| 证书 | `/etc/letsencrypt/live/<域名>/`；宿主机没装 certbot，用 `certbot/certbot:v5.8.0` 容器 + webroot（`/opt/multi-agent-tarot/acme-webroot` 挂成容器里的 `/var/www/certbot`） |
| 证书续期 | 每个站点一个 systemd 定时器：`<名字>-certificate-renew.timer` → `/usr/local/sbin/<名字>-renew-certificate`（共用锁 `/run/lock/shared-certificate-renew.lock`，证书变了才 `nginx -t` 并重载） |
| `deployment.json` | `/opt/shared-ingress/deployment.json` 是另一个项目的部署记录，不要改 |

规矩：

- 只新增自己的文件，不改别人的站点配置。
- 改 nginx 前先备份；每次重载前 `docker exec shared-ingress-nginx-1 nginx -t`，不通过就还原备份。
- 改完用服务器上的 `curl` 检查另外四个站点仍是 200（从用户国内网络直接访问它们会很慢，不准）。
- 服务器内存紧，**不要在上面部署 Oasis 整套服务**（10 个服务、Postgres、对象存储、沙箱和检查容器），等专门的部署阶段再定方案。

| 项 | 内容 |
|---|---|

服务器上不跑任何 Oasis 进程；隧道不开时 `/avatar/health` 返回 502，这是正常的。

## 5. 开发期隧道

```powershell
cd D:\Workplace\Project-Internship\Oasis
pnpm avatar:tunnel     # 服务器 127.0.0.1:15200 → 本机 127.0.0.1:4118，断线 5 秒后重连
```

- 前提：本机 `pnpm dev` 在跑（4118 在监听），`services/model-gateway/.env` 里有 `LIVEAVATAR_API_KEY` 和 `AVATAR_PUBLIC_BASE_URL=https://oasis-dev.elysiumgrid.space/avatar/v1`。开发时 `AVATAR_SANDBOX=true`（免费）；只有真实验收时临时改成 `false`，用完改回，并重启 model-gateway（`.env` 只在启动时读）。
- 检查是否通：在服务器上 `curl -s https://oasis-dev.elysiumgrid.space/avatar/health` 应得到 `{"status":"ok"}`；不带 Key POST 应 401，GET 应 403，其他路径 404。
- **关隧道**：Desktop Commander 后台起的进程，`Stop-Process` 只杀外层 PowerShell，里面的 `node scripts/avatar-tunnel.mjs` 和 `ssh` 会留下。要找到 node 进程用 `taskkill /PID <pid> /T /F` 连子进程一起结束，再确认 `Get-Process ssh` 为空。

### 隧道起不来：`remote port forwarding failed for listen port 15200`

上一条隧道异常断开后，服务器上那条 sshd 会话不会马上退出，15200 还被占着。处理：

1. 只读查看：`ss -tlnp | grep ':15200 '`，以及 `ps -o pid,lstart,args -u ubuntu | grep 'sshd: ubuntu'`。
2. 找出开始时间和那条旧隧道对得上的 `sshd: ubuntu` 会话，**只结束这一个**（先用 `ps -o args= -p <pid>` 确认是 `sshd: ubuntu`）。不要动其他会话，它们可能是用户自己的。
3. 新隧道脚本会在 5 秒内自动重连。

## 6. 本机开发环境的开关（和服务器无关，常一起用）

- Oasis 的中间件跑在 Docker Desktop 里（WSL2 后端，任务管理器里显示为 `VmmemWSL`）。开发前先打开 Docker Desktop，再 `pnpm infra:up`、`pnpm dev`；不开发时 `pnpm infra:down`（保留数据卷）、`docker desktop stop`、`wsl --shutdown` 可以把 `VmmemWSL` 占的内存全部还给系统。
- WSL 里有两个系统：`docker-desktop`（Docker 自己的）和 `Ubuntu`（只跑系统后台服务，Oasis 不用它）。
